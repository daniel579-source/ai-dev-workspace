# ADR-0002：LOG 以「案件」為單位在本機手動匯入

- 日期：2026-10-15
- 狀態：已接受
- 確認者：repo owner（daniel579-source）
- 對應 ticket：Wayfinder「LOG 取得與匯入方式」
- 相關決策：ADR-0001（部署形態採單機桌面程式）

## 背景

- 依 ADR-0001，系統是單機、離線的桌面程式，LOG 在工程師自己的電腦上處理。
- LOG 由同一套自動化倉儲系統產生。同一天的內容放在以日期命名的資料夾中，裡面固定依**模組**分成三個資料夾（EXE、PLC、Server）。三個模組在**同一台電腦**上執行。
- 分析的典型情境是：出問題時，工程師拿到那幾天的 LOG，在自己電腦上分析。
- 系統必須能用於**多個廠別**。每個廠別只有一套倉儲系統，各廠別的 Layout 不盡相同。
- 樣本只涵蓋到當天 14:51（見 `docs/log-format-notes.md` O-009），同一天的資料日後可能被重新下載，而且內容變多。
- 需求：原始 LOG 不得修改（FR-002、NG-5）、記錄檔案中繼資料（FR-003）、避免重複匯入（FR-004）、無法解析的內容不得丟棄（FR-012）、可追溯到原始檔案與行號（FR-040）。

## 決策

1. **匯入方式**：只做**手動、需要時才匯入**，不做排程或即時收集（NFR-005 定為手動批次）。
2. **接受的形式**：資料夾，以及 7z、zip 壓縮檔。系統依「日期資料夾 → `<模組>-<日期>` 資料夾」的結構，自動辨識日期和模組。
3. **案件**：每次分析建立一個獨立的**案件**資料夾，內含原始檔、索引與所選廠別的設定。一個案件只屬於**一個廠別**，可以包含多天。案件可以整包保存、交給別人或直接刪除。
4. **原始檔保存**：匯入時把原始檔（或原始壓縮檔）**複製**進案件，記錄雜湊值、原始路徑、匯入時間；原始檔永遠不修改。
5. **重複匯入**：
   - 雜湊值相同：略過。
   - 舊檔是新檔的開頭部分：以新檔取代舊檔參與查詢，原始行號不變。
   - 內容衝突：不自動處理，提示工程師選擇。
   - 任何情況下，舊的原始檔都保留在案件內，不刪除。
6. **未知 LOG**：
   - 符合共通容器格式（`時間 | 等級 | Logger | 訊息`）：照常匯入，標示「未知種類」，可以搜尋與顯示，但不參與回放的狀態推導。
   - 不符合共通格式：整個檔案保留原樣，標示「無法解析」。
7. **多廠別**：系統管理多組**廠別設定**，每組包含該廠別的 Layout 與 LOG 差異設定（編碼、Logger 種類、時區等）。建立案件時選擇廠別。**不支援**在同一個案件中同時分析多個廠別。

## 理由

- 手動匯入符合「事後回溯分析」的用途，也符合離線、單機的限制。
- 直接接受壓縮檔，工程師不必先解壓縮，原始壓縮檔也能整份保存。
- 以案件為單位，資料範圍清楚，容易保存、交接與清理；真實 LOG 不會無限累積在電腦上，符合資安原則。
- 複製原始檔的成本低（樣本一天約 20 MB），而且原始行追溯不必依賴外部檔案一直留在原地。
- 重複匯入的「開頭相符就取代」規則，能處理「同一天晚一點重新下載」的常見情況，又不破壞已有的行號追溯。
- 多廠別以「廠別設定」處理，可以吸收各廠別在 Layout 與 LOG 上的差異，同時讓單一案件的範圍保持簡單。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 排程或即時自動收集 | 單機離線、事後分析，沒有即時需求；需要長駐程式與網路存取 |
| 只記錄原始檔路徑，不複製 | 原始檔被移走或刪除後就無法追溯原始行 |
| 所有 LOG 累積在單一資料庫 | 資料範圍不清楚、難以清理；真實 LOG 長期累積在電腦上，增加外洩風險 |
| 一個案件同時包含多個廠別 | 需要處理跨廠別的時間對齊與 Layout 拼接，複雜度高；目前沒有這個需求 |
| 重複匯入一律覆蓋或一律拒絕 | 一律覆蓋可能丟失內容衝突的資訊；一律拒絕無法處理「重新下載後內容變多」的情況 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 其他廠別的目錄結構或模組資料夾名稱不同 | 自動辨識失敗 | 目錄辨識規則放在廠別設定中，可以調整；辨識失敗時讓工程師手動指定 |
| 跨日分析時，案件中的資料量變大 | 匯入與查詢變慢 | 在「儲存與索引候選方案比較」中以多天量級實測 |
| 案件資料夾被整包交給別人 | 真實 LOG 隨案件外流 | 在「敏感資訊處理與存取權限」中處理 |
| 「開頭相符」判斷遇到檔案輪替 | 新下載的現行檔已被輪替，開頭不再相符 | 輪替檔與現行檔一起比對；判斷不出來時歸類為內容衝突，交由工程師選擇 |

## 後續驗證方式

- 用樣本測試：匯入 7z、匯入資料夾、同一份資料重複匯入、模擬「新檔多出後半段」的重新匯入。
- 取得其他廠別的目錄結構後，確認自動辨識規則是否適用。

## 影響範圍

- **跨電腦的時間策略**：同一廠別的三個模組在同一台電腦上，共用同一個時鐘，不需要做模組之間的時鐘偏差校正；時區依廠別設定。
- **事件模型與排序規則**：事件需要記錄所屬案件、模組、原始檔（含被取代的版本）與行號。
- **Layout 模型與設定檔**：Layout 屬於廠別設定的一部分。
- **儲存與索引候選方案比較**：儲存以案件為單位，需要支援多天。
- **敏感資訊處理與存取權限**：案件資料夾內含真實 LOG，分享案件時的風險要處理。
