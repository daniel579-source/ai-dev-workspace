# ADR-0006：Layout 模型與設定檔

- 日期：2026-10-16
- 狀態：已接受
- 確認者：repo owner（daniel579-source）
- 對應 ticket：Wayfinder「Layout 模型與設定檔」
- 相關決策：ADR-0001（Layout 以檔案分享）、ADR-0002（Layout 屬於廠別設定）、ADR-0005（回放的世界模型）

## 背景

- 每個廠別一份 Layout，屬於廠別設定的一部分（ADR-0002）；以檔案分享（ADR-0001）。
- 世界模型由站點、搬送機、對接設備、儲位、貨物、命令組成；站點可以有多個別名，未對應的編號要集中呈現；儲位逐格記錄；第一階段 2D，但 Layout 要保留 3D 需要的資訊；站點右上角有在席指示燈（ADR-0005）。
- 樣本 LOG 中站點有兩套編號（WCS 的 4 位數、PLC 的 `A-nn`），正式對照表待確認（`docs/log-format-notes.md` O-012）。
- 以文件草案（虛構的資料結構與畫面草圖）討論資料結構，再以可點擊的 HTML 原型比較三種編輯器版面（三欄式、畫布優先、對應優先），原型保留在 `prototype/layout-editor` 分支，不合併到 `main`。

## 決策

### 1. 元素種類

| 類別 | 元素 | 說明 |
|---|---|---|
| 有 LOG 意義 | 站點、料架（含儲位）、搬送機、對接設備、防火門、電梯 | 可以與 LOG 對應，回放時改變狀態（防火門為 2026-11-06 補充，見第 12 點；電梯為 2026-11-06 #102 補充，見第 15 點） |
| 輔助 | 輸送線、區域、文字、導軌 | 只讓畫面好讀；不與 LOG 對應，也不推導狀態（導軌為 2026-11-06 #100 補充，見第 14 點）。輸送線表示兩個站點、對接設備或搬送機之間的貨物流向，可以是單向或雙向（2026-10-19 #63 修改，原為「只表示兩個站點（或對接設備）之間的方向」；見第 7 點） |

### 2. 別名

- 2026-11-14 補充（使用者決定）：「對接設備」在畫面上改稱 **Conv**；設定檔的 `type` 仍為 `dock`，不升格式版本（Jev 0.96）。搬送機有 STV、RM 兩種，料架有單深、雙深兩種：2026-11-15 由 ADR-0019 決定——RM 另成元素種類 `rm`，STV 維持 `vehicle`；深淺以排號判斷，記在選填的「排的配置表」（見第 16 點）。
- 站點、搬送機、對接設備可以有**多個別名**。防火門也可以（2026-11-06 補充，第 12 點）。電梯也可以（2026-11-06 #102 補充，第 15 點）。
- LOG 中的編號與別名**完全相同**（大小寫視為相同）才算對應；不支援萬用字元。
- 一個別名在一份 Layout 中**只能屬於一個元素**；重複時編輯器直接擋下。
- 2026-10-19 #47 補充：現場問卷確認站點的兩套編號是一對一，而且沒有對照表。建立 Layout 時，把兩個編號都加為同一個站點的別名（可利用第 3 點的未對應清單）。

### 3. 未對應的編號

- 編輯器可以「載入案件比對」，列出案件 LOG 中出現、但 Layout 還沒對應的站點、搬送機、對接設備編號，附上出現次數。
- 把編號拖到元素上，就加為該元素的別名。
- 沒有案件時，編輯器仍可以單獨編輯 Layout。回放畫面也顯示同一份清單。
- 比對方式（2026-10-16 #23 補充）：比對的對象是選擇的案件，與編輯器中**目前的**別名（還沒存檔的也算）；比對不分大小寫。

### 4. 料架與儲位

- 一排料架是一個長方形，記錄排號、起訖列、層數、每層高度。
- 畫面上沿長邊切成「列」的小格；**層不另外畫**，以顏色深淺表示該列有貨的層數。
- 點一格顯示這一列的**側視圖**，逐層列出儲位編號與其中的棧板。
- 儲位編號的拆解規則放在 Layout 中，以字母樣式表示（例如 `RRCCCLL`：排 2 碼、列 3 碼、層 2 碼）。

### 5. 座標與 3D 資訊

- 單位為**公尺**。
- 每個元素有位置（x、y）、尺寸（寬、深）、旋轉（只允許 0、90、180、270 度）、高度；料架的高度由層數 × 每層高度得出。
- 編輯器提供格線吸附。
- 站點右上角保留在席指示燈的位置。
- **位置與旋轉的定義**（2026-10-16 #22 補充）：x、y 是元素**未旋轉時左上角**的位置；w 為寬、h 為深。旋轉以元素**中心點**為準，只允許 0、90、180、270 度。
- **編輯器的操作**（2026-10-16 #22 補充）：格線每 1 公尺一條，拖曳移動與調整大小都吸附到 **0.5 公尺**；最小尺寸為 0.5 公尺；位置不能小於 0。元素旋轉 90 或 270 度時，在畫面上橫向拖曳調整的是元素的深（h）。屬性面板可以直接輸入數值，不受吸附限制。

### 6. 自訂屬性

每個元素可以加任意的「鍵＝值」，值一律是文字；點開元素時顯示，也可以被搜尋。第一階段不支援數字運算或下拉選單。

### 7. 設定檔

- 一個廠別一個**廠別設定檔**；Layout 是其中一個區段，其他區段是編碼、Logger 種類、時區、模組順序、解析規則等。
- 格式採 **JSON**（使用者選定）。
- 檔案記錄**格式版本**、**修訂號**、修改人（作業系統帳號）、修改時間；每次儲存修訂號加 1。新版程式要能讀舊版格式。
- 分享時直接複製檔案。
- **欄位名稱**（2026-10-16 #22 定案）：沿用下方範例結構，採 camelCase：
  - 最上層：`formatVersion`、`plant`、`revision`、`revisedBy`、`revisedAt`、`moduleOrder`、`knownLoggers`、`layout`。
  - `layout`：`units`（固定為 `m`）、`storageCodeRule`、`elements`。
  - 元素：`id`、`type`、`name`、`aliases`、`x`、`y`、`w`、`h`、`rotation`、`height`；料架加上 `row`、`colFrom`、`colTo`、`levels`、`levelHeight`；輸送線加上 `from`、`to`；自訂屬性為 `props`（物件，保持順序）。
  - `type` 的值：`station`、`rack`、`vehicle`、`dock`、`conveyor`、`area`、`label`；2026-11-06 加上 `fireDoor`（第 12 點）。
  - 用不到的欄位不寫出；料架的高度由層數 × 每層高度得出，不另外保存。
- **格式版本**（2026-10-16 #22 補充）：讀取時先看 `formatVersion`。比程式支援的版本新、缺少或無法辨識時，明確提示（例如「請改用較新版的 LogTrace 開啟」），不嘗試讀取。
- **認不得的欄位原樣保留**（2026-10-16 #22 補充）：較新版本加入的欄位，用舊版開啟再存檔時不會遺失。
- **存檔前檢查**（2026-10-16 #22 補充），有問題時不存檔，並指出相關元素：
  - 別名在整份設定中不可重複（大小寫視為相同）。
  - 元素 id 不可重複。
  - 旋轉角度只能是 0、90、180、270。
  - 輸送線的兩端必須是站點或對接設備。
    - 2026-10-19 #63 修改：兩端必須是站點、對接設備或搬送機；連到搬送機的那一端必須有交接點。
  - 只有站點、搬送機、對接設備可以有別名。
  - 自訂屬性的名稱不可空白或重複。
- **存檔方式**（2026-10-16 #22 補充）：先寫到暫存檔再取代原檔，寫到一半失敗時原檔不受影響；存檔失敗時修訂號不變。
- **時區**（2026-10-16 #19 補充）：最上層新增 `timeZone`（IANA 或 Windows 的時區識別碼），預設 `Asia/Taipei`（ADR-0003 第 1 點）。
- **存放位置**（2026-10-16 #22 補充）：預設為 `%LOCALAPPDATA%\LogTrace\Plants\`，每個廠別一個 `.json`，以廠別名稱當檔名；也可以開啟或另存到其他位置，用於分享。
  - 2026-10-19 #47 修改：預設改為 `D:\LogTrace\Plants\`，可以在設定中修改（理由見 ADR-0011 第 3 點）。實作與既有檔案的處理另開 ticket。
  - 2026-10-19 #57 補充：已實作；廠別設定的存放位置可以在主畫面「案件」面板變更，重新開啟後保留。舊位置的設定檔依 ADR-0011 第 3 點詢問後搬移。
- **編碼設定**（2026-10-16 #34 補充）：最上層新增 `encodings`，為陣列，每一項為 `{ "module": "PLC", "logger": "PLCLOG", "encoding": "Big5" }`（範例／虛構）。
  - `module` 可以省略，表示所有模組；`encoding` 只能是 `UTF-8` 或 `Big5`。
  - 比對不分大小寫；模組相符的規則優先，其次是不限模組的規則；沒有規則符合時自動判斷（O-002）。
  - 存檔前檢查加上：編碼規則的 Logger 不可空白、編碼不支援、同一個模組加 Logger 重複；模組順序不可空白或重複；已知 LOG 種類不可空白。
  - 編輯器的「LOG 設定」分頁可以設定模組順序、已知 LOG 種類與編碼。
- **解析規則**（2026-10-16 #23 補充）：最上層新增 `parseRules`，每一項為 `{ name, module?, logger?, pattern }`（規則的形式見 ADR-0005 第 8 點）。新設定從初始規則開始，編輯器可以編輯或還原初始規則。存檔前檢查：正規表示式可以編譯、至少有一個欄位、沒有不認得的欄位。
- **效果與在席訊號**（2026-10-16 #24 補充）：解析規則多了可選的 `effect`（見 ADR-0005 第 8 點），有效果時檢查必要的欄位；最上層新增 `presenceSignal`（在席訊號的名稱，預設「在席」）。
- **遮罩規則**（2026-10-16 #20 補充）：最上層新增 `maskPatterns`（正規表示式的清單，見 ADR-0009 第 1 點），存檔前檢查正規表示式可以編譯。
- **輸送線的方向與搬送機**（2026-10-19 #63 修改）：
  - 新增 `bidirectional`：`true` 表示雙向；沒寫表示單向，方向為 `from` → `to`。舊設定檔不用改。畫面上不畫箭頭，單向或雙向在屬性面板顯示與修改。
  - 輸送線的一端可以是搬送機。這一端另外存**交接點**座標 `fromPoint`／`toPoint`（`{ "x": …, "y": … }`，公尺）：預設為建立時搬送機圖示上最靠近另一端的邊緣點，可以拖曳調整。線畫到交接點，不畫到搬送機中心；與搬送機的關聯只是邏輯上的，日後搬送機會移動時線不動。搬送機被刪除時，連到它的輸送線一起刪除。
  - 格式版本（2026-10-19 #63 定案）：只有用到雙向或交接點時寫 `2`，其他仍寫 `1`；新版程式兩種都能讀。用到新功能的檔案在舊版程式開啟時明確提示改用新版；沒用到的檔案舊版照常開啟。捨棄：一律寫 2（沒用到新功能的檔案舊版也打不開）、維持 1（舊版開啟後雙向被當成單向，存檔時被擋下卻看不出是版本太舊）。
- **防火門**（2026-11-06 補充，見第 12 點）：
  - 元素新增 `doorState`（平時狀態，`open` 或 `closed`；沒寫表示不設定）與 `conveyors`（關聯的輸送線 id 陣列）。只有防火門寫出這兩個欄位。
  - 格式版本：有防火門時寫 `3`，否則照舊寫 `1` 或 `2`。舊版程式不認得 `fireDoor` 這個種類，以版本 3 讓它明確提示改用新版，而不是讀到一半失敗。
  - 存檔前檢查加上：關聯的輸送線必須存在、不可重複。
- **電梯**（2026-11-06 #102 補充，見第 15 點）：
  - `type` 新增 `elevator`。電梯不使用 `floor`，改存 `servedFloors`（服務的樓層名稱陣列）。
  - 有電梯時格式版本寫 `5`。
  - 存檔前檢查加上：服務的樓層至少兩層且都在樓層清單中；輸送線不能接到電梯；刪除電梯服務的樓層時擋下。
- **導軌**（2026-11-06 #100 補充，見第 14 點）：
  - `type` 新增 `rail`。導軌以 `points`（點的陣列，每點 `x`、`y`，以及到下一點那一段的凸度 `b`，0 可省略）與 `closed`（頭尾相接時為 `true`）表示，不存 `x`、`y`、`w`、`h`、`rotation`。
  - 搬送機新增 `rail`（所走導軌的 id）。
  - 有導軌時格式版本寫 `4`（舊版程式不認得 `rail` 這個種類）。
  - 存檔前檢查加上：導軌至少 2 個點、|凸度| ≤ 1；搬送機指定的導軌必須存在且在同一層。
- **樓層**（2026-11-06 #99 補充，見第 13 點）：`layout` 新增 `floors`（樓層名稱的陣列，順序即樓層順序）；元素新增 `floor`（樓層名稱，輸送線除外）。存檔時一律寫出。**不升格式版本**。存檔前檢查加上：樓層名稱不可空白、不可重複（大小寫視為相同）、至少一層、元素的樓層必須在清單中、輸送線兩端必須在同一層。
- **站點模式名稱**（2026-10-19 #58 補充）：最上層新增 `stationModeNames`，為「代號 → 名稱」的物件，保持輸入順序（ADR-0005 第 3 點）。存檔前檢查代號不重複、代號與名稱都有填。編輯器的「在席訊號」下方以表格編輯。沒有這個欄位的舊設定檔照常開啟。真實的代號意義只填在本機的設定檔。
- **沒有 LOG 的門檻**（2026-10-21 #84 補充）：最上層新增 `gapThresholds`，為「模組 → 秒數」的物件（寫法與 `stationModeNames` 相同），用於時間軸標示沒有 LOG 的時段（ADR-0008 第 3 點）。沒有列出的模組使用預設 300 秒；0 表示該模組不標示。存檔前檢查秒數為 0 以上的整數、模組不重複。編輯器以「沒有 LOG 的門檻」表格（模組、秒數）編輯，做法與站點模式名稱相同。沒有這個欄位的舊設定檔照常開啟。與其他設定相同，案件使用快照：修改門檻後，開啟案件時套用新版才生效，套用時會重新解析案件。（2026-10-22 #86 補充）編輯器中門檻的模組改成下拉選單，選項取自同一分頁的模組順序，隨模組順序的編輯即時更新，只能選擇不能輸入。存檔前檢查門檻的模組在模組順序中（不分大小寫），手動編輯 JSON 或模組順序改名後也會擋下；設定檔中不在模組順序的舊名稱在編輯器中仍顯示，但無法存檔。只在存檔時檢查，載入設定檔、開啟案件不受影響。理由：比對只看模組名稱，自由輸入時曾填到 Logger 名稱與 Layout 元件名稱，門檻靜默不生效。

### 8. 案件與 Layout 版本

- 案件保存建立時所用 Layout 的**快照**與修訂號。
- Layout 之後更新時，案件提示「有新版，要不要套用」，由使用者決定。
- 實作方式（2026-10-16 #27 補充）：
  - **快照的內容**：建立案件時，把整份廠別設定檔（含 Layout、解析規則、編碼、遮罩等）與來源路徑存進案件資料庫。案件一律以快照開啟，設定檔被修改、改名或刪除都不影響。
  - **檢查新版**：開啟案件，以及回到主畫面時檢查。先看來源路徑，再依廠別名稱找存放位置下的設定檔；修訂號較新時提示。
  - **不套用**：維持快照；同一修訂不再提示，有更新的修訂時再提示。
  - **套用**：以新設定重建案件的事件（解碼、排序、解析欄位、效果、搜尋用文字），再重建世界模型。原始檔不變；穩定識別碼不變，事件序號可能改變。只重新解析欄位不夠，因為新版可能改了編碼或模組順序。
  - **舊案件**：快照功能加入前建立的案件沒有快照，依廠別名稱找設定檔；套用後即有快照。

### 9. 編輯器版面

採**三欄式**：左邊工具箱、中間畫布、右邊屬性，下方是「未對應」清單（以拖曳對應）。

### 10. 編輯器的選取、剪貼簿與復原（2026-10-19 #64 補充）

- **選取**：可以框選多個元素，框**碰到**的元素就算選到，碰到的輸送線也算；Ctrl＋點選加選或取消選取。選取多個時拖曳會一起移動；屬性面板只在單選時顯示。
- **Del**：刪除所有選取的元素，連到它們的輸送線一起刪除。
- **Ctrl+C／Ctrl+V**：
  - 剪貼簿只在編輯器內部（不用 Windows 剪貼簿）。
  - 貼上時產生新的 id；名稱、尺寸、旋轉、自訂屬性與**別名**照抄。別名重複時由存檔前檢查擋下，使用者自行修改。
  - 輸送線兩端都被選取時一起複製，改連到新元素；只有一端被選取時也複製，另一端連回原本的元素。
  - 以**滑鼠目前的位置**當作貼上元素（整組）的左上角；貼上後自動選取新元素。滑鼠不在畫布上時，放在原位置往右下 1 公尺（2026-10-19 #64 使用者決定）。
- **Ctrl+Z 復原**：新增、刪除、移動、調整大小、貼上、元素屬性修改都可以復原；一次拖曳、同一欄位的連續輸入各算一步。只包含 Layout 元素，不包含「LOG 設定」分頁的設定（文字框有自己的復原）（2026-10-19 #64 補充）。可以復原的步數假設為 50 步。關閉編輯器或存檔之後不能再復原。

### 11. 畫布大小與縮放（2026-10-19 #65 補充）

- 編輯器的畫布依元素範圍**自動加大**：所有元素的範圍再加 20 公尺的空白，最小 60 × 40 公尺；把元素拖到靠近邊緣時畫布跟著變大。畫布大小不寫進設定檔。
- 加入縮放：Ctrl＋滑鼠滾輪，以及「符合視窗」按鈕。縮放不影響吸附（仍為 0.5 公尺）。
- 回放畫面的 Layout 以同樣的方式依元素範圍調整大小，也可以縮放（原本固定 40 × 25 公尺，範圍外的元素看不到）。
- 2026-11-14 補充：回放改為 3D（ADR-0017），編輯器也改為 3D（ADR-0018）；3D 中以相機縮放、旋轉、平移取代畫布大小與縮放，吸附仍為 0.5 公尺。

### 12. 防火門（2026-11-06 補充）

使用者要求 Layout 加入防火門，狀態有開、關兩種。目前的樣本 LOG 中**沒有**防火門的紀錄，LOG 樣式**待確認**（`docs/log-format-notes.md` O-017）。

- **元素**：防火門屬於有 LOG 意義的元素，可以有別名；id 前綴為 `fd`，預設尺寸寬 2、深 0.5、高 3 公尺。不能當作輸送線的端點。
- **狀態的來源**（使用者決定）：
  - 解析規則新增欄位 `fireDoor`（防火門的編號），以及兩種效果：`fireDoorOpened`（防火門開）、`fireDoorClosed`（防火門關）。由規則決定哪一行是哪一種，程式不辨識開或關的文字。
  - 編輯器可以設定**平時狀態**（不設定、開、關）。
  - 回放時的優先順序：
    1. 有 LOG 事件時，依事件顯示開或關，並記錄造成它的事件。
    2. 還沒有 LOG 事件、但有平時狀態時，顯示平時狀態，標為「推估」（虛線框）。
    3. 兩者都沒有時，顯示「未取得資訊」（灰色）。
  - 未對應的編號也列出 `fireDoor` 欄位抽到的編號，可以拖到防火門上成為別名。
- **關聯的輸送線**（使用者決定）：
  - 防火門可以指定穿過它的輸送線。編輯器提供手動加入與移除，以及「依位置帶入」按鈕：把線段碰到門範圍的輸送線加入。
  - 刪除輸送線時，從防火門的關聯中移除。
  - 貼上防火門時，一起貼上的輸送線改成新的 id，沒有一起貼上的保留原本的 id（2026-11-06，Jev 判斷，信心度 0.72）。
- **門關上時的影響**（使用者決定）：
  - 門關著時（含推估的關），關聯的輸送線畫成阻斷：紅色實線；只有推估的門時為紅色虛線。
  - 門關著時，如果貨物在關聯輸送線的兩端之間移動，就標示「不一致」，不判斷哪一邊才對（比照 ADR-0005 第 3 點的在席不一致）。
    - 兩個方向都算，不看輸送線的方向（使用者決定）。
    - 推估的關也算（Jev 判斷，0.65）。
    - 只在貨物移動的那一筆事件標示，下一筆事件就不再標示（使用者決定）。
    - 「移動」是指世界模型中棧板位置的改變，兩端為站點、搬送機或對接設備（已交出）。回放不模擬貨物在輸送線上的移動。
- **設備狀態表**列出防火門（Jev 判斷，0.75）。
- 第一版的警報**不**指向防火門（Jev 判斷，0.25）。

### 13. 樓層（2026-11-06 #99 補充）

自動化倉儲可能分布在不同樓層（使用者，2026-11-06）。電梯（#102）與導軌（#100）都依賴樓層。

- **資料**（使用者決定）：
  - 樓層只記錄**名稱與順序**，暫不記錄樓板高度。`floors` 為名稱的陣列，例如 `["1F", "2F"]`（範例／虛構）。
  - 2026-11-14 補充（ADR-0017）：Layout 回放改為 3D、樓層一律上下堆疊，因此樓層新增**樓板高度**（公尺）；舊設定檔沒有時預設 **5 公尺**（使用者決定）。
  - 2026-11-14 實作（#113，使用者決定）：`floors` 改為物件陣列 `{ "name": "1F", "height": 6 }`，`height` 可省略（＝5 公尺）；讀取時名稱與物件都接受。**只要有一層填了樓板高度，就全部寫成物件、格式版本寫 `6`**（舊版程式明確提示改用新版）；都沒有填時照舊寫成名稱陣列，不升版（「用到新功能才升版」）。樓板高度必須大於 0、不超過 100 公尺，存檔前檢查。每層的地板高度＝下面各層樓板高度的和。捨棄：另開 `floorHeights` 欄位不升版（Jev 建議 0.76；使用者選擇物件陣列）。範例（範例／虛構）：`"floors": [ { "name": "1F", "height": 6 }, { "name": "2F" } ]`。
  - Layout 編輯器的樓層列加「樓板高度」欄位與「套用」：設定目前樓層，空白＝恢復預設；改名時跟著改，可以復原。
  - 元素以 `floor` 存樓層**名稱**（Jev 判斷，0.70）。樓層改名時，所有元素一併更新。
  - 輸送線不存樓層，畫在兩端元素的樓層；兩端必須在同一層，跨樓層靠電梯（Jev，1.0）。
  - 舊設定檔沒有 `floors` 時視為只有「1F」；沒有 `floor` 的元素放在第一層。
  - 存檔時一律寫出樓層清單與每個元素的樓層（使用者決定）。
  - **不升格式版本**（使用者決定）：舊版程式會原樣保留樓層欄位，但把所有樓層的元素畫在一起。
  - 名稱不可空白、不可重複，大小寫視為相同，和別名一致（使用者決定）。
  - 刪除還有元素的樓層時擋下，提示先移走或刪除元素（Jev，0.68）；至少保留一層。
- **編輯器**：
  - 2026-11-14 補充（ADR-0018）：編輯器改為 3D，樓層與回放相同上下堆疊，可勾「只顯示目前樓層」；以下單層／並排、橫向／垂直與並排檢視的拖曳**已於 #117 移除**（只適用於 2D 時期）；拖曳不換樓層，換樓層用屬性面板（ADR-0018 第 12 點）。樓層列的新增、改名、上移、下移、刪除與樓板高度不變。
  - 畫布上方的樓層列：樓層頁籤（切換）、新增、改名、上移、下移、刪除，以及單層／並排、橫向／垂直的切換（Jev，0.72）。
  - 移動元素到其他樓層：屬性面板的「樓層」下拉選單，可以多選一起改（使用者決定）。新增與貼上的元素放在「目前樓層」，也就是最後點選的樓層或元素所在的樓層（Jev，0.92）。
  - **並排檢視**（使用者決定）：
    - 可以完整編輯（拖曳、框選、新增、貼上）。
    - 隨時切換橫向（由左到右）或垂直（低樓層在下）。樓層之間留 5 公尺，每層上方標樓層名稱。
    - 元素拖到另一層的區域時，放開後改到那一層，座標換算成該層的座標。
    - 框選跨兩層時，兩層碰到的元素都選到（Jev，0.81）。
  - 單層檢視的畫布大小依該層的元素範圍計算（Jev，0.80）；並排時每層的區域依該層計算。
  - 防火門的「依位置帶入」只加入同一層的輸送線（Jev，0.62）。
  - 單層檢視切換樓層時，看不到的元素取消選取，避免被 Del 刪除或被拖曳一起移動（實作時補充，Jev，0.78）。從元素清單選了別層的元素時，切到那一層。
- **回放**：
  - 2026-11-14 補充：回放改為 3D、樓層一律堆疊（ADR-0017）。編輯器仍為 2D，編輯器的樓層檢視不變。
  - 2026-11-14 實作（#113，使用者決定）：回放的單層／並排、橫向／垂直與樓層頁籤**已移除**（以下兩點只適用於 2D 時期）；「跟隨切換樓層」改為「跟隨（選取時轉向元素）」：從設備狀態表、命令、事件選取元素時 3D 相機轉向該元素，在 3D 上直接點選時不轉向；預設關，記在本機。詳見 ADR-0017 第 11 點。
  - 同樣可以切換單層／並排、橫向／垂直；只有一層時不顯示樓層列。
  - 「跟隨切換樓層」開關（使用者決定，預設關）：開啟時，從設備狀態表、命令或事件跳到某個元素，Layout 切到那個元素所在的樓層。
  - 實作時發現原本只有點 Layout 上的元素才會選取元素，因此補上以下入口（Jev 判斷）：
    - 點設備狀態表的一列，選取 Layout 上的對應元素（0.80）。
    - 選取命令時，選取目前時刻執行它的搬送機；沒有時不選（0.76）。
    - 選取事件時，切到事件欄位中第一個能以別名對應到元素的樓層，不改變選取的元素（0.60）。
    - 並排檢視時不切換。
  - 元素的詳細資訊與設備狀態表標出樓層。
- **本機設定**（使用者決定）：單層／並排、橫向／垂直、跟隨開關，編輯器與回放各自記住；存在本機設定，不寫進廠別設定檔。回放改為 3D 後只記「跟隨」（2026-11-14，#113）。

### 14. 導軌（2026-11-06 #100 補充）

搬送機平時走在導軌上。導軌依廠別設計不同：有的只有一段直線，有的是直線搭配弧線、頭尾相接成一圈（使用者，2026-11-06）。之後搬送機會沿導軌移動（#101）。

- **元素**：
  - 導軌是**輔助元素**：有名稱，沒有別名，不從 LOG 推導狀態（Jev，0.52；樣本中沒有導軌的紀錄）。
  - id 前綴 `rl`。導軌屬於一個樓層（第 13 點）。
- **路徑**：
  - 一串點，每段是直線或弧線，可以頭尾相接（使用者決定）。範例（範例／虛構）：

    ```jsonc
    { "id": "rl-1", "type": "rail", "name": "導軌 1", "floor": "1F", "closed": true,
      "points": [ { "x": 3, "y": 2 }, { "x": 23, "y": 2, "b": 1 }, { "x": 23, "y": 8 }, { "x": 3, "y": 8, "b": 1 } ] }
    ```

  - 弧線以**凸度**表示（Jev，0.25）：`b` 是從這一點到下一點那一段的凸度，0 是直線（可省略）。凸度 = tan(圓心角 / 4)，1 是半圓；正負表示彎的方向：大於 0 時往行進方向（這一點 → 下一點）的左邊彎，以畫面座標（y 往下）為準（實作時定義）。
    - 範圍 |b| ≤ 1，最多到半圓（Jev，0.60）。更大的弧拆成兩段。
  - 座標是樓層座標（公尺）；導軌不存 `x`、`y`、`w`、`h`、`rotation`，範圍由點算出。
- **範本**：
  - 建立後就是一般的自由路徑（Jev，0.80）。
  - 直線：長 20 公尺。
  - 跑道形環：直線段長 20 公尺，兩條直線相距 6 公尺，兩端各一個半圓，閉合（Jev，0.76）。
- **搬送機與導軌**：
  - 搬送機以 `rail` 存所走導軌的 id（Jev，0.62）。一台搬送機屬於一條導軌，一條導軌可以有多台搬送機。
  - 屬性面板的「導軌」選單只列同一層的導軌。
  - 存檔前檢查：導軌必須存在，而且和搬送機同一層（Jev，0.79）。
  - 刪除導軌時，指定它的搬送機自動清除指定，可以復原（使用者決定）。
  - 貼上的搬送機一律清除導軌指定（使用者決定）。
- **編輯器**：
  - 選取導軌時，每個點與每段的中點有把手（Jev，0.72）。
    - 拖曳點：移動那一點，吸附 0.5 公尺（Jev，0.71）。
    - 拖曳中點：把直線變弧線、調整彎度；弧高（中點離弦的距離）吸附 0.5 公尺（使用者決定），凸度限制在 |b| ≤ 1。
  - 插入點（使用者決定兩種都提供）：
    - 選一段（點中點把手，或在屬性面板選）後按「插入點」，插在那一段的中點。
    - 在畫布上雙擊導軌，插在雙擊處。
  - 屬性面板另有「刪除點」（至少保留 2 點）、「這段改直線」、「閉合」。
  - 拖曳線條時整條移動（吸附 0.5 公尺）；旋轉按鈕以外框中心轉 90 度，和其他元素一致（Jev，0.96）。
  - 框選碰到任一段就算選到，和輸送線一致（Jev，0.50）。
  - 複製貼上、刪除、復原都支援。
- **回放**：畫出導軌，不推導狀態。
- **格式版本**：有導軌時寫 `4`（Jev，0.65），舊版程式會明確提示改用新版。
- **幾何計算**（供 #101 使用）：路徑全長、點投影到路徑（取最近點與它在路徑上的長度位置）、依長度位置取座標。弧線以精確公式計算。
- 搬送機沿導軌移動的規則見 ADR-0005 第 10 點（2026-11-06 #101）。

### 15. 電梯（2026-11-06 #102 補充）

電梯在樓層之間搬送貨物。和搬送機是不同的元素種類，因為兩者有不同的 LOG（使用者，2026-11-06）。狀態的推導見 ADR-0005 第 11 點。

- **元素**：
  - `type: "elevator"`，id 前綴 `ev`，預設 2 × 2 公尺、高 3 公尺（Jev，0.68）。可以有別名。
  - 不使用一般元素的 `floor`，改存 `servedFloors`（服務的樓層），至少兩層（Jev，0.97）。範例（範例／虛構）：`{ "id": "ev-1", "type": "elevator", "name": "電梯 1", "aliases": ["L1"], "servedFloors": ["1F", "2F"], "x": 10, "y": 4, "w": 2, "h": 2, "rotation": 0 }`。
  - 電梯在服務的每一層、同一個位置畫出來。
  - 新增時預設服務所有樓層（使用者決定）；只有一層時存檔前會提示至少兩層。
- **編輯器**：
  - 屬性面板列出所有樓層的勾選框，勾選的就是服務的樓層（Jev，0.88）。
  - 任何一層都可以選取、拖曳、調整大小，所有樓層的圖示一起變（使用者決定）。並排時拖到別層**不會**換樓層；服務的樓層只在屬性面板修改。
  - 樓層改名時 `servedFloors` 一併更新；刪除電梯服務的樓層時擋下，提示先從服務樓層移除（Jev，0.86）。
- **輸送線**：不能接到電梯；電梯只透過每層的出入口站點和其他設備交接（Jev，0.60）。
- **格式版本**：有電梯時寫 `5`（Jev，0.80）。

### 16. RM 與排的配置表（2026-11-15 #121 補充，見 ADR-0019）

- 新增元素種類 `rm`（RM）：有 LOG 意義、可以有別名、可以指定所走的導軌（`rail`），其他欄位比照搬送機。
- 儲位編號格式為 RCCCLL（排 1 碼、列 3 碼、層 2 碼，使用者說明）；`storageCodeRule` 照舊由使用者在廠別設定填寫。
- `layout` 新增選填的 `rows`（排的配置表）：每列 `{ "row": "1", "rm": "rm-1", "depth": "deep", "pair": "2" }`（範例／虛構）；單深的廠只填 `row` 與 `rm`，或整個不填。沒有填時視為單深、排不屬於任何 RM。
- 存檔前檢查：排號不重複；`rm` 指向存在的 RM 元素；`depth` 為 `deep` 或 `shallow`；配對的兩排互相指向、一深一淺、所屬 RM 相同。
- **格式版本**：有 RM 或排的配置表時寫 `7`；否則照舊。

## 理由

- 把有 LOG 意義的元素與輔助元素分開，回放推導只需要處理前者；輔助元素讓畫面好讀，又不會被誤認為有狀態。
- 完全比對加上別名唯一，可以避免一個編號同時對應到兩個元素卻沒人察覺；萬用字元在除錯時容易造成誤判。
- 「載入案件比對」讓使用者從實際 LOG 出發補齊對應，遺漏一目了然。
- 料架只畫列、不畫層，俯視時看得到每一列又不擁擠；層數與每層高度已保存，日後升級 3D 不必重新建 Layout。
- 以公尺為單位、只允許直角旋轉，2D 畫面簡單，日後 3D 可以直接沿用座標。
- Layout 主要由編輯器產生，JSON 讀寫簡單、格式嚴謹；放在同一個廠別設定檔，分享時只要一個檔案。
- 案件保存快照，舊案件的回放結果可以重現；別名修正是否套用由使用者決定。
- 原型比較後，三欄式最容易同時看到畫布、屬性與未對應清單。
- 輸送線（2026-10-19）：現場有雙向的輸送線，也有直接把貨交給搬送機的輸送線（使用者，2026-10-19）；以交接點連到搬送機，第一階段（搬送機固定）與日後搬送機會移動時都能正確顯示。
- 選取、剪貼簿、復原與畫布大小（2026-10-19）：實際建 Layout 時元素多、範圍大，逐一新增與單選操作費時，固定大小的畫布不夠用（使用者，2026-10-19）。
- 防火門（2026-11-06）：
  - 防火門關上時，貨物無法通過。回放時看得到門的開關，工程師就能判斷搬送中斷是否和防火門有關。
  - 樣本中沒有防火門的 LOG，所以另外提供平時狀態。推估一律標示出來，不和 LOG 確定的狀態混在一起（ADR-0005 第 7 點：不猜測）。
  - 用兩種效果、不辨識文字：哪一行代表開或關由規則決定，不必在程式中假設 LOG 的寫法。
- 樓層（2026-11-06 #99）：
  - 一次看一層最清楚；並排可以一眼看到跨樓層的搬送（日後經由電梯）。
  - 樓層名稱就是識別：設定檔好讀，手動修改也直覺；改名時由編輯器一併更新元素。
  - 不升格式版本：舊版程式仍能開啟與存檔，樓層欄位不會遺失；只是畫面會疊在一起（使用者接受）。
- 電梯（2026-11-06 #102）：
  - 電梯有自己的 LOG（使用者），獨立的元素種類讓兩者的規則與狀態互不影響。
  - 服務的樓層用清單：電梯不一定停靠每一層；清單比最低到最高樓層精確。
  - 輸送線不接電梯：交接在每層的出入口站點，LOG 也是從站點到站點。
- 導軌（2026-11-06 #100）：
  - 凸度表示法每段只要一個數字，直線與弧線用同一種結構，檔案精簡；CAD 也常用，換算成圓心與半徑很簡單。
  - 範本建立後就是自由路徑：只有一種資料結構，編輯方式一致；跑道形環要稍作調整時不必轉換。
  - 存在搬送機上：一台搬送機只會走一條導軌，存在搬送機上不會重複。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 別名支援萬用字元或規則式比對 | 一個編號可能對應到兩個元素卻沒人察覺 |
| 料架逐格畫出所有層 | 2D 俯視時層會重疊，畫面擁擠；改用側視圖 |
| 以像素為單位、可任意角度旋轉 | 換成 3D 時無法沿用；任意角度讓 2D 編輯變複雜 |
| YAML 格式 | 人工閱讀較方便，但縮排錯誤不易發現；Layout 主要由編輯器產生，不太需要人工修改 |
| Layout 與其他廠別設定分成多個檔案 | 分享時容易漏掉檔案 |
| 案件一律使用最新版 Layout | 舊案件的回放結果可能改變，無法重現 |
| 畫布優先版面（工具與屬性浮動，未對應在抽屜） | 浮動面板會遮住畫布，未對應清單需要額外開關 |
| 對應優先版面（表格與下拉選單為主） | 畫布變小；以下拉選單對應不如拖曳直覺 |
| 輸送線維持只能接站點或對接設備（2026-10-19） | 不符合現場；在中間另放站點會多出 LOG 中不存在的元素 |
| 輸送線畫到搬送機中心（2026-10-19） | 日後搬送機會移動時，交接位置不對 |
| 輸送線畫到搬送機圖示最近的邊緣、不另存座標（2026-10-19） | 搬送機移動時線跟著移動，不代表固定的交接位置 |
| 方向用文字欄位 `direction`（2026-10-19） | 目前只需要單向與雙向 |
| 畫面上用箭頭表示方向（2026-10-19） | 使用者決定不畫 |
| 使用 Windows 剪貼簿（2026-10-19） | 不需要跨程式貼上；內部剪貼簿較簡單 |
| 貼上時不帶別名（2026-10-19） | 使用者決定照抄，由存檔檢查擋下重複 |
| 框選時元素完全在框內才算（2026-10-19） | 使用者決定碰到就算 |
| 畫布大小可以手動設定並存進設定檔（2026-10-19） | 使用者決定只自動加大 |
| 沒有 LOG 的門檻只用一個全廠別的數值（2026-10-21 #84） | 有心跳與有事情才寫 LOG 的模組，合適的門檻相差很大 |
| 防火門只當輔助元素，不和 LOG 對應（2026-11-06） | 使用者要求回放時依 LOG 開關 |
| 回放時沒有 LOG 事件就把平時狀態當成確定的狀態（2026-11-06） | 和 LOG 確定的狀態分不出來；改為標示「推估」 |
| 一種效果加「門狀態」文字，由廠別設定對照開或關（2026-11-06） | 使用者選兩種效果，規則較簡單 |
| 只依位置自動判斷關聯的輸送線，不另外存（2026-11-06） | 線畫在中心之間，可能誤碰；使用者選手動指定加上依位置帶入 |
| 不一致一直顯示到門的下一次變化，或到案件結束（2026-11-06） | 使用者決定只在那一筆事件標示 |
| 單向輸送線只看 from → to 方向（2026-11-06） | 門關著時兩個方向都過不去；使用者決定都算 |
| 樓層有 id 與名稱兩個欄位（2026-11-06 #99） | 多一層對應；名稱改名由編輯器一併更新即可（Jev） |
| 樓層記錄樓板高度（2026-11-06 #99） | 使用者決定暫不記錄，需要 3D 時再加 |
| 用到樓層時升格式版本（2026-11-06 #99） | 使用者決定不升，讓舊版仍能開啟 |
| 刪除樓層時連同元素刪除，或移到另一層（2026-11-06 #99） | 容易誤刪或移錯；改為擋下（Jev） |
| 輸送線可以跨樓層，或自己存樓層（2026-11-06 #99） | 跨樓層搬送靠電梯；輸送線畫在兩端之間（Jev） |
| 並排檢視只能看（2026-11-06 #99） | 使用者決定可以完整編輯 |
| 並排時拖曳不能換樓層（2026-11-06 #99） | 使用者決定放開時改到滑鼠所在的樓層 |
| 只有一層 1F 時不寫樓層欄位（2026-11-06 #99） | 使用者決定一律寫出 |
| 電梯沿用搬送機的元素種類（2026-11-06 #102） | 搬送機有不同的 LOG（使用者） |
| 電梯存最低與最高樓層，或畫在所有樓層（2026-11-06 #102） | 電梯不一定停靠每一層（Jev） |
| 輸送線可以接到電梯（2026-11-06 #102） | 要決定輸送線畫在哪一層，規則較複雜；交接在出入口站點（Jev） |
| 只在第一個服務的樓層編輯電梯（2026-11-06 #102） | 使用者決定任何一層都可以編輯 |
| 刪除樓層時自動從服務樓層移除（2026-11-06 #102） | 容易不小心改到電梯（Jev） |
| 導軌可以有別名、和 LOG 對應（2026-11-06 #100） | 樣本中沒有導軌的紀錄；搬送機的移動依搬送機的事件計算（Jev） |
| 弧線存三點，或圓心＋半徑＋角度（2026-11-06 #100） | 點與弧要分開存，結構較複雜（Jev） |
| 範本存成種類＋參數（2026-11-06 #100） | 兩種資料結構；改成不規則形狀時要轉換（Jev） |
| 只在屬性面板以表格編輯點（2026-11-06 #100） | 不直覺（Jev） |
| 導軌列出走在上面的搬送機，或取最近的導軌（2026-11-06 #100） | 一台搬送機可能被列在兩條導軌；最近的不一定正確（Jev） |
| 凸度不限制（2026-11-06 #100） | 拖曳時彎度可能變得極大；超過半圓的弧可以拆成兩段（Jev） |
| 刪除導軌時擋下（2026-11-06 #100） | 使用者決定自動清除指定 |
| 貼上搬送機時沿用或改指定導軌（2026-11-06 #100） | 使用者決定一律清除 |
| 有防火門時仍寫格式版本 2（2026-11-06） | 舊版程式讀到不認得的種類時，只會顯示 JSON 錯誤，看不出是版本太舊 |
| 門檻的模組名稱自由輸入（2026-10-22 #86） | 實際使用時填到不是模組的名稱，門檻靜默不生效 |
| 下拉選項取自開啟中案件的模組（2026-10-22 #86） | 編輯器開啟時不一定有案件；模組順序是設定檔中的模組清單 |
| 下拉選單也允許自由輸入（2026-10-22 #86） | 仍然可能填錯 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 兩套站點編號沒有對照表，手動對應費時 | 建立 Layout 的成本高 | 未對應清單附出現次數，先處理最常出現的；日後改為匯入對照表。→ 2026-10-19 #47：現場沒有對照表，維持手動對應 |
| 其他廠別的儲位編號不符合字母樣式規則 | 無法拆出排、列、層 | 規則放在 Layout 中；遇到不符時再以新的 ADR 擴充 |
| 料架不是直線排列（例如 L 形） | 單一長方形無法表示 | 以多個料架元素拼接；必要時再擴充 |
| 單一 JSON 檔變大（元素很多時） | 讀寫與比對變慢 | 在實作階段以實際廠別規模測試 |
| 多人各自修改同一份設定檔後互相覆蓋（2026-10-16 #22） | 修改遺失 | 修訂號、修改人與時間寫在檔案中，可以判斷是誰的版本；第一階段不做合併 |
| 舊版程式開啟有雙向或連到搬送機的輸送線的設定檔（2026-10-19） | 舊版保留新欄位，但存檔檢查會擋下連到搬送機的輸送線；雙向會被當成單向顯示 | 用到新功能時格式版本寫 2，舊版明確提示改用新版（2026-10-19 #63） |
| 框選碰到就算，可能誤選大的區域或料架（2026-10-19） | 刪除或移動到不想動的元素 | Ctrl＋點選取消選取；Ctrl+Z 復原 |
| 解析規則等區段尚未定義（#23；時區已於 #19 加入） | 加入時要改格式 | 認不得的欄位會保留；加入區段時評估是否需要升格式版本 |
| 只修改沒有 LOG 的門檻也要重新解析案件（2026-10-21 #84） | 大案件套用新版較久 | 先維持快照規則；太慢時再評估讓門檻不必重新解析 |
| 模組順序沒有列出全部模組（2026-10-22 #86） | 沒列出的模組無法設定門檻，只能用預設 300 秒 | 把該模組加進模組順序（也會決定相同時間戳記時的排序） |
| 防火門的 LOG 樣式、是否有開關回報都**待確認**（2026-11-06） | 沒有 LOG 時只能顯示推估或未取得資訊；不一致只能依推估判斷 | 推估一律標示；取得樣本後在本機設定填寫規則（O-017） |
| 推估的關造成的不一致可能是誤報（2026-11-06） | 實際上門是開的，卻標示不一致 | 詳細資訊註明是推估；取得 LOG 後以 LOG 為準 |
| 世界模型的棧板位置不一定逐站記錄（2026-11-06） | 貨物經過門、但 LOG 只記錄起點與終點時，不會被判斷為穿越 | 只判斷關聯輸送線兩端之間的直接移動；需要時再擴充 |
| 舊版程式開啟有防火門的設定檔（2026-11-06） | 無法開啟 | 格式版本寫 3，舊版明確提示改用新版 |
| 舊版程式開啟有多層的設定檔（2026-11-06 #99） | 所有樓層的元素畫在一起，看不出樓層；仍可存檔，樓層欄位保留 | 使用者接受；分享設定檔時一併更新程式 |
| 並排時拖曳不小心換到別的樓層（2026-11-06 #99） | 元素跑到錯的樓層 | Ctrl+Z 復原；輸送線兩端不同層時存檔擋下 |
| 凸度最多半圓（2026-11-06 #100） | 大於半圓的弧要拆成兩段 | 插入點後各段分別調整 |
| 導軌的形狀沒有樣本依據（2026-11-06 #100） | 畫出來的導軌可能和現場不符 | 由工程師依現場繪製；#101 的位置一律標為推估 |
| 舊版程式開啟有導軌的設定檔（2026-11-06 #100） | 無法開啟 | 格式版本寫 4，舊版明確提示改用新版 |
| 舊版程式開啟有電梯的設定檔（2026-11-06 #102） | 無法開啟 | 格式版本寫 5，舊版明確提示改用新版 |

## 後續驗證方式

- 以樣本 LOG 建立一份 Layout，確認所有站點、搬送機、對接設備編號都能對應，未對應清單歸零。
- 確認重複的別名會被擋下，大小寫不同的編號視為相同。
- 確認新版程式能讀取 `formatVersion` 較舊的設定檔。
- 確認 Layout 更新後，舊案件仍使用快照，套用新版後回放結果隨之更新。
- 以樣本建 Layout 時，確認輸送線可以連到搬送機、雙向設定可以存檔與重新開啟；框選、複製貼上、刪除與復原可以正常操作；超過 60 × 40 公尺的 Layout 在編輯器與回放畫面都看得到（2026-10-19）。
- 取得含防火門開關的 LOG 後，填寫規則，確認回放時門的開關、輸送線阻斷與不一致標示和現場一致（2026-11-06）。
- 以多樓層的虛構 Layout 確認：舊檔開啟在 1F、改名與刪除樓層、跨層拖曳、並排的橫向與垂直、回放的跟隨切換（2026-11-06 #99）。
- 以虛構 Layout 確認電梯：服務的樓層勾選、在每一層畫出來、任何一層拖曳時一起移動、樓層改名與刪除、輸送線不能接（2026-11-06 #102）。
- 以虛構 Layout 確認：直線與跑道形環的範本、點與中點的拖曳、插入與刪除點、閉合、整條移動與旋轉、搬送機指定導軌；幾何計算（全長、投影、依長度取位置）有單元測試（2026-11-06 #100）。

## 影響範圍

- **回放畫面與操作**：沿用三欄式中的畫布、料架側視圖、未對應清單與在席指示燈位置。
- **用戶端技術選型**：需要 2D 畫布、拖曳與格線吸附、讀寫 JSON；日後可能升級 3D。
- **儲存與索引候選方案比較**：案件需要保存 Layout 快照。
