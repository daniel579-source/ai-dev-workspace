# ADR-0007：用戶端技術選型

- 日期：2026-10-16
- 狀態：已接受（**待技術驗證**）
- 確認者：repo owner（daniel579-source）
- 對應 ticket：Wayfinder「用戶端技術選型」
- 相關決策：ADR-0001（單機桌面程式）、ADR-0005（回放的世界模型）、ADR-0006（Layout 模型與設定檔）

## 背景

- 部署形態為單機桌面程式：Windows 10／11 64 位元、免安裝、完全離線、手動替換更新、新版要能讀舊版資料（ADR-0001）。
- 用戶端需要：Docking 多視窗、Layout 編輯畫布（拖曳、調整大小、格線吸附、直角旋轉）、清單之間的拖放、大量事件的時間軸、讀寫 JSON 格式的廠別設定檔（ADR-0006）。
- 第一階段回放為 2D 俯視；使用者希望日後升級成 3D（ADR-0005）。
- 事實：
  - 系統由熟悉 **C#** 的人開發與維護（使用者確認）。
  - 現有倉儲系統以 .NET 開發（樣本 LOG 的錯誤堆疊中有 .NET 例外類別）。
  - 目標電腦是否一定有 **WebView2 Runtime**：**不確定**。
- 評估條件的優先順序（使用者確認）：
  1. 團隊能長期維護。
  2. 大量事件的顯示效能。
  3. Docking 元件成熟度。
  4. 免安裝打包可靠。
  5. 日後能否加入 3D。
  6. 執行檔大小與記憶體用量。

## 決策

### 1. 技術組合

**C# + .NET 10（LTS）+ WPF**。以 **self-contained** 方式發佈（執行環境一起打包），目標電腦不需要安裝 .NET，也**不依賴 WebView2**。

### 2. 打包與更新

- 發佈成**單一資料夾**（壓成 zip），解壓後執行其中的 exe。
- 更新時整個資料夾替換。
- 案件與使用者資料**不放在程式資料夾內**，替換程式不影響資料；存放位置由「儲存與索引候選方案比較」決定。

### 3. 元件政策

- 以**免付費即可使用**的元件為主，優先選擇開放原始碼、允許商業使用的授權（MIT、Apache 2.0、MS-PL 等）。
- 有條件的免費授權（例如以公司營收或人數為條件的社群版），採用前要確認公司符合條件並記錄。
- 初步組合（**候選方案**，技術驗證後確定）：

| 用途 | 元件 | 授權 |
|---|---|---|
| Docking 多視窗 | AvalonDock（Dirkster.AvalonDock 5.0.1；版面儲存另需 Dirkster.AvalonDock.Serializer.Xml） | MS-PL |
| MVVM 架構 | CommunityToolkit.Mvvm | MIT |
| 事件列表 | WPF 內建虛擬化清單（技術驗證後建議 ListView＋GridView、固定列高） | — |
| 時間軸、Layout 畫布 | 自行繪製（時間軸的密度長條畫進點陣圖再一次送出） | — |
| 日後的 3D | HelixToolkit | MIT |

### 4. 技術驗證

進入實作後的第一件事，確認：

1. 10 萬筆事件的清單與時間軸可以流暢捲動。
2. AvalonDock 可以儲存與還原視窗配置。
3. self-contained 資料夾能在**乾淨、離線**的 Windows 10 上直接執行。
4. 2D 畫布的拖曳與縮放順暢。

不通過時，退回 Avalonia，或重新評估；結果以新的 ADR 或更新本 ADR 狀態記錄。

### 5. 技術驗證結果（2026-10-16，開發用電腦）

驗證程式與數據：`validation/`（#15）；摘要見 `validation/results/summary-dev-pc.md`。使用虛構資料。

| 項目 | 結果 | 判定 |
|---|---|---|
| 1. 10 萬筆清單 | 每格換掉整個可見範圍的極端情境：DataGrid 約 21 fps、ListView 約 31～36 fps | **待體感確認** |
| 1. 時間軸 | 60 fps（密度長條畫進點陣圖；每欄一個幾何圖形只有約 8 fps） | 通過 |
| 2. 版面儲存與還原 | 儲存、改變、還原後完全相同；損壞的版面檔可退回預設 | 通過 |
| 3. self-contained | 單一資料夾 136 MB（zip 59 MB），本機確認 self-contained 執行 | 本機通過；**乾淨、離線的 Windows 10 待測** |
| 4. 2D 畫布 | 縮放＋平移 60 fps；拖曳元素 54 fps | 通過 |

狀態維持「待技術驗證」，第 1 項的體感與第 3 項完成後再更新。實作（#16 起）依下列結果進行：

- AvalonDock 使用 5.0 版：版面序列化拆到 `Dirkster.AvalonDock.Serializer.Xml` 套件，API 與 4.x 不同。
- 事件清單建議使用 ListView＋GridView、固定列高；DataGrid 每格的版面配置成本約為 ListView 的 1.7 倍。體感仍不順時，再考慮自行繪製的清單。
- 時間軸等大量圖形先畫進點陣圖再一次送出，不要每個資料點一個幾何圖形。

## 理由

- 維護者熟悉 C#，現有倉儲系統也是 .NET，長期維護的風險最低（評估條件 1）。
- WPF 的虛擬化清單、AvalonDock 都很成熟，符合評估條件 2、3。
- self-contained 加單一資料夾，不需要安裝任何執行環境，也避開 WebView2 是否存在的不確定性（評估條件 4）。
- HelixToolkit 以 DirectX 繪製 3D，日後升級不必更換技術（評估條件 5）。
- 單一資料夾比單一 exe 檔可靠：單檔發佈會在執行時把原生元件解壓到暫存資料夾，可能被公司資安政策擋下。
- .NET 8 的支援期到 2026 年 11 月結束；.NET 10 是 LTS，支援到 2028 年 11 月。
- 第三方元件以免付費為主，避免每年的授權費與授權管理負擔。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| Electron + 網頁技術 | 要以網頁技術開發，不是維護者熟悉的 C#；執行檔約 150 MB 以上、記憶體用量大；原生模組讓打包變複雜。3D 最方便，但不足以抵銷維護成本 |
| Tauri + 網頁技術 | 依賴 WebView2，而目標電腦是否一定有 WebView2 不確定；後端要寫 Rust |
| .NET + WinForms | 日後的 3D 支援弱；2D 互動與縮放要自己處理的部分較多。**保留為備案** |
| .NET + Avalonia | 主要優點是跨平台，但本案只在 Windows 上使用；Docking 套件比較不成熟。**作為技術驗證失敗時的退路** |
| 商業元件套件（DevExpress、Telerik、Syncfusion 等） | 要付授權費；以免付費元件為主 |
| 單一 exe 檔發佈 | 原生元件在執行時解壓到暫存資料夾，可能被資安政策擋下 |
| .NET 8 | 支援期即將結束 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 大量事件的時間軸效能不足 | 畫面卡頓 | 技術驗證第 1 項；時間軸自行繪製並只畫可見範圍 |
| AvalonDock 維護停滯（社群維護的分支） | 遇到問題需要自己修 | 授權允許修改原始碼；備案為 WinForms 的 DockPanel Suite 或 Avalonia |
| AvalonDock 5.0 是新的主版本，API 與 4.x 不同 | 網路上的範例多半不適用；可能有新版本的問題 | 以技術驗證的寫法為準；版面檔損壞時退回預設版面 |
| 事件清單捲動不夠順 | 大量事件時操作卡頓 | 改用 ListView、固定列高；必要時自行繪製清單 |
| 公司資安政策擋下未簽章的 exe | 無法執行 | 部署前向 IT 確認；必要時對執行檔做程式碼簽章 |
| self-contained 資料夾較大（約數十至一百多 MB） | 分發較慢 | 可以接受；壓成 zip 分發 |
| 日後 3D 改用 HelixToolkit 的學習成本 | 3D 開發時間較長 | 3D 不在第一階段範圍；屆時再評估 |

## 後續驗證方式

- 依第 4 點進行技術驗證，並記錄結果（開發用電腦的結果見第 5 點）。
- 尚待完成：事件清單的實際操作體感；乾淨、離線的 Windows 10（`validation/README.md` 的手動檢查）。
- 在乾淨、離線的 Windows 10 與 Windows 11 上，解壓後直接執行，確認不需要額外安裝任何元件。
- 列出所有第三方元件與授權，確認都可以免費用於公司內部。

## 影響範圍

- **回放畫面與操作**：畫面以 WPF＋AvalonDock 實作；原型仍然可以用 HTML 做，只用來確認畫面。
- **儲存與索引候選方案比較**：儲存元件要能從 .NET 使用、能放進 self-contained 資料夾；資料不放在程式資料夾內。
- **敏感資訊處理與存取權限**：存取控制以單機桌面程式的條件設計（例如作業系統帳號）。
