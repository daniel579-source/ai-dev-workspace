# ADR-0008：回放畫面與操作

- 日期：2026-10-16
- 狀態：已接受
- 確認者：repo owner（daniel579-source）
- 對應 ticket：Wayfinder「回放畫面與操作」
- 相關決策：ADR-0003（時間策略）、ADR-0004（事件模型與排序規則）、ADR-0005（回放的世界模型）、ADR-0006（Layout 模型與設定檔）、ADR-0007（用戶端技術選型）

## 背景

- 回放要依 LOG 在 Layout 上重現站點、搬送機、儲位、貨物的狀態（ADR-0005）；大部分事件（例如 SQL、除錯訊息）不會改變狀態。
- 必須呈現四種時間不確定性與事件旗標（ADR-0003、ADR-0004），並提供混合與分軌兩種事件檢視（使用者需求）。
- 畫面以 WPF + AvalonDock 實作（ADR-0007）；Layout 畫布、料架側視圖與在席指示燈位置沿用 Layout 編輯器（ADR-0006）。
- 以文件草案討論操作規則後，做了可點擊的 HTML 原型（虛構資料，含 3 個命令、警報、不一致與各種旗標）；使用者試用後確認**操作順手、沒有缺少的功能**。原型保留在 `prototype/playback-ui` 分支，不合併到 `main`。

## 決策

### 1. 方向鍵

| 按鍵 | 動作 |
|---|---|
| → ／ ← | 下一個／上一個**狀態變化**（會改變任何元素狀態的事件） |
| Shift + → ／ ← | 下一筆／上一筆**事件** |
| Ctrl + → ／ ← | 下一筆／上一筆**符合目前篩選條件**的事件 |
| 空白鍵 | 播放／暫停 |
| Home ／ End | 跳到案件開頭／結尾 |

2026-10-16 #25 補充：焦點在輸入框時不攔截按鍵；到頭或尾時停在原地並說明原因；搜尋中或「只看這個元素」時，→、Shift ＋ →、Home／End 都只在顯示中的事件之間移動。

### 2. 播放

- 速度：×1、×2、×5、×20、×60。
- 「**略過閒置時段**」：超過 N 秒（預設 10 秒）沒有狀態變化時，直接跳到下一個變化；可以關閉。
- 2026-10-16 #25 補充：依實際經過的時間 × 速度推進。略過閒置時段的判斷是「下一個狀態變化在 10 秒以後」時直接跳到它。播到結尾時停止；在結尾按播放時從頭開始。

### 3. 時間軸

- **總覽**：整個案件的事件密度長條圖、警報期間（紅色區段，從發生到復歸；沒有復歸時延伸到案件結束）、時間不確定的位置（刻度標示）。
- **細部**：目前時刻前後 30 秒；狀態變化以長刻度、其他事件以短刻度表示，顏色代表模組。
- 兩者都可以點擊或拖曳以跳到任意時刻。
- 異常熱區第一階段以**警報期間**與**單位時間內的警報次數**呈現；正式判定方式另行決定。
- 2026-10-16 #25 補充：「時間不確定」指時間倒退與時間無效的事件。總覽同時標出搜尋符合的位置（ADR-0010 第 4 點）。「單位時間內的警報次數」尚未實作。
- 2026-10-21 #84 補充：**沒有 LOG 的時段**（FR-037）。
  1. 以**模組**（LOG 來源）為單位：同一模組相鄰兩筆事件的間隔超過門檻時，該段標示為「這段時間沒有 LOG（可能是閒置或缺漏）」，不斷定是缺漏。
  2. 門檻預設 300 秒；可以依模組在廠別設定 `gapThresholds` 調整，0 表示該模組不標示（ADR-0006）。
  3. 案件開頭與結尾：模組的第一筆事件比案件開始晚、或最後一筆比案件結束早，且超過門檻時也標示。案件的開始與結束為全部事件最早與最晚的時間。
  4. 時間基準與時間軸相同（校正後時間）；所有事件都納入計算，包括時間無效（時間為沿用）的事件。
  5. 顯示：時間軸總覽每個模組一條細列，以灰色斜線表示，滑鼠移上去顯示「模組 X：開始～結束 沒有 LOG（N 分鐘）」；目前時刻落在某模組的時段中時，回放與詳細資訊顯示「目前時刻 模組 X 沒有 LOG」。點選跳到時段的缺口清單之後再做。
  6. 開啟案件時在記憶體中計算（與狀態快照相同，ADR-0011），不存進案件資料庫。

### 4. 面板連動

- 所有面板共用**一個「目前時刻」**。
- 在事件清單選一筆事件 → 時間軸、Layout、原始 LOG 一起跳到該時刻與該行。
- 點 Layout 上的元素 → 詳細資訊顯示該元素；「**只看這個元素**」把事件清單篩選成與該元素（含所有別名）相關的事件。
- 點命令編號 → 列出該命令串起來的所有跨模組事件，點一筆即跳到該時刻。
- 2026-10-16 #25 補充：目前時刻是一個時間點，不一定要落在事件上。跳到某個時刻時，Layout 顯示該時刻（含）之前所有事件套用後的狀態，事件清單選取該時刻之前最後一筆顯示中的事件。「只看這個元素」以搜尋的元素篩選實作，以「清除搜尋」恢復。
- 2026-10-16 #24 補充：時間軸（#25）完成之前，「目前時刻」是事件清單選取的事件。「元素狀態」面板的每一列都附上造成該狀態的事件，可以跳過去。

### 5. 事件清單

- 欄位：時間、模組、Logger、等級、訊息、旗標；會改變狀態的事件另外標記。
- **混合檢視**（預設）：以底色區分模組。**分軌檢視**：每個模組一欄。
- 旗標以圖示呈現並附圖例：同時間戳記、時間倒退、時間無效（時間為沿用）、未知種類、編碼錯誤；滑鼠移上去顯示說明。
- 「目前時刻」之後的事件以淡色顯示。
- 畫面頂端顯示時區；案件設定偏移量時，頂端明顯標示「已校正」與偏移量。
- 2026-10-16 #19 補充：頂端右側顯示時區、「已校正（…）」與「時間校正…」按鈕。旗標新增「± 已校正」。詳細資訊顯示原始時間，以及校正前後的時間。

### 6. 面板

| 面板 | 內容 |
|---|---|
| Layout 回放 | 世界狀態（ADR-0005 的顏色、在席指示燈、不一致提示、搬送機三層狀態），附圖例 |
| 詳細資訊 | 站點、搬送機、對接設備、貨物（含桶清單）、料架某一列的側視圖 |
| 時間軸 | 第 3 點 |
| 事件清單 | 第 5 點 |
| 原始 LOG | 依**原始行序**顯示目前事件所在檔案，標出該行；時間倒退的行維持原位 |
| 命令 | 每個命令目前的狀態，以及到案件結束時的狀態（已完成或「案件範圍內未完成」） |
| 設備狀態表 | 所有站點、搬送機、對接設備在目前時刻的狀態；可排序，可以只看「異常中或不一致」 |
| 未對應的編號 | 目前時刻前後 30 秒內出現、但 Layout 還沒對應的編號，附附近次數與案件中總次數（2026-10-16 #26 修改；原為「案件中出現」的編號） |

2026-10-16 #26 補充：

- 命令：欄位為命令、事件數、目前時刻的狀態、案件結束時的狀態（未完成時為「案件範圍內未完成（…）」）。選一個命令後，下方列出串起來的事件，點一筆跳到該時刻；該事件被篩選掉時改為顯示全部。
- 設備狀態表：狀態以分號串接，例如「在席 ON；貨物 …；不一致」「連線 …；模式 …；閒置」「異常中（警報 …）」。可依名稱、種類、異常、狀態排序，再按同一欄反向。異常＝有未復歸的警報或不一致，以紅底標示。與 Layout 面板使用同一份世界狀態。
- 未對應的編號：只列目前時刻前後 30 秒內出現的站點、搬送機、對接設備編號，避免大案件的清單過長、與目前時刻無關；已對應的編號不列出。整個案件的比對在 Layout 編輯器中進行（ADR-0006）。

### 7. Docking 版面

- 版面配置**依使用者保存**，不依案件保存。
- 預設版面：「**回放**」（Layout 為主）與「**搜尋**」（事件清單為主）；提供「**還原預設**」。

2026-10-16 #28 補充：

- 從選單「版面」切換兩種預設版面，或還原預設。「還原預設」等於「回放」版面，也就是初次啟動時的版面。
- 回放：左邊是案件與搜尋；中間上方是事件清單與 Layout 回放（Layout 較寬）；接著是時間軸；下方是詳細資訊、元素狀態等分頁、原始 LOG。
- 搜尋：左邊搜尋面板在前；中間上方是事件清單（較寬）與詳細資訊；接著是時間軸；下方是原始 LOG、Layout 回放、元素狀態等分頁。
- 關閉程式時，版面存到使用者的本機資料夾（`layout.xml`），啟動時還原。版面檔無法讀取，或面板與目前程式不同（來自其他版本的程式）時，改用預設版面並在狀態列提示，不影響啟動。
- 面板不能關閉也不能隱藏，避免找不回來；浮動、自動隱藏、拖曳重排都可以。

## 理由

- 大部分事件不改變狀態；以「狀態變化」為預設的一步，按一次就看得到變化，其他兩種步進則保留逐筆檢查與聚焦單一元素的能力。
- 「略過閒置時段」讓長時間沒有變化的段落不必等待。
- 共用一個「目前時刻」，任何面板的操作都能同步其他面板，符合「以時間為核心」的目標。
- 原始 LOG 依原始行序顯示，時間倒退的事件在時間軸上被移動後仍能看到它原本的位置（ADR-0004）。
- 設備狀態表在元素很多時比在 Layout 上尋找更快。
- 版面依使用者保存，換案件時不必重新調整。
- 原型試用確認操作順手。
- 沒有 LOG 的時段（2026-10-21 #84）：只看時間無法分辨缺漏與閒置（以真實樣本統計：有心跳的模組間隔固定，有事情才寫 LOG 的模組可以數小時沒有事件），所以標示中性的事實，由工程師判斷；依模組設定門檻，有心跳的模組可以設小，抓出心跳中斷。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 方向鍵一步＝下一筆事件 | 大部分事件不改變狀態，要按很多次才看得到變化；保留為 Shift + 方向鍵 |
| 方向鍵一步＝固定時間（例如 1 秒） | 會跳過同一秒內的多個變化，或在閒置時段空轉 |
| 播放時不略過閒置時段 | 長時間沒有變化的段落要空等 |
| 每個面板各自有時間 | 面板之間容易不同步，造成誤判 |
| 版面依案件保存 | 每個案件都要重新調整 |
| 原始 LOG 依排序後的順序顯示 | 看不到時間倒退的行原本的位置 |
| 沒有 LOG 的時段以設備（站點、搬送機）為單位（2026-10-21 #84） | 設備常常閒置，誤報太多 |
| 依各模組平常的間隔自動推算門檻（2026-10-21 #84） | 有事情才寫 LOG 的模組間隔變化很大，推算的門檻會產生大量誤報 |
| 依檔名或輪替順序偵測缺少的檔案（2026-10-21 #84） | 檔名規則待確認；檔案內部的缺漏偵測不到 |
| 沒有 LOG 的時段存進案件資料庫（2026-10-21 #84） | 要改資料表結構；開啟案件時計算已足夠快 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 事件很多時，每次移動都要重算世界狀態 | 操作卡頓 | 定期保存狀態快照（列入「儲存與索引候選方案比較」）；技術驗證時測試 |
| 異常熱區只以警報呈現，沒有警報的異常看不出來 | 可能漏看問題點 | 異常熱區判定仍列在 Not yet specified |
| 「狀態變化」的判定依賴廠別設定的解析規則 | 規則漏掉時，→ 會跳過實際的變化 | Shift + → 可以逐筆檢查；規則可依廠別調整 |
| 原型的資料量小，無法反映真實的捲動效能 | 實作後才發現效能問題 | ADR-0007 的技術驗證（10 萬筆事件） |
| 預設 5 分鐘對有事情才寫 LOG 的模組可能誤報（2026-10-21 #84；真實樣本推算一個模組 10 段） | 工程師誤以為有缺漏 | 說明寫「可能是閒置或缺漏」；可以依模組調整門檻或設 0 |

## 後續驗證方式

- 以樣本 LOG 實作後，確認 → 的每一步都對應到一個狀態變化，Shift + → 逐筆不漏。
- 確認事件清單、時間軸、Layout、原始 LOG 在任一處操作後都同步。
- 確認時間倒退、時間無效等旗標與 `docs/log-format-notes.md` 的統計一致。
- 確認 Docking 版面關閉程式後重新開啟仍然保留，「還原預設」可以恢復。
- 沒有 LOG 的時段（2026-10-21 #84，AC-011）：以刻意刪除一段 LOG 的虛構樣本，確認時間軸標出該時段、回放與詳細資訊顯示提示；自動化測試涵蓋門檻、0、案件開頭與結尾、模組自訂門檻；本機以真實案件驗證，只回報各模組的段數。

## 影響範圍

- **搜尋模式與比對規則**：搜尋結果放進事件清單（沿用排序規則與旗標），並與「目前時刻」連動；可以使用「搜尋」預設版面。
- **儲存與索引候選方案比較**：需要能快速取得某一時刻的世界狀態（例如狀態快照），以及依元素、命令編號篩選事件。
