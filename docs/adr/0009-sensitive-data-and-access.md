# ADR-0009：敏感資訊處理與存取權限

- 日期：2026-10-16
- 狀態：已接受
- 確認者：repo owner（daniel579-source）
- 對應 ticket：Wayfinder「敏感資訊處理與存取權限」
- 相關決策：ADR-0001（單機桌面程式）、ADR-0002（案件含原始 LOG 複本）、ADR-0003（偏移量的修改紀錄）、ADR-0006（廠別設定與 Layout 分享）、ADR-0007（用戶端技術）

## 背景

- LOG 含內網 IP、客戶名稱、物料、單號，以及簡訊通知內容中的**電話號碼**（個人資料）（`docs/log-format-notes.md` O-015）。
- 系統是單機桌面程式，資料在本機，由使用者自己的作業系統帳號使用（ADR-0001）。
- 案件資料夾內含真實 LOG 的完整複本（ADR-0002）；廠別設定（含 Layout）會以檔案分享（ADR-0006）。
- 「證據打包匯出」已列為第一階段範圍外。
- 使用者確認的事實：
  - 工程師的電腦有**全碟加密**。
  - 公司**允許**把現場 LOG 放在個人電腦上。
  - **沒有**保存期限的規定。
- 在先前的 LOG 分析中，AI 協作工具（Claude Code，屬於外部 AI 服務）曾在本機讀取真實 LOG；大部分輸出有遮罩，但仍有少量未遮罩的字串傳到該服務。這與 `CLAUDE.md` 第 13 條原本的文字衝突，需要明確規範。

## 決策

### 1. 系統內的顯示

- 只遮罩**個人資料**（電話號碼）：預設以 `09xx-xxx-xxx` 的形式顯示，點一下才顯示完整號碼。
- 內網 IP、客戶、物料、單號照常顯示。
- 遮罩規則放在**廠別設定**中。
- 遮罩只影響顯示；原始 LOG 與索引內容不變。
- 實作方式（2026-10-16 #20 補充）：
  - 遮罩規則是廠別設定的 `maskPatterns`（正規表示式），預設為台灣手機號碼。
  - 遮罩方式：保留前兩個數字，其餘數字顯示為 x，長度不變（醒目標示的位置仍正確）。
  - 遮罩範圍包括事件清單、詳細資訊、原始 LOG。
  - 「顯示完整電話號碼」只對選取的事件有效，換一筆事件就恢復遮罩。

### 2. 存取控制

- 程式**不另外設登入或帳號**，依賴作業系統帳號。
- 案件資料預設存放在**使用者個人的資料夾**，同一台電腦的其他帳號預設看不到；實際位置由「儲存與索引候選方案比較」決定。
- **不依廠別或設備分權**：拿到哪個案件，就能看哪個案件。

### 3. 加密

程式**不自行加密**案件資料，依賴作業系統的全碟加密。

### 4. 分享

- 第一階段不提供分享或匯出案件的功能。
- 案件資料夾內放一個說明檔，提醒「本資料夾含真實 LOG，請勿外流」。
- 廠別設定（含 Layout）只存放結構資訊（元素、別名、規則）；程式**不會自動把 LOG 內容寫入**。自訂屬性由使用者填寫，內容由使用者自行注意。
- 不限制截圖或複製文字。

### 5. 稽核紀錄

- **記錄**：匯入、重複匯入時的選擇、偏移量設定（ADR-0003）、套用新版 Layout。內容為操作人（作業系統帳號）、時間與操作內容，存放在案件中。
- 2026-10-16 #27 補充：「套用新版 Layout」的稽核紀錄記為「套用新版廠別設定」，內容包括舊修訂號、新修訂號，以及重建後的事件數。
- 2026-10-16 #18 補充：稽核範圍加上「**建立案件**」與「**刪除案件**」。刪除案件後案件資料庫就不存在，所以建立與刪除另外記在**案件存放位置**下的 `audit-log.jsonl`。
- **不記錄**：查詢與瀏覽。

### 6. 保存與備份

- 程式**不自動刪除**任何案件。
- 程式**不提供備份功能**；案件資料夾內容完整，複製整個資料夾即為備份，由使用者或公司既有的備份機制負責。
- 提供「**刪除案件**」，刪除前要確認；刪除的是案件中的複本，倉儲電腦上的原始 LOG 不受影響。

### 7. 開發與測試資料

- 真實 LOG 只放在開發者的**本機**（例如已排除於版本控制的 `log/` 資料夾），**永遠不 commit 到 GitHub**（包括 private repo），由開發者自行管理。
- 暫時不做去識別化工具。
- repo、issue、留言與文件中只能使用虛構或去識別化的資料。

### 8. AI 協作工具

- 經 repo owner 核准，AI 協作工具（例如 Claude Code）可以在本機讀取真實 LOG 進行分析。
- **不得**把真實 LOG 的內容寫入 repo、issue、留言或其他文件。
- AI 協作工具的輸出盡量遮罩。
- `CLAUDE.md` 第 13 條同步修改。

## 理由

- 除錯幾乎用不到電話號碼，但 IP、客戶、物料、單號常是線索；只遮罩個資兼顧保護與可用性。
- 單機程式中的帳號機制很容易被繞過（直接開啟檔案就能讀取），反而造成虛假的安全感；作業系統帳號與個人資料夾已經提供基本隔離。
- 全碟加密已經涵蓋電腦遺失的風險；程式自行加密要管理金鑰，忘記密碼就無法開啟案件。
- 截圖與複製在技術上擋不住，限制只會降低可用性。
- 稽核記錄「資料怎麼來的、被改過什麼」，足以解釋過去的分析結果；單機程式記錄查詢沒有實質意義。
- 沒有保存期限規定；案件資料夾內容完整，複製即可備份，不需要另外設計備份機制。
- GitHub 即使是 private repo 也屬於外部服務，上傳後會留在 git 歷史中，很難徹底刪除。
- 規則與實際做法一致，之後的協作者才不會被誤導。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 完全不遮罩 | 電話號碼屬於個人資料，除錯又用不到 |
| 全部預設遮罩 | 除錯需要的線索被遮住，每次都要切換 |
| 程式內設登入與帳號、依廠別分權 | 單機程式容易繞過；增加管理負擔 |
| 程式自行加密案件資料 | 已有全碟加密；金鑰管理與遺失風險 |
| 提供案件分享或匯出功能 | 證據打包匯出不在第一階段範圍 |
| 記錄查詢與瀏覽 | 單機程式沒有實質意義，徒增資料量 |
| 程式內建備份功能 | 複製資料夾即可備份；公司已有備份機制 |
| 測試用真實 LOG 放進 private repo | 屬於外部服務，且難以從 git 歷史中刪除 |
| 先做去識別化工具再開始開發 | 使用者決定由開發者在本機自行管理真實 LOG |
| 禁止 AI 協作工具讀取真實 LOG | 使用者決定維持現狀；格式分析需要真實樣本 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 使用者把案件資料夾交給不該拿到的人 | 真實 LOG 外流 | 案件資料夾內的說明檔提醒；依公司資安規範 |
| 電話號碼以外的個人資料（例如人員姓名、帳號）出現在其他廠別的 LOG | 未被遮罩 | 遮罩規則放在廠別設定，可以擴充 |
| 使用者在 Layout 的自訂屬性填入敏感資訊後分享 | 敏感資訊外流 | 說明文件提醒；屬性只能由人工填寫 |
| AI 協作工具的輸出含未遮罩內容 | 少量內容傳到外部服務 | 已經 repo owner 核准；輸出盡量遮罩；不寫入任何文件 |
| 開發者本機的真實 LOG 管理不一 | 外流風險 | 由開發者自主管理；`.gitignore` 排除 `log/` |
| 日後公司訂出保存期限或備份規範 | 需要新增刪除或備份功能 | 屆時以新的 ADR 處理 |

## 後續驗證方式

- 以樣本確認電話號碼都被遮罩，點擊後顯示完整號碼；原始 LOG 不變。
- 以另一個作業系統帳號登入同一台電腦，確認預設看不到案件資料。
- 確認稽核紀錄涵蓋匯入、重複匯入的選擇、偏移量、套用新版 Layout。
- 確認刪除案件前有確認，且只刪除案件資料夾。
- 定期檢查 repo 與 issue 中沒有真實 LOG 內容。

## 影響範圍

- **儲存與索引候選方案比較**：案件放在使用者個人的資料夾；程式不加密；要能刪除案件；稽核紀錄存放在案件中。
- **搜尋模式與比對規則**：搜尋對象是原始內容，但結果中的電話號碼仍遮罩顯示；需要決定是否允許以電話號碼搜尋。
- **CLAUDE.md**：第 13 條加上 AI 協作工具的規定。
