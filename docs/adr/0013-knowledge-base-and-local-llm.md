# ADR-0013：知識庫與本機離線 LLM

- 日期：2026-10-19
- 狀態：**部分接受**：第 2 點「知識庫第一版」已接受（2026-10-21）；第 3～8 點（向量搜尋、LLM、候選技術）仍為提議中（技術全部為**候選方案**；取得現場硬體後才改為已接受）
- 確認者：repo owner（第 2 點，2026-10-21）；其餘待確認
- 對應 ticket：#55、#80（知識庫第一版）
- 相關 ADR：ADR-0014（第一線問答助理）、ADR-0015（知識檢索）、ADR-0016（異常紀錄與經驗累積）、ADR-0022（向量搜尋的模型、執行環境與儲存）

## 背景

ADR-0001 把離線 LLM 與向量資料庫排除在第一階段之外。系統規格書 v2（`docs/system_spec_v2_0_0.md`）原本提議的 AI 功能有：以向量資料庫作為知識庫（機台手冊、SOP 等）、錯誤碼的語意化說明、報告自動總結與翻譯、自然語言查詢。

現場可能使用有 NPU 的 AI 筆電（**待確認**），在本機執行小型 LLM 變得可行。

限制條件：

- ADR-0001：免安裝、完全離線、不另外架設伺服器；工程師電腦不能自行安裝軟體、連不到外網。
- ADR-0009：真實 LOG 不得提交到外部 AI 服務。

## 決策（提議）

1. **定位**：AI 功能是第一階段之後的**可選功能**，不影響現有功能，也不影響第一階段驗收。
2. **知識庫先做，不依賴 LLM**：知識庫收錄手冊、SOP、錯誤碼表。第一版以查表與關鍵字搜尋，從事件的解析欄位（例如警報代碼）直接查到說明，並附出處。知識庫屬於廠別，存放在本機，與廠別設定一樣不進 repo。
   - 2026-10-21 #80 補充（已接受）：知識庫第一版的做法如下。
     1. **檔案**：每個廠別一個 CSV 檔，放在廠別設定旁邊，檔名為廠別設定檔名加 `.kb.csv`（例如 `D:\LogTrace\Plants\<廠別>.kb.csv`）。屬於廠別的本機資料，不進 repo（ADR-0009）；repo 只放虛構的範例與測試資料。
     2. **欄位**：第一列為標題 `代碼,說明,處置,出處`。「代碼」「說明」必填，「處置」「出處」可以空白。出處寫文件名稱與頁碼或章節；第一版只顯示文字，不開啟文件。
     3. **編碼**：UTF-8（有沒有 BOM 都可以）；不是有效的 UTF-8 時改用 Big5 讀取（正體中文 Windows 的 Excel 另存「CSV」預設為 Big5）。
     4. **同一代碼可以有多列**，全部顯示，依檔案順序（例如同一代碼在不同設備有不同意義）。
     5. **比對**：事件的解析欄位「警報代碼」與知識庫的「代碼」完全比對，不分大小寫、全形與半形相同（與 ADR-0010 的正規化相同）。找不到時顯示「知識庫中沒有這個代碼」，不推測。
     6. **入口**：事件詳細資訊中，事件有警報代碼時顯示對應的說明、處置與出處；另有「知識庫」面板，以關鍵字搜尋四個欄位（不分大小寫、全半形相同、部分比對，與 ADR-0010 相同）。
     7. **讀取時機**：開啟案件時依案件的廠別名稱讀取 `Plants\` 下的知識庫檔；面板提供「重新載入」。知識庫**不存入案件快照**（它是參考資料，不是推導事件的規則）。檔案不存在時面板顯示「這個廠別沒有知識庫」，其他功能照常；格式有誤的列不使用，並在面板列出行號與原因。
     8. **不記入稽核**：只讀取，不改變案件。
   - 2026-11-18 補充（使用者確認，見 ADR-0022 待確認 6）：知識庫增加選填欄位「別名或俗稱」：多個以頓號「、」分隔；只用於知識庫面板的關鍵字搜尋與向量搜尋（加入條目文字，改過的條目重算向量），事件詳細資訊與面板的結果清單都不顯示；依標題名稱讀取，舊檔沒有這一欄照常讀取。已實作（2026-11-19，#190）。
   - 2026-10-21 補充（提議中，見 ADR-0014）：知識庫增加「執行者」欄（「現場可執行」或「限工程師」，沒有填的視為「限工程師」），供第一線問答助理判斷能否直接回覆第一線。第一版程式尚未讀取這一欄。
   - 2026-11-13 補充（提議中，見 ADR-0016）：知識庫分成兩類內容：「參考資料」（警報代碼表、手冊、SOP，第一版即本點的 CSV）與「異常紀錄」（處理完的異常，由 AI 產生草稿、工程師審核後列入，每個廠別一個 `<廠別>.incidents\` 資料夾）。手冊與 SOP 原文如何收錄，待取得文件樣本後決定。
3. **向量搜尋是下一步**：候選方案為 sqlite-vec 加上小型 embedding 模型，維持 ADR-0011「案件是一個資料夾」的做法。
   - 2026-11-04 補充：檢索方式改為規則關聯圖加向量搜尋，見 ADR-0015（提議中）。
   - 2026-11-17 補充（提議中，見 ADR-0022）：embedding 模型以 multilingual-e5-small 與 bge-m3 比較，以 Ollama 執行；向量儲存改為不加套件、逐條比對，不使用 sqlite-vec。
4. **LLM 只在本機離線執行**：不使用外部 API（ADR-0009），不另外架設伺服器（ADR-0001）。
5. **LLM 只做「轉換」與「摘要」，事實由引擎決定**：
   - 自然語言查詢：LLM 只把句子轉成搜尋條件；條件顯示在畫面上，工程師可以修改後再搜尋。
   - 摘要與錯誤碼說明：每一句都附事件序號或知識庫出處，點選可以跳到原始事件或文件（CLAUDE.md 3.4 節的可追溯性）。
   - 送給 LLM 的只有已經用搜尋或命令串接篩選出的事件，不送整份 LOG。
   - 2026-10-21 補充：最終目標是回覆第一線人員並給出處置；AI 回覆第一線時的範圍、轉交工程師的條件與安全規則依 ADR-0014（提議中）。
   - 2026-11-13 補充（提議中，見 ADR-0016）：放寬給工程師的範圍：LLM 可以根據事件、規則關聯圖展開結果與相似的異常紀錄，推論可能的原因與處置，一律標示「AI 推測」並附出處，只給工程師看；給第一線的內容不變。以對話操作 Windows 或其他程式暫緩，不在本 ADR 範圍。
6. **可以降級**：偵測不到模型或硬體不足時，隱藏 AI 面板，其他功能照常使用（規格書 v2 的 Graceful Degradation）。
7. **交付方式**：模型檔有數 GB，與程式分開存放，從內部共用資料夾複製，不需安裝。IT 是否允許把模型檔放在工程師電腦，**待確認**。
   - 2026-11-17 補充（提議中，見 ADR-0022）：向量搜尋的 embedding 使用 Ollama，**需要安裝**，本點「不需安裝」不適用於 Ollama；安裝要經 IT 同意（待確認）。LLM 仍依第 8 點，不使用 Ollama。
   - 2026-11-17 補充（使用者轉述 IT）：IT **同意**在工程師電腦安裝 Ollama 與放置模型檔（待確認 3 已確認；ADR-0022 待確認 1 已確認）。
   - 2026-11-27 補充：廠區離線，檔案要經客戶以郵件轉寄（ADR-0030 背景），附件上限每廠不一定；數 GB 的模型檔與 Ollama 可能無法以本點「從內部共用資料夾複製」的方式送進廠區。ADR-0030 的升級機制只涵蓋 LogTrace 程式與 WebView2 Runtime，LLM 相關元件的交付與更新方式**待確認**（#47 E）。
8. **候選技術**（實測後再定案）：
   - 模型：3～8B、INT4 量化。候選例如 Qwen 系列（中文較強）、Phi-4-mini（較小，中文較弱）。
   - 2026-11-17 補充（授權條款查核，以 Hugging Face 官方模型頁與 GitHub 授權檔為準）：Phi-4-mini-instruct（含 Microsoft 官方 ONNX 版）為 MIT；Qwen3-4B、Qwen3-8B、Qwen2.5-7B-Instruct 為 Apache-2.0，都可以商用。**Qwen2.5-3B-Instruct 為 Qwen Research License（只限研究或評估，不能商用），排除在正式產品之外**；3～4B 的 Qwen 改測 Qwen3-4B。執行環境 ONNX Runtime、ONNX Runtime GenAI、llama.cpp 都是 MIT。發佈時保留各自的授權檔；第三方轉檔版本的授權沿用原模型，但來源與品質另外確認。以上為條款整理，不是法律意見。
   - 執行環境：ONNX Runtime GenAI（可使用各廠牌 NPU，與 .NET 整合容易）為主，llama.cpp（模型最多，主要用 CPU／GPU）為備案。
   - 硬體：AI 筆電，建議 32 GB 記憶體（7～8B 量化模型約 4～6 GB，加上 LogTrace 與索引）。
   - 2026-11-17 補充（使用者提供規格）：執行 LogTrace 的現場筆電為 **MSI Prestige 16 AI Evo B1MG**：Intel Core Ultra 7 165H（Meteor Lake，16 核心 22 執行緒，x64）、**32 GB LPDDR5-6400**（板載、不能升級）、Intel Arc 內顯（沒有獨立 GPU；Windows 顯示的 128 MB 是專用顯示記憶體，跑模型時與系統共用 32 GB 記憶體，可用量待實機確認）、Intel AI Boost NPU（算力約 11 TOPS，**待確認**）、1 TB NVMe PCIe 4.0、Windows 11 Pro 25H2、電池 99.9 Wh。符合本點「建議 32 GB」。依公開資料（待實機確認）：不是 Copilot+ PC（NPU 未達 40 TOPS），替代方案中的 Phi Silica 不能使用；Ollama 官方只能用內顯（Vulkan）或 CPU，不能用 NPU（ADR-0022 的 embedding 不受影響）。
   - 2026-11-17 補充（實測順序，候選）：LLM 先實測 3～4B 的模型（例如 Phi-4-mini、Qwen 3B／4B；Jev 判斷，信心度 0.80），量測完再試 7～8B。執行裝置在內顯、CPU、NPU 三者都量測後再決定（使用者決定；Jev 偏向內顯但信心度只有 0.35）。

## 理由

- 知識庫查表不需要 LLM 就有用，結果可以驗證，風險最低。
- 2026-10-21 #80 補充：CSV 可以直接從 Excel 整理；知識庫不放進案件快照，修改說明不必重建案件。
- 本機、離線、可選的做法，同時符合 ADR-0001 與 ADR-0009。
- LLM 只做轉換與摘要、事實由引擎決定並附出處，可以守住可追溯性，降低 LLM 產生錯誤內容的影響。
- 筆電上能一次處理的內容有限，先用既有的搜尋與命令串接篩選，才符合實際能力。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 外部 LLM API | ADR-0009 禁止把真實 LOG 提交到外部 AI 服務 |
| Edge Server 集中運算（規格書 v2 提議） | ADR-0001 已排除；現場或出差時不一定連得到伺服器 |
| Windows 內建模型（Phi Silica） | 只限 Copilot+ PC；中文能力與可做的事有限 |
| 不做 AI 功能 | 失去錯誤碼說明、摘要等可能的效益；保留為「降級」時的狀態 |
| 知識庫用 JSON（2026-10-21 #80） | 與廠別設定一致，但不便從 Excel 整理 |
| 知識庫寫進廠別設定檔（2026-10-21 #80） | 每次修改說明都產生新修訂、提示套用新版，代價太高 |
| 知識庫存入案件快照（2026-10-21 #80） | 同一份說明在每個案件各複製一份；修正後舊案件看不到 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 現場硬體不足 | 太慢或記憶體不夠 | 實機量測後才接受本 ADR；可以降級 |
| LLM 產生錯誤內容 | 誤導排查方向 | 只做轉換與摘要；附出處；搜尋條件可以修改 |
| 中文品質不足 | 說明不準確 | 以虛構資料評估候選模型 |
| ~~現場筆電為 ARM64（Snapdragon）~~ | 要另外發佈 ARM64 版並重新驗證（ADR-0007） | **已解除**（2026-11-17）：現場筆電為 Intel x64（第 8 點補充） |
| 模型授權 | 不能在公司內部使用 | 選型時確認授權條款；2026-11-17 已查核（第 8 點補充），Qwen2.5-3B 為研究授權、排除 |
| NPU 驅動差異、一次可處理的內容長度有限 | 可處理的事件數受限 | 先以引擎篩選，再交給 LLM |
| 現場筆電的 NPU 算力不高（Meteor Lake 世代，約 11 TOPS，待確認）、沒有獨立 GPU（2026-11-17） | LLM 可能太慢 | 內顯、CPU、NPU 都量測；先用 3～4B 模型 |
| 知識庫文件屬於公司機密 | 外流風險 | 存放在本機，不進 repo；依 ADR-0009 處理 |
| 真實知識庫文件的格式未知（2026-10-21 #80） | 可能要另外做匯入工具 | 取得去識別化樣本後確認 |
| 警報代碼要由廠別設定的解析規則抽出（2026-10-21 #80） | 沒有抽出這個欄位的廠別無法自動查表 | 可以用知識庫面板的關鍵字搜尋 |
| 知識庫不放進快照（2026-10-21 #80） | 日後重看舊案件時，看到的是目前最新的說明，不是案件當時的版本 | 出處欄註明文件版本 |

## 後續驗證方式

- 以現場 AI 筆電與虛構資料量測：第一個字出來的時間、每秒產生的字數、與 LogTrace 同時執行時的記憶體用量、接電與用電池的差別（可以與 #47 A 類一起進行）。
  - 2026-11-17 補充：機型為 MSI Prestige 16 AI Evo B1MG（32 GB）。先量測 3～4B 模型在內顯、CPU、NPU 上的表現，再試 7～8B；同時量測 ADR-0022 的 embedding 與 Ollama 一起執行時的記憶體。
- 取得知識庫文件的去識別化樣本後，確認格式與查表方式。
- 以虛構資料評估「自然語言轉搜尋條件」的正確率。
- 知識庫第一版（2026-10-21 #80）：以虛構的知識庫與 LOG 測試比對規則（大小寫、全半形）、多列、UTF-8 與 Big5、格式錯誤列、檔案不存在；取得去識別化樣本後，確認欄位是否足夠。
