# ADR-0013：知識庫與本機離線 LLM

- 日期：2026-10-19
- 狀態：提議中（技術全部為**候選方案**；取得現場硬體與知識庫文件樣本後，才改為已接受）
- 確認者：待確認
- 對應 ticket：#55

## 背景

ADR-0001 把離線 LLM 與向量資料庫排除在第一階段之外。系統規格書 v2（`docs/system_spec_v2_0_0.md`）原本提議的 AI 功能有：以向量資料庫作為知識庫（機台手冊、SOP 等）、錯誤碼的語意化說明、報告自動總結與翻譯、自然語言查詢。

現場可能使用有 NPU 的 AI 筆電（**待確認**），在本機執行小型 LLM 變得可行。

限制條件：

- ADR-0001：免安裝、完全離線、不另外架設伺服器；工程師電腦不能自行安裝軟體、連不到外網。
- ADR-0009：真實 LOG 不得提交到外部 AI 服務。

## 決策（提議）

1. **定位**：AI 功能是第一階段之後的**可選功能**，不影響現有功能，也不影響第一階段驗收。
2. **知識庫先做，不依賴 LLM**：知識庫收錄手冊、SOP、錯誤碼表。第一版以查表與關鍵字搜尋，從事件的解析欄位（例如警報代碼）直接查到說明，並附出處。知識庫屬於廠別，存放在本機，與廠別設定一樣不進 repo。
3. **向量搜尋是下一步**：候選方案為 sqlite-vec 加上小型 embedding 模型，維持 ADR-0011「案件是一個資料夾」的做法。
4. **LLM 只在本機離線執行**：不使用外部 API（ADR-0009），不另外架設伺服器（ADR-0001）。
5. **LLM 只做「轉換」與「摘要」，事實由引擎決定**：
   - 自然語言查詢：LLM 只把句子轉成搜尋條件；條件顯示在畫面上，工程師可以修改後再搜尋。
   - 摘要與錯誤碼說明：每一句都附事件序號或知識庫出處，點選可以跳到原始事件或文件（CLAUDE.md 3.4 節的可追溯性）。
   - 送給 LLM 的只有已經用搜尋或命令串接篩選出的事件，不送整份 LOG。
6. **可以降級**：偵測不到模型或硬體不足時，隱藏 AI 面板，其他功能照常使用（規格書 v2 的 Graceful Degradation）。
7. **交付方式**：模型檔有數 GB，與程式分開存放，從內部共用資料夾複製，不需安裝。IT 是否允許把模型檔放在工程師電腦，**待確認**。
8. **候選技術**（實測後再定案）：
   - 模型：3～8B、INT4 量化。候選例如 Qwen 系列（中文較強）、Phi-4-mini（較小，中文較弱）。
   - 執行環境：ONNX Runtime GenAI（可使用各廠牌 NPU，與 .NET 整合容易）為主，llama.cpp（模型最多，主要用 CPU／GPU）為備案。
   - 硬體：AI 筆電，建議 32 GB 記憶體（7～8B 量化模型約 4～6 GB，加上 LogTrace 與索引）。

## 理由

- 知識庫查表不需要 LLM 就有用，結果可以驗證，風險最低。
- 本機、離線、可選的做法，同時符合 ADR-0001 與 ADR-0009。
- LLM 只做轉換與摘要、事實由引擎決定並附出處，可以守住可追溯性，降低 LLM 產生錯誤內容的影響。
- 筆電上能一次處理的內容有限，先用既有的搜尋與命令串接篩選，才符合實際能力。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 外部 LLM API | ADR-0009 禁止把真實 LOG 提交到外部 AI 服務 |
| Edge Server 集中運算（規格書 v2 提議） | ADR-0001 已排除；現場或出差時不一定連得到伺服器 |
| Windows 內建模型（Phi Silica） | 只限 Copilot+ PC；中文能力與可做的事有限 |
| 不做 AI 功能 | 失去錯誤碼說明、摘要等可能的效益；保留為「降級」時的狀態 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 現場硬體不足 | 太慢或記憶體不夠 | 實機量測後才接受本 ADR；可以降級 |
| LLM 產生錯誤內容 | 誤導排查方向 | 只做轉換與摘要；附出處；搜尋條件可以修改 |
| 中文品質不足 | 說明不準確 | 以虛構資料評估候選模型 |
| 現場筆電為 ARM64（Snapdragon） | 要另外發佈 ARM64 版並重新驗證（ADR-0007） | 確認型號後再決定 |
| 模型授權 | 不能在公司內部使用 | 選型時確認授權條款 |
| NPU 驅動差異、一次可處理的內容長度有限 | 可處理的事件數受限 | 先以引擎篩選，再交給 LLM |
| 知識庫文件屬於公司機密 | 外流風險 | 存放在本機，不進 repo；依 ADR-0009 處理 |

## 後續驗證方式

- 以現場 AI 筆電與虛構資料量測：第一個字出來的時間、每秒產生的字數、與 LogTrace 同時執行時的記憶體用量、接電與用電池的差別（可以與 #47 A 類一起進行）。
- 取得知識庫文件的去識別化樣本後，確認格式與查表方式。
- 以虛構資料評估「自然語言轉搜尋條件」的正確率。

## 待確認

1. 現場筆電的型號與規格（處理器廠牌、NPU、記憶體）。
2. 知識庫文件的格式、機密等級與去識別化樣本。
3. IT 是否允許把模型檔放在工程師電腦。
4. 候選模型的授權條款。
