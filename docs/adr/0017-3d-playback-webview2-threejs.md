# ADR-0017：Layout 回放改用 3D（WebView2 + three.js）

- 日期：2026-11-14
- 狀態：**已接受（待實機驗證）**：在乾淨、離線的 Windows 10 實機確認可以執行，並量測 zip 大小與記憶體後，改為已接受
- 確認者：repo owner（決策內容，2026-11-14）
- 相關 ADR：ADR-0001（單機、離線）、ADR-0005（回放的世界模型）、ADR-0006（Layout 模型與設定檔）、ADR-0007（用戶端技術選型）、ADR-0008（回放畫面與操作）
- 對應 ticket：#112（決策）、#113（實作）

## 背景

- 使用者要求以 three.js 把 Layout 的內容呈現成 3D，**正式整合**進 LogTrace，範圍為靜態 Layout 加上回放狀態（2026-11-14）。
- ADR-0007 決定 C# + .NET 10 + WPF、self-contained 單一資料夾發佈，**不依賴 WebView2**（目標電腦是否有 WebView2 Runtime 不確定），日後的 3D 候選為 HelixToolkit。
- three.js 是網頁技術，要在 WPF 中使用必須內嵌瀏覽器元件（WebView2）。
- Layout 以公尺為單位，元素已有高度，料架有層數與每層高度（ADR-0006 第 5 點）；樓層只記錄名稱與順序，當初決定「需要 3D 時再加」樓板高度（ADR-0006 第 13 點）。
- 現有的 2D 回放（WPF 自行繪製）與世界模型（ADR-0005）已完成並有測試。

## 決策

1. **技術**：在 WPF 中以 **WebView2** 內嵌 **three.js** 繪製 Layout 回放。取代 ADR-0007 第 1 點的「不依賴 WebView2」與第 3 點元件表的「日後的 3D：HelixToolkit」。C#、.NET 10、WPF、AvalonDock 等其他選擇不變。
2. **WebView2 Runtime**：以**固定版本（Fixed Version）隨程式資料夾打包**，不依賴電腦上是否安裝 Runtime。zip 與資料夾大小**待實測**；Runtime 的安全性修正要靠重新發佈程式。程式指定使用程式資料夾內的 Runtime，不改用電腦上的版本。
3. **離線**：three.js 以固定版本放在程式資料夾內（不使用 CDN）。WebView2 只載入程式資料夾內的檔案，**封鎖所有網路請求**與外部導覽；不使用瀏覽器的帳號、同步等功能。three.js 為 MIT 授權，WebView2 Runtime 依其散布條款，兩者加入 `THIRD-PARTY-NOTICES.md` 與 `licenses\`（散布條款待確認）。
4. **取代 2D**：「Layout 回放」面板改為 3D，移除 2D 回放的繪製。
   - 世界模型（ADR-0005）與回放狀態的推導**不變**，仍在 C# 引擎中。
   - C# 把**場景資料**（Layout 元素與目前時刻的狀態）以 JSON 傳給網頁；three.js 只負責畫出來與回報操作（點選、載入完成、錯誤），不推導狀態。
   - Layout 編輯器維持 2D（第 8 點；2026-11-14 由 ADR-0018 取代，編輯器也改為 3D）。
5. **呈現內容**：
   - 靜態：站點、輸送線、料架（依層數 × 每層高度）、搬送機、對接設備、導軌、電梯、防火門、區域與標籤；顏色與圖例沿用 ADR-0005、ADR-0008。
   - 回放狀態：搬送機沿導軌移動（沿用現有的內插，屬於**推估**，照舊標示）、貨物、在席指示燈、警報與不一致的顏色、執行中／閒置，跟隨事件清單的目前時刻。
   - 操作：旋轉、平移、縮放；可以回到預設視角。
   - **外觀參考**（使用者，2026-11-14）：物件外觀參考自動倉儲設備廠商的公開網站（https://www.daifuku.com/tw/）上常見設備的一般樣式，以簡化的幾何形狀表現，例如堆高起重機（立柱與上下移動的載貨台）、由直立框架與橫樑組成的格狀料架、貼近軌道的低矮軌道車（上方為輸送面）、輸送線。**只參考一般外觀**：不使用該網站的圖片、3D 模型、標誌或產品名稱，元素一律用通用名稱（ADR-0006 的元素種類）。網站文字沒有外觀的細節，實際形狀、顏色與比例在 #113 實作前與使用者確認（**待確認**）。
6. **樓層一律上下堆疊**：
   - ADR-0006 的樓層新增**樓板高度**（公尺）；舊設定檔沒有時預設 **5 公尺**（使用者決定）。欄位名稱與格式版本依 ADR-0006「用到新功能才升版」的原則，在實作時確認。
   - 電梯畫成跨越它服務的樓層。
   - 原本的單層／並排、橫向／垂直、「跟隨切換樓層」是 2D 的檢視設定；改為 3D 後如何處理，在實作 ticket 中確認。
7. **點選連動**：在 3D 中點選元素，與現在的 2D 相同，顯示元素狀態，並可跳到造成狀態的事件；從設備狀態表、命令、事件選取元素時，3D 中也標出該元素。
8. ~~**Layout 編輯器維持 2D**。~~ **已由 ADR-0018 取代**（2026-11-14，#116）：編輯器也改為 3D，完全取代 2D 編輯畫布。
9. **WebGL 或 WebView2 不能使用時**（例如顯示卡驅動程式問題）：面板顯示原因，其他功能（事件清單、詳細資訊、設備狀態表等）照常使用。2D 已移除，這時沒有 Layout 回放畫面。
10. **後續**：決策記錄在 #112；實作為 #113，經使用者指示後才進行。

## 理由

- 使用者選擇 three.js；三維呈現能看到料架層數、樓層之間的電梯與搬送，2D 俯視看不到。
- 固定版本隨程式打包，離線的 Windows 10 也一定能執行，沿用 ADR-0001「免安裝、完全離線」的要求。
- 狀態推導留在 C#，回放邏輯與既有測試不受影響；網頁端只負責繪製，換畫法不必改引擎。
- 只維護一套回放畫面（使用者選擇取代 2D）。
- 一律堆疊能同時看到所有樓層之間的關係（使用者選擇）。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| HelixToolkit（WPF 原生 3D，ADR-0007 的候選） | 不需要 WebView2，但使用者選擇 three.js |
| 只用電腦上已安裝的 Evergreen Runtime | 離線的 Windows 10 不一定有，沒有時 3D 不能用 |
| 先用已安裝的 Runtime，沒有時改用打包的固定版本 | 兩種情況都要測試；既然一定要打包，直接固定使用打包的版本較單純 |
| 保留 2D，與 3D 並存（Jev 建議） | 使用者選擇只維護一套 |
| 新增獨立的「3D 回放」面板 | 3D 取代 2D，直接沿用「Layout 回放」面板 |
| 預設一次一層，可切換堆疊（Jev 建議） | 使用者選擇一律堆疊 |
| 以 CDN 載入 three.js | 違反完全離線（ADR-0001） |
| 網頁端自己解析 LOG 或推導狀態 | 世界模型會有兩份；改由 C# 傳場景資料 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 固定版本 Runtime 讓 zip 變大很多 | 發佈與複製較慢 | 實測大小後記錄；仍為單一資料夾 |
| Runtime 的安全性修正要重新發佈 | 舊版 Runtime 有已知漏洞 | 只載入本機檔案、封鎖網路與外部導覽，降低暴露；發佈新版時更新 Runtime |
| WebGL 與顯示卡驅動程式有關 | 某些電腦沒有 Layout 回放 | 面板顯示原因，其他功能照常；實機驗證 |
| 2D 已移除，沒有退路 | WebView2 或 WebGL 出問題時看不到 Layout | 第 9 點；必要時以新的 ADR 恢復 2D |
| UI 自動化看不到 WebGL 畫面內容 | 冒煙測試無法檢查畫出來的東西 | 測場景資料的產生；網頁回報載入完成、元素數量與點選結果 |
| 大型 Layout 或大量儲位的繪製效能 | 操作不順 | 以虛構的大型 Layout 量測；必要時合併幾何或簡化料架 |
| 記憶體用量增加（瀏覽器程序） | 低規格筆電較吃力 | 實機量測 |
| 一律堆疊時樓層多、互相遮擋 | 看不清下層 | 可以旋轉、縮放；必要時另外決定是否加入隱藏樓層 |
