# ADR-0018：Layout 編輯器改用 3D

- 日期：2026-11-14
- 狀態：**已接受（待實機驗證）**：實作（#117）完成，並在乾淨、離線的 Windows 10 實機確認可以編輯後，改為已接受
- 確認者：repo owner（決策內容，2026-11-14）
- 相關 ADR：ADR-0006（Layout 模型與設定檔）、ADR-0017（Layout 回放改用 3D）
- 取代：ADR-0017 第 8 點「Layout 編輯器維持 2D」
- 對應 ticket：#116（決策）、#117（實作）

## 背景

- ADR-0017 把 Layout 回放改為 WebView2 內嵌 three.js 的 3D，取代 2D；第 8 點決定編輯器維持 2D。#113 已實作並合併。
- 使用者要求「編輯 Layout 也要 3D 化」（2026-11-14）。
- 現有的 2D 編輯器功能很多：新增、拖曳移動、調整大小、旋轉 90 度、0.5 公尺吸附、框選、Ctrl+C／V、Del、復原、導軌的點與弧線（凸度）、輸送線交接點、多樓層的單層／並排、屬性面板、存檔前檢查。
- 編輯的邏輯在 C# 的 `LayoutEditorViewModel`（有大量測試）；2D 畫面只把滑鼠座標（公尺）傳給 ViewModel。
- 3D 回放已有場景資料（C# → 網頁）與點選回報（網頁 → C#）的機制。

## 決策

1. **3D 完全取代 2D 編輯畫布**（使用者決定）：選取、拖曳移動、框選、0.5 公尺吸附、調整大小、旋轉、導軌的點與弧線、輸送線交接點、貼上到滑鼠位置，都在 3D 中完成。取代 ADR-0017 第 8 點。
2. **技術**：沿用 ADR-0017：WebView2 內嵌 three.js，使用同一份隨程式打包的固定版本 Runtime，只載入程式資料夾內的檔案、封鎖所有網路請求；元素的外觀與回放相同。
3. **程式架構**：編輯邏輯留在 C# ViewModel（Jev 1.0）。網頁只負責：
   - 把滑鼠動作換算成**目前樓層平面上的座標**（公尺）回報 C#；C# 呼叫 ViewModel 既有的選取、拖曳、框選、貼上等方法，吸附、復原、存檔前檢查不變。
   - 畫出 C# 傳來的場景與選取狀態。
4. **滑鼠**（使用者決定）：
   - 左鍵：點選、拖曳元素、在空白處拖曳框選。
   - 右鍵拖曳旋轉相機、中鍵拖曳平移、滾輪縮放。
   - 回放仍為左鍵旋轉、右鍵平移（ADR-0017）；兩者不同，在使用說明中說明。
5. **視角**：預設**正上方俯視、正交投影**（像 2D，方便精確放置），按鈕切換為斜上方 45 度透視；可以回到預設視角（Jev 0.78）。
6. **樓層**：與回放相同上下堆疊（樓板高度，ADR-0006 第 13 點），可勾「只顯示目前樓層」避免上層遮擋（Jev 0.64）。原本的單層／並排、橫向／垂直移除。
7. **高度**：3D 中提供**垂直拖曳把手**調整元素高度（使用者決定）；料架的層數與每層高度在屬性面板修改。
8. **調整大小與旋轉**：選取元素時，在樓層平面上顯示四角的調整大小把手與旋轉 90 度的按鈕（Jev 0.72）。
9. **WebGL 或 WebView2 不能用時**：畫布位置顯示原因；元素清單、屬性面板、樓層列、解析規則等表格照常使用（可以直接改座標數字）。**不保留 2D 退路**（Jev 0.96）。
10. **測試**（使用者決定）：冒煙測試改為透過網頁回報與 3D 上的名稱標籤操作；拖曳、框選、調整大小、高度、導軌點與交接點由 ViewModel 測試（以樓層平面座標）涵蓋。
11. **後續**：決策記錄在 #116；實作為 #117，經使用者指示後才進行。實作前與使用者確認把手外觀、鍵盤快速鍵、「只顯示目前樓層」的預設值（#117 待確認）。

## 理由

- 使用者希望編輯與回放看到同一個 3D 模型，避免兩套畫法。
- 編輯邏輯留在 C#：拖曳、吸附、復原、存檔前檢查與既有測試不必重寫，網頁只做座標換算與繪製，與 ADR-0017「網頁不推導狀態」一致。
- 俯視正交投影保留 2D 的精確放置；需要看高度時再切換斜視。
- 表格與屬性面板本來就能修改所有欄位，WebGL 不能用時仍可完成編輯，不必另外維護 2D。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 維持 2D（ADR-0017 第 8 點） | 使用者要求 3D 化 |
| 2D 編輯＋3D 預覽 | 使用者選擇 3D 完全取代 |
| 2D 與 3D 並存，3D 只做基本編輯（Jev 建議） | 使用者選擇只維護一套畫布 |
| 編輯邏輯移到網頁端 | 既有邏輯與測試要重寫，且 C# 與網頁會有兩份 Layout 的狀態 |
| 編輯／檢視模式切換 | 使用者選擇左鍵編輯、右鍵旋轉，不需要切換 |
| 預設斜視透視 | 精確放置較難 |
| 高度只在屬性面板（Jev 建議） | 使用者希望在 3D 中直接拖曳 |
| 保留隱藏的 2D 畫布給測試 | 只為測試維護一套畫面，不划算 |
| 保留 2D 作為 WebGL 不能用時的退路 | 要維護兩套畫布；表格與屬性面板已可完成編輯 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 3D 中精確拖曳比 2D 難，斜視時更明顯 | 放置不準、操作慢 | 預設俯視正交；拖曳投影到目前樓層的地板；0.5 公尺吸附；屬性面板可輸入數字 |
| 導軌的點與弧線把手在 3D 中不好點 | 編輯導軌困難 | 把手大小隨相機距離調整；實作後試用（#117） |
| 左右鍵的操作與回放不同 | 使用者混淆 | 畫布上顯示操作提示，使用說明說明 |
| 冒煙測試無法直接在 WebGL 畫面上拖曳 | 拖曳的畫面整合沒有自動測試 | ViewModel 測試涵蓋拖曳邏輯；冒煙測試檢查載入、點選與網頁回報；人工試用 |
| WebGL 不能用的電腦看不到畫布 | 只能用表格編輯 | 第 9 點；必要時以新的 ADR 恢復 2D |
| 編輯器與回放共用網頁程式 | 修改一邊影響另一邊 | 共用繪製部分，編輯專用的操作分開；兩邊的冒煙測試都要通過 |

## 後續驗證方式

- ViewModel 測試：以樓層平面座標測試拖曳、框選、調整大小、高度、導軌點與交接點、貼上位置。
- 冒煙測試：編輯器 3D 載入完成、沒有網路請求、點 3D 上的名稱標籤選取元素並在屬性面板顯示。
- 人工試用：導軌與交接點把手、斜視下的拖曳精確度。
- 乾淨、離線的 Windows 10 實機確認（與 ADR-0017 一起）；確認後本 ADR 改為已接受。
