# ADR-0019：RM 與雙深料架

- 日期：2026-11-15
- 狀態：**已接受**（深淺推估的啟用條件與 LOG 中的編號對應待確認，見「待確認」）
- 確認者：repo owner（決策內容，2026-11-15）
- 相關 ADR：ADR-0005（回放的世界模型）、ADR-0006（Layout 模型與設定檔）、ADR-0017（3D 回放的外觀）、ADR-0018（Layout 編輯器 3D）
- 對應 ticket：#121（決策）；實作另開 ticket

## 背景

使用者說明（2026-11-14～15）：

- **搬送機有兩種**：
  - **STV**：低矮的軌道車，沿導軌前後移動（目前的「搬送機」元素）。
  - **RM**：只負責把貨物從 Conv 取走放進料架，或從料架取出放到 Conv。
- **料架有兩種**：單深，以及有深、淺之分的**雙深**。
  - 深、淺庫位是不同的儲位，**各有獨立的儲位編號**。
  - 深淺是相對所屬的 RM 而言，離 RM 近的為淺。
  - 排號依序為：深(1) 淺(2) **RM1** 淺(3) 深(4) ｜ 深(5) 淺(6) **RM2** 淺(7) 深(8) ……（範例）。
  - 深淺庫位都正常時，**入庫必先入深庫位**，之後才放淺庫位；**出庫反之**，深淺都有貨時必先取淺庫位的貨物。
  - 不是每個廠都有雙深儲位，有些廠只有單深。
- 儲位編號的格式為 **RCCCLL**（排 1 碼、列 3 碼、層 2 碼），例如 `100101`＝第 1 排、001 列、01 層（範例／虛構）。
- 本機 LOG 樣本中有三種搬送機編號的字首（細節只在本機，ADR-0009）；哪一種是 RM、哪一種是 STV **待確認**。

判斷紀錄（2026-11-14～15）：

| 題目 | Jev | 結果 |
|---|---|---|
| 另開決策 issue（不放進外觀的 PR） | 1.0 | 採用 |
| Layout 怎麼區分 STV／RM | 搬送機加種類欄位 0.94 | 使用者決定：**RM 另成新的元素種類** |
| 雙深在 Layout 的表示 | 0.14（無法判斷） | 使用者決定：由儲位編號（排號）判斷深淺 |
| 排的設定方式 | 選填的排配置表 0.70 → 0.56 | 使用者決定：**選填的「排的配置表」**，沒填＝單深 |
| 深淺規則的用途 | 推估 0.38（不足） | 使用者決定：**LOG 沒寫明時用規則推估** |
| RM 在回放中的位置 | 沿巷道內插 0.62 | 採用 |
| RM 的走行範圍 | 指定導軌 0.66 | 採用 |
| RM 的 3D 外觀 | 堆高起重機樣式 0.36（不足） | 使用者決定：堆高起重機樣式 |
| 回放怎麼呈現雙深 | 側視圖分深淺 0.52（不足） | 使用者決定：側視圖分深淺 |

## 決策

1. **RM 是新的元素種類**（`type`: `rm`，使用者決定），不是搬送機的一個種類。
   - 有 LOG 意義，可以有別名；命令一段的派送、抵達、作業完成與狀態（連線、模式、作業、載著的貨物、警報）的推導比照搬送機（ADR-0005）。
   - 設定檔用到 RM 時格式版本寫 `7`（ADR-0006「用到新功能才升版」）。
   - STV 維持現有的「搬送機」元素（`vehicle`）。
2. **儲位編號格式為 RCCCLL**（使用者決定）。深淺由**排號**判斷，不另設深淺碼。
3. **排的配置表**（選填，廠別設定，使用者決定）：
   - 每個排號填**所屬的 RM**；雙深的廠再填**深或淺**與**配對的排號**。配對是同一側相鄰的兩排、同列同層（例如 1↔2、3↔4）。
   - 沒有填配置表：視為單深，也不知道排屬於哪台 RM（RM 固定顯示，不移動）。
   - 存檔前檢查：排號不重複；所屬 RM 存在；深淺與配對成對（深配淺、互相指向、所屬 RM 相同）。
   - 用到配置表時格式版本寫 `7`。
4. **深淺規則的推估**（使用者決定）：LOG 沒寫明深淺時，用「入庫先深、出庫先淺」推測貨物放在哪一格，**標示推估**，並可跳到造成的事件。
   - 什麼情況 LOG 不會寫明深淺 **待確認**（第 10 題）；在確認以前，推估的功能**不啟用**，只在 LOG 寫出儲位編號時記錄（依 LOG）。
   - 只用來推估，不做違反規則的一致性檢查（使用者選擇推估，不選「兩者都做」）。
5. **RM 的走行**：RM 比照 STV 指定一條導軌（巷道中央的直線，使用者決定）。
   - 回放時沿導軌移動：位置依派送的來源／目的（Conv，或儲位所在的列）在派送與抵達之間依時間內插；載貨台高度依儲位的層；**全部標示推估**（沿用 ADR-0005 第 10 點）。
   - 沒有指定導軌或沒有排的配置表時，固定畫在 Layout 放的位置。
6. **RM 的 3D 外觀**（使用者決定）：一般堆高起重機的樣式——底部走行台車、兩支立柱、頂部連桿、沿立柱上下的載貨台，貨物放在載貨台上。只參考一般外觀，不使用任何廠商的模型或標誌（ADR-0017 第 5 點）。
7. **回放的呈現**（使用者決定）：
   - 料架側視圖每層分**深、淺兩格**（有排的配置表時）；推估的格子標示推估。
   - 3D 中深淺兩排各自放貨箱。
   - 設備狀態表列出 RM（比照搬送機），其他不變。
8. **後續**：決策記錄在 #121；實作另開 ticket，經使用者指示後才進行。

## 理由

- RM 與 STV 的動作範圍與外觀不同（使用者），另成元素種類讓 Layout、3D 外觀與屬性面板各自清楚。
- 深淺各有儲位編號，排號就能判斷深淺；用配置表記錄所屬 RM 與配對，不規則的配置也能處理，單深的廠不必填。
- 推估與一致性檢查都要能追溯到事件，並明確標示，符合「推不出來就標示未知或推估」的原則（ADR-0005）。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 搬送機加「種類」欄位（Jev 建議） | 使用者選擇 RM 另成元素種類 |
| 一個料架元素加「深度＝2」填兩個排號 | 使用者選擇由儲位編號（排號）判斷；配對改在排的配置表 |
| 只設定固定樣式（每台 RM 4 排）由程式推算 | 不規則的配置無法表示 |
| 每個料架元素各填深淺與配對 | 同一排可能分成多個料架元素，重複填寫容易不一致 |
| 規則只做一致性檢查 | 使用者選擇 LOG 沒寫明時也要推估 |
| RM 固定顯示 | 使用者選擇沿巷道移動（推估） |
| RM 元素畫成巷道長條 | 使用者選擇比照 STV 指定導軌 |
| 只在元素狀態列出深淺 | 使用者選擇側視圖分深淺兩格 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| LOG 中 RM／STV 的編號對應未確認 | 別名設錯，命令與貨物推導錯誤 | 待確認；程式不依字首判斷，以 Layout 的元素種類為準 |
| 深淺推估的時機未確認 | 推估錯誤或過度推估 | 確認前不啟用推估；推估一律標示並可跳到事件 |
| 本機廠別設定的儲位規則（7 碼）與 RCCCLL 不同 | 儲位編號拆錯，料架與側視圖對不上 | 使用者確認後在編輯器修改；程式不自動改 |
| RM 的位置與載貨台高度是推估 | 被當成實際位置 | 一律標示推估，與 STV 相同 |
| 舊版程式打不開有 RM 或排配置表的設定檔（格式版本 7） | 舊版無法使用 | 明確提示改用新版（ADR-0006 第 7 點） |

## 後續驗證方式

- 以虛構資料測試：RM 元素的讀寫與格式版本、排配置表的檢查、深淺的推估與標示、RM 沿導軌的位置與載貨台高度、側視圖的深淺兩格、3D 外觀。
- 取得含 RM 與雙深料架的 LOG 樣本後，確認編號對應與深淺沒寫明的情況，再決定推估是否啟用。

## 待確認

1. LOG 樣本中三種搬送機編號字首各是什麼設備（是否有第三種）。
2. 什麼情況 LOG 不會寫明深淺（推估的啟用條件）。
3. 本機廠別設定的儲位規則改為 RCCCLL（使用者在編輯器修改）。
