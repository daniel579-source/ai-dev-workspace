# ADR-0020：工站點、圍欄、圍欄門與設備外觀修正

- 日期：2026-11-16
- 狀態：**已接受**（電梯閘門的開關為推估；圍欄門的開關與模式待 LOG 有紀錄時再加）
- 確認者：repo owner（決策內容，2026-11-16）
- 相關 ADR：ADR-0005（回放的世界模型）、ADR-0006（Layout 模型與設定檔）、ADR-0017（3D 回放）、ADR-0018（Layout 編輯器 3D）、ADR-0019（RM 與雙深料架）
- 對應 ticket：#150

## 背景

使用者說明（2026-11-16）：

- STV 的示意圖中，滾筒要轉 90 度；Conv 的示意圖兩側不要護欄。
- 電梯兩側有圍欄；電梯與其他 Conv 對接的位置有會開關的閘門。有些特殊位置兩側都對接 Conv，兩側都需要閘門。
- 除了料架、電梯和 RM 之外，設備的預設高度為 0.8 公尺。
- 需要三種新元件：
  1. **工站點**：類似站點，但站點兩端都對接設備；工站點一端給使用者操作的設備（例如堆高機），另一端接 Conv。示意圖要有紅、藍、白、綠、黃 5 色燈柱。
  2. **圍欄**：與搬送命令無關，只幫助使用者辨識位置。現場大多是黃色網狀、2.5 公尺高。
  3. **圍欄門**：配合圍欄使用，門邊有手動／自動切換的旋鈕，門高約 1.8 公尺，門的上方也是黃色網狀。LOG 目前沒有記錄門的切換狀態，未來需要時再加。
- LOG 沒有記錄電梯閘門的開關（電梯只有派送、抵達、作業完成，ADR-0005 第 11 點）。

## 決策

1. **外觀修正**（回放與 Layout 編輯器共用，ADR-0017、ADR-0018）：
   - STV：頂面滾筒轉 90 度。
   - Conv：拿掉兩側護欄。
   - 電梯：四個側面中，對接的側面畫閘門，其餘側面畫圍欄。
   - 2026-11-16 補充（使用者要求）：RM 載貨台的滾筒也轉 90 度（軸沿寬度方向）。
2. **預設高度**：站點、STV、Conv、輸送線改為 **0.8 公尺**（使用者決定只改設備類）。防火門、區域、導軌、文字維持原樣；料架、電梯、RM 不變。元素在 Layout 編輯器填的高度優先。
3. **電梯閘門**：
   - 位置自動判斷：服務樓層上緊鄰電梯（0.3 公尺內）的 Conv、站點、工站點所在的那一側。兩側都對接時兩側都畫閘門。
   - 輸送線仍不接電梯（ADR-0006 第 15 點不變：電梯只透過每層的出入口站點和其他設備交接）。決策討論時曾寫成「有輸送線連到電梯的那一側」，實作時發現與 ADR-0006 衝突，改為只依緊鄰的設備判斷（2026-11-16）。
   - 開關（**推估**，以虛線表示）：台車抵達某樓層時，朝向這次目的地設備的那一側閘門畫成開；其他時間畫成關。目的地不在閘門那一側時不畫開。LOG 沒有記錄閘門開關。
4. **工站點**（新元件種類 `workstation`）：
   - 世界模型比照站點：別名、在席、貨物、命令、警報、站點模式與運轉狀態都一樣處理；只有外觀與種類名稱不同（使用者決定，Jev 0.68）。
   - 可以當作輸送線的一端（和站點相同）。
   - 外觀：台面加 5 色燈柱（紅、藍、白、綠、黃），燈柱只是**裝飾**，不代表狀態（使用者決定）。預設高度 0.8 公尺。
5. **圍欄**（新元件種類 `fence`）：
   - 折線，畫法與導軌相同（使用者決定）。外觀為黃色網狀，預設高度 2.5 公尺。
   - 不參與世界模型，不推導任何狀態；不需要別名。
6. **圍欄門**（新元件種類 `fenceGate`）：
   - 獨立元件，放在圍欄的缺口上；預設寬 1 公尺（使用者決定）。
   - 外觀：門高約 1.8 公尺，門上方到 2.5 公尺為黃色網狀，門邊有手動／自動旋鈕（裝飾）。門一律畫成關著。
   - 不推導狀態。LOG 目前沒有記錄門的開關與模式，有需要時再加效果與欄位。
7. **設定檔格式**：用到工站點、圍欄或圍欄門時，格式版本為 **8**；沒用到時照舊寫最低版本（ADR-0006 第 7 點），舊版程式照常開啟。
8. **EQ**（2026-11-16 補充，使用者決定，#154；新元件種類 `eq`）：
   > 2026-11-26：「只是外觀、不推導狀態」**由 ADR-0026 取代**——EQ 可以有別名、當輸送線的端點，貨物交給 EQ 並收到完成回報才算已交出；門改為 EQ 上有棧板等待完成回報時開。外觀與門的方向不變。
   - 其他公司的對接設備（ADR-0005 背景：LOG 中的 EQxxx）。**只是外觀，不推導狀態**：沒有別名、警報或貨物（使用者選擇；Jev 傾向比照 Conv，信心度 0.3）。Conv 的「等待完成回報／已交出」不變。
   - 外觀：像洗衣機或單門冰箱的箱體與一扇門；預設寬 1.5、深 1.5、高 1.8 公尺。
   - 門的方向：自動朝緊鄰（0.3 公尺內）的 Conv（Jev 0.91）；沒有緊鄰的 Conv 時朝元件的前方（深度方向的 +y 側）。
   - 門的開關（**推估**）：緊鄰的 Conv 上有棧板「等待完成回報」時畫成開，其他時間畫成關（Jev 0.43，使用者確認）。LOG 是否記錄門的開關**待確認**（假設沒有）。
   - 用到 EQ 時格式版本為 **9**。
   - 捨棄的方案：EQ 比照 Conv 推導「交出」（與 Conv 的行為重複，LOG 中交出的對象目前對應到 Conv）；EQ 比照站點（貨物不會停在其他公司的設備上）；在編輯器手動選門的方向（多一個要維護的設定）。

## 理由

- 外觀依現況修正，工程師在回放中比較容易對應到現場。
- 工站點在 LOG 中與站點的行為相同（讀到棧板、在席、命令的來源與目的地），比照站點可以沿用全部推導規則；分成獨立種類是為了外觀與編輯器中的辨識。
- 圍欄與圍欄門只是位置的參考；不參與世界模型，避免與命令或狀態混淆。
- 電梯閘門與圍欄門沒有 LOG，依 CLAUDE.md 3.3 節不寫成事實：閘門開關標示為推估，圍欄門一律畫成關著。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 預設高度照字面全部改 0.8（含防火門、區域、導軌、文字） | 防火門只剩 0.8 公尺，貼地的區域與導軌變成立體元件，與現況不符（使用者選擇只改設備類） |
| 電梯閘門一律畫成關著 | 回放時看不出台車在哪一側交接 |
| 電梯閘門等 LOG 有紀錄再表示 | 現在完全看不出閘門的意義（使用者選擇推估） |
| 電梯閘門在 Layout 編輯器手動勾選 | 多一個要維護的設定；設備的位置已經在 Layout 中（使用者選擇自動判斷） |
| 讓輸送線可以接電梯，依輸送線判斷閘門 | 會改變 ADR-0006 第 15 點「輸送線不接電梯」的決策；緊鄰的設備已足以判斷 |
| 工站點只是站點上的一個屬性 | 編輯器與回放中不容易分辨，篩選與統計也要另外處理（Jev 0.68，使用者確認） |
| 5 色燈柱依狀態亮燈 | 各顏色在現場代表什麼還不清楚；沒有依據時不推測（使用者選擇裝飾） |
| 圍欄用直線段 | 圍一圈要放很多段；折線與導軌的編輯方式一致（使用者選擇折線） |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 電梯閘門位置的自動判斷不準（對接的設備沒有緊鄰電梯） | 閘門畫在錯的一側或沒有畫 | 在 Layout 中把對接的設備放在電梯旁（0.3 公尺內）；需要時再增加手動設定 |
| 電梯閘門的開關是推估 | 與現場實際不同 | 以虛線表示推估；LOG 有紀錄時改依 LOG |
| 圍欄門畫成關著，但現場可能開著 | 誤以為門關著 | 使用手冊說明門的狀態沒有 LOG；待需要時再加 |
| 工站點兩端（使用者端、Conv 端）在外觀上沒有區分方向 | 不容易看出哪一端給堆高機 | 先以燈柱位置辨識；需要時再增加方向設定 |

## 後續驗證方式

- 以虛構資料的測試涵蓋：格式版本 8 的讀寫、舊版設定開啟、工站點的狀態推導與站點相同、電梯閘門位置的判斷與抵達時的開關。
  - 2026-11-16 **已完成**（#150）：引擎 5 個、Workspace 3 個測試；截圖確認圍欄、圍欄門、工站點、STV、Conv 的外觀。電梯閘門因虛構資料沒有電梯事件（台車未畫出），只以測試確認。
- 以截圖確認外觀，並在乾淨、離線的 Windows 10 實機確認（與 ADR-0017 相同方式）。
