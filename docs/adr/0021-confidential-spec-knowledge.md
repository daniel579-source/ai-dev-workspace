# ADR-0021：機密規格書的知識庫整理流程與電文／代碼對照表

- 日期：2026-11-17
- 狀態：**已接受**（對照表的欄位為**候選**格式，實作與實際整理後再確認）
- 確認者：repo owner（決策內容，2026-11-17）
- 相關 ADR：ADR-0009（資安）、ADR-0013（知識庫與本機離線 LLM）、ADR-0014（第一線問答助理）、ADR-0015（知識檢索）、ADR-0016（異常紀錄）
- 對應 ticket：#156（實作，2026-11-17 完成）

## 背景

使用者說明（2026-11-17）：

- 手上的資料分成兩類：
  1. **搬送設備的通信仕樣書**：AGC（Word，197 頁）、RM（PDF，178 頁）、STV（PDF，93 頁）。內容是通訊相關的規格，各廠共用、沒有差別；內部機密，中文與日文都有。除了不能外流之外沒有其他使用限制。
  2. **各廠專屬的機密資料**：網路架構、設備數量、軟體流程圖、各廠 layout。絕對不能外洩。
- 目前**沒有**異常代碼表，也沒有故障排除資料。
- 公司**授權使用 M365 Copilot** 處理公司資料；Claude Code（開發用的雲端助理）**沒有**獲得授權讀取這些資料。CLAUDE.md 第 13 條的例外只涵蓋在本機讀取真實 LOG（ADR-0009）。
- 回溯系統的使用現場**沒有對外網路**，最多只有地端 LLM（ADR-0013，硬體待確認）。
- AGC 目前沒有廠使用；未來有廠使用時會有 LOG。

通信仕樣書規定 WCS 與設備之間的電文格式、欄位與狀態碼，可以用來解讀 LOG：例如命令錯誤訊息、搬送機連線與自動／手動的電文（#47 C1、C2 的待確認項目）。

## 決策

1. **分工：程式送到資料那邊，資料不送到 Claude**（Jev 判定此做法較安全，信心度 1.0）：
   - **M365 Copilot**（已授權）：在辦公室依「指令包」讀規格書，抽出對照表草稿。
   - **工程師**：審核、修正草稿，放進本機 `D:\LogTrace\Knowledge\`。
   - **Claude Code**：只寫指令包、輸出格式、以**虛構**規格書片段做的範例與檢查程式；**不讀任何機密內容**，只看檢查程式輸出的統計數字。
   - 技術上的阻擋（2026-11-17 已在開發電腦設定，`.claude/` 不進 repo）：權限規則禁止讀寫 `D:\LogTrace\Knowledge\**`、`D:\LogTrace\Plants\*.kb.csv`、`D:\LogTrace\Plants\*.incidents\**`；PreToolUse hook 另外檢查檔案工具的路徑與 Bash／PowerShell 指令，碰到這些路徑就阻擋。廠別設定（`*.json`）與 repo 內的 `log\` 不在阻擋範圍。
   - Jev 是外部服務，同樣不得經手這些資料。
2. **現場離線**：LogTrace 只讀**審核過**的檔案，以程式查表，**不需要 LLM**（Jev 0.08 判定查表不需要地端 LLM）。地端 LLM 不負責整理規格書，只保留給日後的自然語言問答（ADR-0013、ADR-0014）。
3. **知識庫分層**：
   - **共用的設備對照表**：依設備種類放在 `D:\LogTrace\Knowledge\shared\<RM|STV|AGC>\`，各廠共用。
   - **各廠補充**：`D:\LogTrace\Knowledge\plants\<廠別>\`。
   - 原本的 `<廠別>.kb.csv`（警報代碼表，ADR-0013 第 2 點）照舊可以使用。
   - 一個廠套用哪幾份共用對照表，依該廠 Layout 中有的設備種類決定（例如有 RM 元件就套用 RM 的對照表）。
4. **對照表格式**（**候選**，CSV）：設備種類（RM／STV／AGC）、類別（電文／欄位／狀態碼／錯誤碼）、代碼或名稱、意義（原文）、意義（中文；原文為日文時由 Copilot 翻譯並標示「翻譯」）、出處（文件名、章節、頁碼）、規格書版本或日期、狀態（已審核／待確認）、審核者、審核日期。
   - 規格書中查不到的一律填「待確認」，不推測。
   - 日文保留原文，另加中文翻譯（Jev 0.91）；每一列記錄規格書版本或日期，規格改版時可以追溯（Jev 0.78）。
5. **LogTrace 中的用法**：事件的解析欄位抽出代碼時，詳細資訊顯示這個代碼在對照表中的意義與出處頁碼；翻譯標示「翻譯」；狀態為「待確認」的列不當作確定的說明。對照表與知識庫一樣只放本機，不存入案件、不記入稽核。
6. **指令包**（放在 repo 的 `tools/spec-extract/`，只含程式、提示詞與虛構範例）：分步驟的提示詞（切段、判斷段落類型、抽出電文欄位、抽出代碼對照）、輸出格式、虛構範例、本機檢查程式（格式、缺頁碼、重複、矛盾，只輸出統計）。
7. **以規格書修正解析規則**：由工程師在本機對照規格書，以**去識別化**的方式描述格式（例如「錯誤碼是 2 碼英文加冒號加 2 碼數字」）給 Claude 修改解析規則；不貼規格書原文。
8. **各廠專屬的機密資料先不放進知識庫**（使用者同意；Jev 0.19）：Layout 已在 Layout 編輯器中；網路架構、流程圖等日後有需要再另外決定。
9. **AGC**：等有廠使用、有 LOG 時，再新增 AGC 元件與解析欄位（使用者同意；Jev 0.21）。對照表的 AGC 部分可以先整理。

## 理由

- 只有已授權的 Copilot 與工程師碰到機密原文；Claude 只接觸程式、格式、虛構範例與統計，符合 CLAUDE.md 第 13 條與 ADR-0009。
- Copilot 的模型能力比筆電上的小模型強，處理長文件與跨頁表格的錯誤較少；規格書整理一次就好，不需要每個現場重做，也不必等現場筆電規格確定。
- 現場只做查表，離線也能使用，與 ADR-0001（單機、離線）一致。
- 對照表附出處頁碼，工程師可以回到原文確認，符合 ADR-0013「事實要有出處」的原則。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| Claude Code 直接讀規格書（比照真實 LOG 的例外） | 沒有授權；內容會送到外部服務 |
| 地端 LLM 讀規格書，寫成摘要或去識別化內容交給 Claude | 摘要仍帶有機密（例如代碼的意義本身就是規格內容），小模型也不保證遮罩乾淨（Jev 0.1 判定不足以避免外洩） |
| 由現場的地端 LLM 整理規格書 | 3～8B 小模型處理長文件與跨頁表格的錯誤率高，且要等現場筆電規格（ADR-0013 待確認） |
| 在程式內收錄規格書全文、做全文搜尋 | 需要 PDF 抽取套件（技術選型）；現場主要需要代碼查詢，全文留待日後再評估 |
| 每廠各放一份設備資料 | 規格各廠共用，複製多份容易改漏 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| Copilot 抽錯或漏抽 | 回放顯示錯誤的代碼意義 | 工程師審核、抽查原文；檢查程式的統計；每列附出處頁碼 |
| 阻擋設定只在開發電腦 | 換電腦時可能沒有阻擋 | 換電腦時重新設定；這份 ADR 與使用說明記錄設定內容 |
| hook 執行失敗時不阻擋（避免所有工具都不能用） | 只剩權限規則擋 Read／Edit，shell 指令不受限 | 權限規則仍有效；hook 需要 Python，換環境時先確認 |
| 日文翻譯錯誤 | 中文說明與原意不同 | 保留原文；翻譯標示「翻譯」並在審核時確認 |
| 規格書改版 | 對照表過期 | 每列記錄版本或日期；改版時重新整理 |
| 對照表本身是機密 | 外流 | 只放本機 `D:\LogTrace\Knowledge\`，不進 repo；repo 只放虛構範例 |

## 實作（2026-11-17，#156）

- 引擎 `SpecTables`：讀取 `shared\<RM|STV|AGC>\*.csv` 與 `plants\<廠別設定檔名>\*.csv`；讀取時檢查，格式有誤的列不使用，同一代碼意義不同、缺版本列為「需要注意」；統計一行文字（給工程師回報）。檢查內建在 LogTrace（Jev 0.85），不另寫腳本。
- 第一版以事件的警報代碼（`alarmCode`）查表（Jev 0.67）；設備種類依事件對應到的元素（Jev 0.98）。要抽出其他代碼欄位，等依規格書確定解析規則後再加（待確認 3）。
- 知識庫資料夾＝廠別設定資料夾的上一層加 `Knowledge`。
- `tools/spec-extract/`：README、欄位說明、Copilot 提示詞 5 段、虛構範例（日文 RM、中文 STV）與正確輸出；測試確認範例輸出通過檢查。

## 後續驗證方式

- 以虛構規格書片段驗證指令包與檢查程式：抽取結果與正解的符合率、缺頁碼與重複的偵測。
- 使用者以 Copilot 實際整理一份規格書後，回報檢查程式的統計與抽查結果（去識別化），依此修正指令包。
- LogTrace 讀取對照表的單元測試與冒煙測試（虛構資料）。

## 待確認

1. 實際整理後，對照表欄位是否足夠（候選格式）。
2. 各廠專屬的機密資料日後是否需要、以何種方式進入知識庫。
3. 解析規則要抽出哪些代碼欄位，才能對到對照表（依規格書的電文格式而定）。
