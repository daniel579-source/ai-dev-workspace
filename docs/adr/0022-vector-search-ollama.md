# ADR-0022：向量搜尋的 embedding 模型、執行環境與儲存方式

- 日期：2026-11-17
- 狀態：**提議中**（模型與執行環境都是**候選方案**；IT 同意安裝 Ollama、以 #89 情境集比較並在現場筆電實測後，才改為已接受）
- 確認者：repo owner（決策內容，2026-11-17）；接受與否待實測
- 相關 ADR：ADR-0001（交付形式）、ADR-0009（資安）、ADR-0013（知識庫與本機離線 LLM）、ADR-0015（知識檢索）、ADR-0016（異常紀錄）
- 對應 ticket：#89（比較驗證）、#55（現場硬體、IT、授權）

## 背景

ADR-0013 第 3 點把「sqlite-vec 加上小型 embedding 模型」列為向量搜尋的候選方案；ADR-0015 第 5 點保留向量搜尋，用來找出用詞不同但意思相近的知識庫條目與異常紀錄現象。2026-11-16 #89 的虛構情境集第一版中，「只用問題文字的關鍵字比對」的知識庫條目召回只有 27%，要和「只用向量搜尋」比較，必須先選定 embedding 模型與套件（ADR-0015 後續驗證）。

限制條件：

- 知識庫以正體中文為主，含部分日文（ADR-0021）；條目數量約數百到數千條（**假設**，數量待確認，ADR-0015 待確認 2）。
- 現場離線；真實資料不得送到外部服務（ADR-0009）。
- 現場筆電規格未知（ADR-0013 待確認 1），同一台還要執行 3～8B 的 LLM。
- 程式是 .NET 10 的 Windows 桌面程式。
- ADR-0001：LogTrace 本身為免安裝執行檔；工程師電腦不能自行安裝軟體。

## 決策（提議）

1. **模型**：multilingual-e5-small 與 bge-m3 一起比較，兩者都是**候選方案**。
   - multilingual-e5-small：約 118M 參數、384 維、512 tokens；查詢與條目前分別加 `query: `、`passage: ` 前綴。
   - bge-m3：約 568M 參數、1024 維、8192 tokens。
   - 參數量、維度與授權（兩者都標示為 MIT）依整理時的知識，選定前以官方模型卡核對（ADR-0013 待確認 4）。
   - Ollama 官方模型庫沒有 multilingual-e5-small 時，從 Hugging Face 取得現成的 GGUF 檔匯入 Ollama，記錄來源網址、檔名與 SHA-256。
2. **執行環境**：embedding 使用 **Ollama**（本機服務，以 HTTP API 呼叫），驗證與正式產品都使用。
   - Ollama 需要安裝；修改 ADR-0013 第 7 點「不需安裝」（見該點 2026-11-17 補充）。安裝要經 IT 同意（ADR-0001 限制：工程師電腦不能自行安裝軟體），列為待確認。
   - LogTrace 本身仍是免安裝執行檔（ADR-0001 第 2 點不變）；Ollama 是 AI 可選功能的外部元件。
   - 只連本機位址（預設 `127.0.0.1:11434`，**待確認**），不連外網、不使用 Ollama 的雲端功能。
3. **LLM 的執行環境不變**：維持 ADR-0013 第 8 點的候選（ONNX Runtime GenAI 為主、llama.cpp 為備案），Ollama 只負責 embedding（使用者決定，2026-11-17）。
4. **向量儲存**：不加套件，在 C# 對所有條目逐條計算 cosine 相似度，取代 ADR-0013 第 3 點的 sqlite-vec。
   - 條目的向量另外存成檔案，放在知識庫旁的本機位置，不進 repo、不存入案件 SQLite；檔案格式在實作時決定。
   - 向量檔記錄所用的模型名稱與版本；模型或條目內容變更時重建，不沿用舊向量。
5. **向量搜尋只找候選條目**（ADR-0015 第 5 點不變）：最後顯示的仍是知識庫原文與出處，不顯示由模型產生的文字。
6. **可以降級**：偵測不到 Ollama 服務或模型時，停用向量搜尋，規則關聯圖與知識庫查表照常使用（ADR-0013 第 6 點、ADR-0015 第 9 點）。
7. **範圍**：本 ADR 只決定選型。下載與安裝 Ollama 和模型、修改程式，另外由使用者指示後進行。

## 理由

- 兩個模型大小差距大：e5-small 檢查「小模型是否就夠用」，bge-m3 檢查「中日文表現較好的大模型能改善多少」，比較結果直接決定現場的記憶體需求。
- Ollama 的模型取得與執行最簡單，不必自己處理分詞與 pooling；bge-m3 在官方模型庫有現成版本。
- LLM 維持 ONNX Runtime GenAI，保留使用 NPU 的可能；Ollama 對 NPU 的支援有限（**待確認**），用 Ollama 跑 LLM 在沒有獨立 GPU 的 AI 筆電上可能太慢、太耗電。
- Ollama 有問題時只影響向量搜尋，不影響 LLM。
- 知識庫條目只有數百到數千條，逐條比對的成本很低；不增加相依套件與原生 dll。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| ONNX Runtime + Microsoft.ML.Tokenizers 執行 embedding | 不需安裝、可在程式內執行，但要自己處理分詞與 pooling，XLM-R 系列（e5、bge-m3）的 SentencePiece 分詞支援待確認；使用者選擇 Ollama |
| llama.cpp／LLamaSharp 執行 embedding | 要帶原生 dll，主要只能用 CPU／GPU |
| LLM 也改用 Ollama（只用一套執行環境） | 部署較簡單、記憶體統一管理，但 NPU 支援有限；使用者選擇 LLM 維持 ONNX Runtime GenAI |
| sqlite-vec | 還沒到 1.0 版、要多帶原生擴充 dll；條目少時逐條比對就夠快 |
| 只測一個模型 | 無法判斷小模型是否就夠用 |
| Qwen3-Embedding-0.6B | 最大、最慢；保留為之後的候選 |
| EmbeddingGemma-300M | 授權為 Gemma 專用條款，需要法務確認 |
| granite-embedding-278m-multilingual | 中日文表現的資料較少；保留為之後的候選 |
| jina-embeddings-v3 | 授權為 CC BY-NC，不能商用 |

## 尚存風險

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| IT 不允許安裝 Ollama | 正式產品無法使用向量搜尋 | 可以降級（第 6 點）；改用替代方案中的 ONNX Runtime，另立補充 |
| 現場要同時部署 Ollama 與 ONNX Runtime GenAI 兩套執行環境 | 部署與維護較複雜；兩邊各自載入模型，記憶體互不知道 | 實機量測同時執行時的記憶體；必要時 LogTrace 控制載入順序，或用完卸載 embedding 模型 |
| Ollama 本機服務的 HTTP 埠 | 其他程式可以呼叫 | 確認只監聽本機位址；不開放外部連線 |
| 從 Hugging Face 匯入的 GGUF 是第三方轉檔 | 品質或內容可能有問題 | 記錄來源與 SHA-256；以情境集結果確認品質 |
| bge-m3 與 LLM 同時執行時記憶體不足 | 太慢或無法執行 | 比較結果若 e5-small 已足夠，改用小模型；現場筆電實測 |
| 中日文用詞與現場用語差距大 | 向量搜尋找錯條目 | 只用來找候選條目，最後內容仍是原文與出處；以情境集量測 |
| 知識庫條目遠多於預期 | 逐條比對變慢 | 量測查詢時間；必要時改用 sqlite-vec 等索引 |

## 後續驗證方式

- 以 #89 同一份虛構情境集比較：關鍵字比對（召回 27%）、只用 e5-small 向量搜尋、只用 bge-m3 向量搜尋、規則關聯圖加向量搜尋。量測知識庫條目的召回與精確度、查詢時間、建立向量的時間、Ollama 的記憶體用量。只用虛構資料。
- 在現場筆電量測：Ollama 與 ONNX Runtime GenAI 的 LLM 同時執行時的記憶體與速度（可以與 #47、#55 一起進行）。
- 確認 Ollama 只監聽本機位址、離線時能正常運作。

## 待確認

1. IT 是否允許在工程師電腦與現場筆電安裝 Ollama。
2. 兩個模型與 Ollama 的授權條款（以官方模型卡與授權檔核對）。
3. Ollama 官方模型庫是否有 multilingual-e5-small；沒有時採用哪一個 GGUF 來源。
4. Ollama 的預設監聽位址與 NPU 支援情況（以官方文件確認）。
