# ADR-0026：站點與 Conv 合併為 Conv；EQ 負責交出

- 日期：2026-11-26
- 狀態：**已接受**
- 確認者：repo owner（決策內容與待決項目 1a、2a、3a、4c、5a、6a，2026-11-26）
- 相關 ADR：ADR-0005（狀態推導，第 2 點交出）、ADR-0006（Layout 模型與設定檔，第 1 點元素種類與 2026-11-14 補充）、ADR-0020（工站點、EQ，第 8 點）
- 取代：ADR-0006 第 1 點 2026-11-14 補充（「對接設備」畫面上改稱 Conv）、ADR-0020 第 8 點（EQ 只是外觀、不推導狀態）

## 背景

使用者更正（2026-11-26）：**Conv 就是站點**，之後統一顯示為 Conv，是**本公司的輸送設備**；**EQ 才是其他公司的設備**。

原本的元素種類：

- 站點（`station`）：可被 LOG 識別的位置，在席、讀到棧板、命令的來源與目的地。
- 對接設備（`dock`）：ADR-0005 中為其他公司的設備（LOG 中的 `EQxxx`），貨物在這裡交出。2026-11-14 畫面上改稱「Conv」（ADR-0006 第 1 點補充）。
- EQ（`eq`）：2026-11-16 加入，其他公司的對接設備，只是外觀（ADR-0020 第 8 點）。

2026-11-14 的改名把「其他公司的設備」稱為 Conv，與現場用語不符；「Conv」與「EQ」兩個名詞的說明也互相矛盾（GLOSSARY）。

## 決策

1. **元素種類合併為 Conv**：
   - 站點與原本的 Conv（`dock`）合併為一種元素 **Conv**：本公司的輸送設備；狀態推導沿用原本站點的規則（在席、讀到棧板、命令的來源與目的地、可能卡住）。
   - 設定檔的 `type` 改為 `conv`（4c）。讀舊設定檔時，`station` 與 `dock` 都讀成 Conv，別名、位置與 id 保留（1a）。
   - 新增 Conv 的 id 沿用 `st` 開頭（6a）。
   - 設定檔中有 Conv 時格式版本為 **11**；沒有 Conv 時照舊寫最低版本（ADR-0006 第 7 點）。
2. **EQ 負責「已交出」**（2a，回到 ADR-0005 第 2 點的原意）：
   - EQ 可以設別名（對應 LOG 中的 `EQxxx`）、可以當輸送線的端點、可以有警報。
   - 貨物抵達 EQ 時標示「等待完成回報」，收到完成回報才標示「已交出」並從畫面移除（ADR-0005 第 2 點 2026-11-15 #47 C3 修正的規則不變，只是對象從 `dock` 改為 EQ）。
   - EQ 門的開關仍依緊鄰的 Conv 推估（ADR-0020 補充）。
3. **工站點維持獨立的元素種類**（3a），名稱、外觀與推導不變（一端給使用者操作的設備，另一端接 Conv）。
4. **解析欄位種類改名**（5a）：
   - `station` → `conv`（顯示 Conv），`dock` → `eq`（顯示 EQ，對應到 EQ 元素）。
   - 規則的正規表示式**不改寫**：舊的群組名稱 `station`、`dock` 在抽取時分別視為 `conv`、`eq`；新寫的規則使用新名稱（Jev 0.94）。
   - 已建立的案件資料庫不修改：讀取時把舊的欄位種類對應到新名稱，搜尋與統計同時查新舊名稱（Jev 0.64）。
5. **畫面用語**（4c）：畫面上所有「站點」改為「Conv」：Layout 編輯器、回放與狀態面板、解析規則的欄位種類與效果名稱、搜尋條件、使用說明與 GLOSSARY。
6. **Layout 編輯器的元件依類別排列**：本公司設備（Conv、工站點、搬送機（STV）、RM、電梯、料架、防火門）、其他公司（EQ）、輔助（輸送線、導軌、圍欄、圍欄門、區域、文字）。

## 理由

- 使用者說明 Conv 與站點是同一種現場設備；保留兩種元素會讓同一個設備有兩種畫法，回放的推導也分成兩套。
- ADR-0005 的「交出」原本就是交給其他公司的設備（`EQxxx`）；由 EQ 負責與現場一致，也解決 GLOSSARY 中 Conv 與 EQ 的矛盾。
- 設定檔與欄位種類都改用新名稱（4c、5a），檔案內容與畫面用語一致；舊名稱只在讀取時對應，不需要使用者手動轉換。
- 不改寫正規表示式：使用者寫的規則可能有複雜的群組，自動改寫有改壞的風險；抽取時對應就能沿用。
- 不修改案件資料庫：案件資料庫可以繼續被舊版程式開啟，也不需要重新匯入。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 舊的 `dock` 讀成 EQ，或保留 `dock` 並提示使用者逐一轉換 | 使用者決定讀成 Conv（1a；Jev 0.97） |
| 交出改由「交出點」屬性或「緊鄰 EQ 的 Conv」決定 | 使用者決定由 EQ 負責（2a；Jev 0.52，信心度 0.28） |
| 工站點併入 Conv，成為 Conv 的選項 | 使用者決定維持獨立種類（3a；Jev 傾向合併 0.60，信心度 0.20） |
| 只改畫面名稱，設定檔仍寫 `station` | 使用者決定設定檔也改名（4c；Jev 0.64，信心度 0.46） |
| 欄位種類代碼不改，只改顯示名稱 | 使用者決定改名（5a；Jev 0.63，信心度 0.26） |
| 新增 Conv 改用 `cn` 開頭 | 使用者決定沿用 `st`（6a；Jev 傾向 `cn` 0.78，信心度 0.56） |
| 存檔時改寫正規表示式的群組名稱 | 自動改寫使用者的規則有改壞的風險（Jev 0.03） |
| 開啟案件時改寫資料庫，或要求重新匯入 | 改寫後舊版程式打不開該案件；重新匯入耗時（Jev 0.09、0.15） |

## 尚存風險

| 風險 | 影響 | 因應 |
|---|---|---|
| 幾乎所有設定檔都有 Conv，存檔後格式版本為 11 | 0.15.0 以前的程式打不開存過的設定檔 | 舊版程式會擋下並提示版本太新；發佈時一起更新 |
| 舊設定檔中的 Conv（`dock`）別名其實是 `EQxxx` | 轉成 Conv 後不再「交出」，回放中貨物停在 Conv、不會消失 | 使用說明寫明：把這些別名改放到 EQ 元素；存檔前檢查提示「有 EQ 欄位的值沒有對應的 EQ 元素」由未對應清單呈現 |
| 舊案件中以 `dock` 抽出的值 | 讀取時對應為 `eq`；Layout 中沒有對應的 EQ 元素時列為未對應 | 同上 |
| 工站點與 Conv 外觀只差燈柱 | 不容易分辨 | 元素清單分開列出；需要時再調整外觀 |

## 後續驗證方式

- 以虛構資料的單元測試：舊設定檔的 `station`、`dock` 讀成 Conv 並以 `conv` 寫出、格式版本 11；舊群組名稱的抽取；舊案件的欄位種類對應與搜尋；貨物抵達 EQ 後「等待完成回報」→「已交出」；EQ 可以當輸送線端點。
- 冒煙測試：既有的 Layout 編輯器與回放冒煙測試通過。
- 使用者以實際 Layout 試用：原本的 Conv（`dock`）是否需要改成 EQ。
