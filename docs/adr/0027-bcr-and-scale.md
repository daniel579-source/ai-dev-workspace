# ADR-0027：BCR 與磅秤的可視化

- 日期：2026-11-26
- 狀態：**已接受**
- 確認者：repo owner（決策內容與待決項目 1～12，2026-11-26）
- 相關 ADR：ADR-0005（回放的狀態推導）、ADR-0006（Layout 模型與設定檔）、ADR-0008（設備狀態表、異常紀錄）、ADR-0017（3D 回放）、ADR-0026（Conv）
- Ticket：#206

## 背景

使用者要求：回放時**只看 Layout** 就能看出

- 是否發出讀取 BCR（條碼讀取器）或磅秤的要求；
- BCR 讀到的條碼、磅秤的數值；
- 是否異常（讀取失敗、逾時、超重）。

本機真實樣本的調查（只在本機讀取，輸出遮罩；不記錄內容）：

- BCR 的紀錄有：開始讀取、停止讀取、讀到的資料、讀取失敗；PLC 另記錄讀取逾時（附錯誤代碼）、手動輸入的條碼。
- 每個 Conv 可能有棧板 BCR 與桶 BCR；桶 BCR 一次回傳多個條碼（逗號分隔）。
- 部分 Conv 有磅秤：PLC 只記錄磅秤的回傳值，**沒有記錄發出磅秤要求**；數值沒有單位。
- 與上位系統的介面 LOG 有重量上下限的欄位，但**樣本中全部為 0**。

改動前，回放只有「在 Conv 讀到棧板」一種效果，讀取器、讀取失敗、磅秤都沒有建模。

## 決策

1. **新增兩種元件**（Layout 編輯器的「本公司設備」，Jev 0.80）：
   - **BCR**（`bcr`）：別名為讀取器名稱（例如 `A-01_DRUM`）；`owner` 為所屬 Conv 的 id；`reads` 為 `bin` 時是桶 BCR，沒有寫時是棧板 BCR。讀取器名稱與 Conv 的別名相同時不必（也不能，別名不可重複）設別名，以所屬 Conv 對應。
   - **磅秤**（`scale`）：別名選填；`owner` 為所屬 Conv 的 id。
   - 有 BCR 或磅秤時格式版本為 **12**。
   - LOG 中的編號對應到 Conv 時（例如讀取器名稱與 Conv 相同、PLC 的讀取逾時、磅秤回傳值），對應到所屬為該 Conv 的 BCR（優先棧板 BCR）或磅秤。
2. **新增欄位種類與效果**：
   - 欄位：`bcr`（讀取器）、`barcode`（條碼，可以多個，逗號分隔）、`errorCode`（錯誤代碼）、`scale`（磅秤）、`weight`（重量）、`maxWeight`、`minWeight`（重量上下限）。
   - 效果：開始讀取（`bcrReadStart`）、停止讀取（`bcrReadStop`）、讀到條碼（`bcrRead`）、讀取失敗（`bcrFailed`）、手動輸入（`bcrManual`）、磅秤讀值（`scaleRead`）、重量上下限（`weightLimits`，依棧板）。
   - 預設規則涵蓋 BCR 讀取器的紀錄與 PLC 的讀取逾時、手動輸入、磅秤回傳值；**重量上下限沒有預設規則**（介面 LOG 的欄位屬於上位系統，由使用者在本機規則中設定）。
3. **BCR 的狀態**：
   - 閒置：灰色。
   - 讀取中（開始讀取之後、還沒有回傳）：藍色掃描光束閃爍，標籤「讀取中 n 秒」（8c）；重複送出開始讀取時，從第一次開始計算。
   - 讀到條碼：綠色，標籤只寫簡短結果（9a）：棧板 BCR 寫條碼的末幾碼，桶 BCR 寫桶數；點元件後在元素狀態面板看完整內容。
   - 桶 BCR 讀到的條碼拆成多個桶（5a）：所屬 Conv 上目前只有一個棧板時，加入該棧板的桶清單（比照「棧板加入一個桶」，標示依據）；沒有或多於一個時只記錄在 BCR（Jev 0.64）。
   - 手動輸入：橘色，標「手動」（7a）；**手動輸入解除讀取失敗的異常**（11a）。
   - 讀取失敗或逾時：紅色，標籤寫錯誤代碼；**算異常，直到下一次讀到條碼或手動輸入**（3a、11a）。
   - 讀取中送出停止讀取但沒有回傳：回到閒置，保留上一次的結果，不算異常（12a）；逾時另有紀錄時才算異常。
   - 結果標籤顯示到同一台下一次讀取，註明幾秒前（Jev 0.68）。
4. **磅秤的狀態**：
   - 等待中（推估，10a）：從所屬 Conv 的棧板 BCR 開始讀取起，到收到磅秤值或該 Conv 讀取失敗為止（Jev 0.77）；LOG 沒有記錄磅秤要求，畫面標示「推估」。
   - 讀值：標籤顯示「512 kg」；單位視為 kg（6b，**假設**）。
   - 與重量上下限比對（4b）：以讀值當時所屬 Conv 上的棧板，取該棧板最近一次的上下限；超出範圍時紅色並算異常；上下限為 0 或空白時標「無上下限」，不算異常（Jev 0.77）。
5. **其他面板**：元素狀態面板列出完整條碼清單、重量、上下限與依據的事件；設備狀態表包含 BCR 與磅秤，「只看異常」包含讀取失敗與超重；時間軸的異常時段加上 BCR 讀取失敗（到下一次讀到或手動輸入）；BCR 與磅秤的標籤在 3D 一直顯示（不像其他設備只在點選時顯示名稱）。「異常紀錄」面板是工程師整理的經驗紀錄（ADR-0016），不自動加入。

## 理由

- 使用者要只看 Layout 就看得出狀態；BCR 與磅秤是獨立的實體設備，以元件擺在 Conv 旁，位置與狀態一目了然（Jev 0.80）。
- 標籤只放簡短結果，避免桶 BCR 的多個條碼蓋滿 Layout；完整內容放在元素狀態面板（9a）。
- 讀取中顯示秒數，可以直接看出是否接近逾時（8c）。
- LOG 沒有記錄磅秤要求，以入庫讀取的開始推估，並明確標示推估（ADR-0005 第 7 點：未知不當作已知）。
- 重量上下限的欄位屬於上位系統，意義與對應的資料未確認，因此不放預設規則，只提供效果。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| 不新增元件，在 Conv 上加徽章 | 一個 Conv 可能有多台讀取器與磅秤，徽章擠在一起不易分辨（Jev 0.06） |
| Conv 加「有 BCR／有磅秤」屬性 | 同上；也無法放別名（Jev 0.09） |
| 另開 BCR／磅秤表格面板 | 使用者要求從 Layout 回放就看得出來（第 1 題） |
| 讀取中只把狀態燈變黃 | 看不出已經等了多久（8c） |
| 標籤列出完整條碼 | 桶條碼多，蓋滿 Layout（9b，Jev 0.40） |
| 手動輸入不解除異常 | 使用者決定手動輸入視為讀取完成（11a；Jev 傾向不解除 0.75，信心度 0.50） |
| 停止讀取但沒有回傳視為失敗 | 逾時另有紀錄；使用者決定不算異常（12a；Jev 傾向視為失敗 0.61，信心度 0.42） |
| 只顯示重量、不比對上下限 | 使用者決定比對（4b） |
| 重量單位讓使用者設定 | 使用者決定以 kg 顯示（6b） |

## 尚存風險

| 風險 | 影響 | 因應 |
|---|---|---|
| 樣本中的重量上下限全為 0 | 超重判定無法以真實資料驗證；實務上可能一律顯示「無上下限」 | 列為待確認；以虛構資料的單元測試驗證比對邏輯 |
| 上下限對應到哪個棧板未確認 | 比對的對象可能錯誤 | 以棧板對應（假設）；待確認後再調整規則 |
| 磅秤單位未確認 | 顯示的 kg 可能不對 | 標示為假設 |
| 磅秤要求是推估 | 等待中的時段可能與實際不同 | 畫面標示「推估」 |
| 有 BCR 或磅秤的設定檔為格式版本 12 | 0.16.0 以前的程式打不開 | 發佈時一起更新 |
| BCR 的回傳與 PLC 的「收到回傳」可能重複記錄同一次讀取 | 預設規則只取讀取器的紀錄，避免重複 | 使用者自行加規則時要注意 |

## 後續驗證方式

- 以虛構資料的單元測試：各效果的狀態變化（讀取中、讀到、失敗、手動、停止沒有回傳）、Conv 對應、桶條碼加入棧板、磅秤等待中與上下限比對、格式版本 12、舊設定檔不受影響。
- 冒煙測試：Layout 編輯器可新增 BCR 與磅秤、指定所屬 Conv；既有冒煙測試通過。
- 使用者以實際 Layout 與案件試用。

## 待確認

1. 磅秤數值的單位。
2. PLC 設定資料中重量欄位的負值意義。
3. 重量上下限對應的資料，以及樣本中上下限皆為 0 的原因。
4. 桶 BCR 讀取器確實是讀桶的條碼。
