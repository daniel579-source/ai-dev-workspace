# ADR-0030：放入升級資料夾、重新啟動後升級（版本並存＋啟動程式）

- 日期：2026-11-27
- 狀態：**已接受**
- 確認者：repo owner（方案 B 與決策摘要 Q1～Q31，2026-11-27）
- 對應 ticket：#218
- 相關 ADR：ADR-0001（部署形態）、ADR-0007（用戶端技術、打包與更新）、ADR-0011（儲存與案件資料夾）、ADR-0017（WebView2 固定版本 Runtime）、ADR-0024（學習樣板）
- 取代：ADR-0001 第 4 點「新版放在內部共用資料夾，由工程師自行複製替換，不做自動更新」；ADR-0007 第 2 點「更新時整個資料夾替換」

## 背景

- 廠區內的電腦不能連網；新版要由客戶以郵件轉寄進廠區。版本可能無法馬上更新，甚至拖好幾個版本才更新。
- 使用者要求：把升級檔放到指定資料夾，重新啟動程式後自動更新。
- 現況（2026-11-27 量測）：發佈 zip 約 387 MB，解開 821 MB，其中 WebView2 固定版本 Runtime（ADR-0017）佔 679 MB；不含 Runtime 的程式壓縮後約 60 MB。
- 現況：廠別設定等 JSON 檔遇到較新的格式版本會拒絕並提示更新程式；案件資料庫 `schema_version` 不同時直接報錯「請重新建立案件並匯入」。案件資料夾保留原始 LOG（`raw\`、`sources\`）。
- 客戶郵件的附件上限與過濾規則**待確認**；設計以「上限約 25 MB、含 exe 的檔案可能被擋」為**假設**（Q1）。

## 決策

### 1. 資料夾結構（方案 B：版本並存＋啟動程式；Q3）

```
D:\LogTrace\Program\           ← 以啟動程式所在位置為準，建議放這裡
  LogTrace.exe                 ← 小型啟動程式，捷徑一直指向它
  updates\                     ← 放升級包
    rejected\                  ← 無法套用的升級包，附原因說明的文字檔
  app-<版本>\                  ← 每個版本一個資料夾
  runtimes\webview2-<版本>\    ← WebView2 Runtime，多個版本共用
```

- 版本資料夾**全部保留**，由使用者手動刪除（Q10，Jev 0.68，使用者確認）。
- WebView2 Runtime 放在 `runtimes\webview2-<版本>\`，多個程式版本共用，舊的 Runtime 全部保留（Q27，Jev 0.73）。
- 案件、廠別設定（`D:\LogTrace\Cases`、`Plants`）與程式設定、版面（`%LOCALAPPDATA%\LogTrace`）位置不變，所有版本共用。

### 2. 升級包（Q2、Q4、Q8、Q9、Q19、Q22）

- 分成**程式包**（完整的程式、不含 WebView2）與 **Runtime 包**（只有 Runtime 版本變更時才寄）（Q2，Jev 0.94）。
- 程式包是**完整包**，從任何舊版都能直接升級，不使用差異包（Jev 1.00）。
- 程式包內有**版本資訊檔**：版本號、需要的 Runtime 版本、必要檔案清單；並附新版啟動程式與該版的更新說明。
- **不做來源驗證**（不簽章、不附雜湊）：自行撰寫的輔助程式，使用者決定不需要（Q4）。
- **分割與合併**由開發者與工程師自己以 7-Zip 處理，分割大小在寄送前決定；啟動程式只認完整的升級包（Q8、Q19）。
- **郵件過濾不特別處理**，被擋時改用其他管道（Q9，使用者選 c）。
- 新增 `CHANGELOG.md`，每版記錄；打包時把該版說明放進程式包（Q22，Jev 0.88）。

### 3. 套用流程（啟動程式開啟時）

1. 掃描 `updates\`。
2. **檢查結構完整**：壓縮檔 CRC、版本資訊檔、必要檔案清單；不完整就不套用（Q15，Jev 0.87）。
3. **檢查磁碟剩餘空間**，不足時不解開並提示需要多少空間（Q30，使用者決定）。
4. **詢問使用者**：顯示目前版本、新版本與**新版本那一版**的更新說明，按確認才套用，可以選「稍後」（Q5、Q22）。Runtime 包也要詢問（Q29，Jev 0.17 不贊成免詢問）。
5. 解開到新的版本資料夾，改成預設啟動的版本，再啟動它。
6. 套用成功**刪除升級包**；失敗或無法使用的移到 `updates\rejected\`，附原因說明的文字檔（Q20，使用者選 a）。
7. **程式包需要的 Runtime 還沒到**：不套用，繼續用目前版本啟動，提示需要哪一個 Runtime 包；程式包留在 `updates\`，Runtime 到了再套用（Q28，Jev 0.69）。
8. **版本不比已安裝最新版新的升級包**：這個版本的資料夾還不存在時照樣解開，但**不**改成預設啟動的版本（Q21，Jev 0.68）。
9. **啟動程式本身的更新**：程式包附新版啟動程式，由新版主程式在啟動程式結束後替換（Q12）。

### 4. 啟動程式的技術（Q31，使用者決定）

- **C# + Native AOT**，編譯成單一原生 exe（約數 MB），不需要 .NET 執行環境。
- 只做掃描、檢查、確認、解開、切換與啟動；不放業務邏輯。避免使用不相容 Native AOT 的寫法（例如依賴反射的序列化），JSON 使用 source generator。
- 解開 zip 使用 .NET 內建的 `System.IO.Compression`（ADR-0012 第 2 點）。

### 5. 退回舊版（Q11、Q26）

- 不做特別的介面：需要時由使用者自己進版本資料夾執行舊版（Q11，Jev 0.92）。
- 所有版本共用的**面板版面檔**舊版讀不了時，舊版改用預設版面，**不覆寫原檔**（Q26，Jev 0.65）。
- JSON 檔維持現行：遇到較新的格式版本就拒絕並提示更新程式。

### 6. 案件資料庫格式改變時（Q6、Q16、Q17、Q18、Q23、Q24、Q25）

- **開啟該案件時**才提示（Q23，Jev 0.88），使用者同意後：
  1. 自動**備份**舊資料庫到案件資料夾外的集中位置，例如 `D:\LogTrace\Backups\<案件名稱>\`（Q24，Jev 0.70）；每個案件只保留**最近一份**（Q18）。
  2. 依案件內保留的**原始 LOG 自動重建**（Q6，使用者決定）。
- 重建時**保留**案件名稱、時間偏移量、建立時的廠別設定快照、匯入紀錄、檔案紀錄、稽核紀錄；**以建立時的快照**重新解析事件；**不重複**累積到學習樣板（ADR-0024 的 `.flows.json`）（Q16，使用者三點都接受）。
- **重建失敗或中途取消**：不自動還原，保留備份並顯示錯誤，案件標示「需要重建」，下次開啟時再試（Q25，使用者決定）。
- 重建過的案件在舊版顯示「版本不符」；需要時由使用者手動還原備份（Q17，Jev 0.72）。
- 這一點補足 ADR-0001 第 4 點「新版必須能讀取舊版產生的資料」在案件資料庫上的落差。

### 7. 轉移到新機制（Q7）

- 第一個含啟動程式的版本，以含 Runtime 的完整 zip **手動安裝一次**（解到 `D:\LogTrace\Program\`），之後走升級資料夾（Jev 0.90）。
- `scripts/package.ps1` 改為產生三種輸出：完整 zip（首次安裝）、程式包、Runtime 包。

### 8. 實作確認（2026-11-27，#218）

使用者裁決（Jev 信心度偏低的項目）：1a、2a、3a、4b、5a、6a、7b。

- **確認畫面**：Win32 MessageBox（1a；Jev 0.35），「是」＝套用、「否」＝稍後；更新說明超過 1200 字時截斷並註明完整內容在 `CHANGELOG.md`。
- **進度**：解開時另外顯示只有說明文字與進度列的 Win32 視窗，不能關閉（4b；與 1a 並存）。
- **預設版本**記在 `Program\launcher.json`；不見或指向不完整的版本時改用最新且完整的版本（Jev 0.80）。版本資料夾與 Runtime 資料夾解開完成後才寫入 `installed.json`，沒有的視為不完整。
- **辨識升級包**：只看 `updates\` 下的 `.zip`，讀根目錄的 `update.json`（kind、version、runtimeVersion、files、notes），不靠檔名（Jev 0.66）。程式包內容在 `app\`，Runtime 包在 `runtime\`。
- **CRC**：解開時逐一核對，不符就刪除解開一半的 `<目的>.partial` 並移到 `rejected\`；不安全的路徑整包拒絕。磁碟空間需要「解開後大小＋200 MB」。
- **案件重建**：在 `case.db.rebuilding` 建立新的資料庫，複製 meta、imports、files、audit 中兩邊都有的欄位，再以 `CaseImporter.Rebuild` 重新解析；成功後才取代 `case.db`，失敗或中途中斷時 `case.db` 完全不動（2a）。格式較舊的案件在清單中標示「（需要重建）」（3a）。備份位置為案件存放位置的上一層下的 `Backups\`（預設 `D:\LogTrace\Backups\`）。
- **WebView2 Runtime**：主程式先找自己資料夾的 `WebView2Runtime\`，再找 `..\runtimes\webview2-<版本>\`；版本由建置時寫入組件中繼資料（5a）。
- **版面**：結束時在版面檔旁寫 `.version`（寫入的程式版本）；讀不了而且寫入版本比自己新時，結束時不儲存（6a）。舊版沒有 `.version` 的版面不受影響。
- **啟動程式替換**：啟動時若預設版本的 `app-<版本>\launcher\LogTrace.exe` 與自己內容不同，把自己改名成 `LogTrace.old.exe` 再複製新版，下次啟動生效並刪除舊檔（7b）。
- **Native AOT** 啟動程式約 3.1 MB；打包需要 Visual Studio 的 C++ 工具，`package.ps1` 在 `vswhere.exe` 不在 PATH 時自動加上。
- **.NET 弱點**：AOT 編譯時發現 SDK 10.0.402 附帶的執行環境 10.0.13 有 CVE-2026-111497（GHSA-p3jp-9v83-76w9，高嚴重性，10.0.14 修正）；0.19.0 以前發佈的主程式（self-contained）也帶 10.0.13。使用者決定升級開發電腦的 SDK 到 10.0.404（執行環境 10.0.15，2026-11-27），之後發佈的主程式與啟動程式都使用 10.0.15。
- 開發電腦以虛構升級包實測：0.19.0 完整包 → 放入 0.20.0 程式包 → 確認畫面 → 進度視窗 → 從 `app-0.20.0\` 啟動、`launcher.json` 更新、升級包刪除、啟動程式替換；第二次啟動不詢問並刪除 `LogTrace.old.exe`。輸出大小：完整包 372 MB、程式包 64 MB、Runtime 包 306 MB。

## 理由

- 版本並存不覆蓋執行中的檔案，避開檔案被鎖住的問題；新版有問題時舊版仍在，可以直接退回（方案 B，Jev 0.86）。
- 完整包讓跳過任意多版都能一次升級；差異包要依序套用，漏一包就壞。
- WebView2 Runtime 佔 8 成以上、版本很少變，拆出後程式包約 60 MB，郵件分割 3～4 份即可。
- 先詢問再套用，使用者知道什麼時候換了版本、換了什麼。
- 舊案件以原始 LOG 重建，跳版升級後仍能開啟，不必請使用者重建案件。
- Native AOT 與主程式同一種語言、單一小 exe、不需要執行環境。

## 考慮過的替代方案與捨棄原因

| 方案 | 捨棄原因 |
|---|---|
| A：在程式資料夾內直接覆蓋，搭配 updater | 執行中的檔案被鎖住；失敗時新舊混雜、無法退回（Jev 0.01） |
| C：維持手動整個資料夾替換 | 使用者要求放入資料夾、重新啟動就升級（Jev 0.13） |
| 每次寄含 WebView2 的完整 387 MB 包 | 郵件寄不出去（Jev 0.03） |
| 差異包 | 跳版時要依序套用，漏一包就壞（Jev 0.00） |
| 以自己的金鑰簽章或附 SHA-256 | 使用者決定自用輔助程式不需要來源驗證（Q4） |
| 不詢問直接套用 | 使用者不知道換了版本（Q5） |
| 程式根資料夾固定在 `%LOCALAPPDATA%` | 使用者選 D 槽，與案件一起備份（Q3） |
| 啟動程式自動合併分割檔 | Jev 不贊成（0.26），使用者決定自己以 7-Zip 處理 |
| 7z 加密檔名或改副檔名避開郵件過濾 | 使用者決定不處理，被擋改走其他管道（Q9） |
| 只保留 2～3 個版本 | Jev 傾向全部保留（0.68），使用者確認 |
| 啟動時按住 Shift 或選單選擇舊版 | Jev 傾向手動進資料夾（0.92） |
| 套用成功後保留升級包到 `applied\` | Jev 不贊成（0.14），使用者選刪除（Q20） |
| 確認畫面列出跳過的所有版本說明 | Jev 不贊成（0.05）；中間版本的變更看不到，列為已接受的風險 |
| 升級後一次重建所有案件 | 案件多時啟動很久（Jev 0.06） |
| 舊案件維持報錯、請使用者重建 | 使用者決定自動備份並重建（Q6） |
| 備份放在案件資料夾內 | 案件資料夾變大；Jev 傾向放外面（0.70） |
| 重建失敗時自動還原舊資料庫 | Jev 不贊成（0.18），使用者選標示「需要重建」 |
| 舊版自動改用符合版本的備份 | Jev 傾向手動還原（0.86） |
| 每個版本各帶一份 Runtime、或只保留最新 Runtime | 浪費空間，或退回舊版時沒有對應的 Runtime |
| 只有 Runtime 包時免詢問 | Jev 不贊成（0.17） |
| 啟動程式以 C++／Win32 撰寫 | 另一種語言，維護成本高（Q31） |
| 啟動程式以 PowerShell 或批次檔撰寫 | 確認畫面與錯誤處理粗糙，容易被執行原則擋下（Q31） |
| 啟動程式以 self-contained .NET 發佈 | 單是執行環境就約 70 MB |
| 現成的更新框架（例如 Velopack） | 偏向安裝模式，與免安裝不合；未深入評估 |

## 尚存風險

| 風險 | 影響 | 因應與後續驗證 |
|---|---|---|
| 客戶郵件的附件上限、是否擋 exe 未知（**待確認**） | 升級包寄不進廠區 | 分割大小寄送前決定；被擋時改用其他管道；第一次實際寄送時記錄結果 |
| 公司防毒或應用程式白名單擋下啟動程式執行剛解開的 exe（**待確認**） | 升級後無法啟動 | 向 IT 確認；在現場筆電實機確認 |
| 不做來源驗證 | 轉寄途中被換掉的升級包偵測不到 | 已接受（自用輔助程式）；結構檢查只防損壞與缺檔 |
| 跳版時只顯示最新那一版的說明 | 使用者不知道中間版本的變更 | 已接受；`CHANGELOG.md` 隨程式提供，可以自行查看 |
| 版本資料夾全部保留 | 每版約 142 MB，磁碟用量增加 | 使用者手動刪除；套用前檢查磁碟空間 |
| 重建案件需要原始 LOG | 原始 LOG 被刪除或損壞時無法重建 | 重建失敗時保留備份、標示「需要重建」（第 6 點） |
| 重建後與原本的結果不同 | 回放結論改變 | 以建立時的快照解析；以虛構資料測試重建前後事件相同 |
| 新版寫入的資料舊版讀不了 | 退回舊版後部分資料打不開 | JSON 拒絕較新格式；版面改用預設；案件以備份手動還原 |
| Native AOT 的限制 | 部分 .NET 功能不能用 | 啟動程式保持很小；建置時把 AOT 警告當成錯誤 |

## 後續驗證方式

- 以虛構資料測試：從舊版（例如 0.19.0）直接跳到最新版；Runtime 缺少時保留程式包；版本較舊的升級包只解開不切換；結構不完整、空間不足時不套用並移到 `rejected\`。
- 準備各版本產生的舊資料（案件、廠別設定、版面）當作測試資料，確認跳版升級後讀得到。
- 案件重建前後事件、時間偏移量、匯入紀錄相同；學習樣板不重複累積；重建失敗時標示「需要重建」。
- 在乾淨、離線的 Windows 10 與現場筆電實機確認：首次手動安裝、放入升級包後重新啟動完成升級、啟動程式替換。
- 第一次實際經客戶轉寄時，記錄附件大小與是否被擋。

## 影響範圍

- **ADR-0001 第 4 點**、**ADR-0007 第 2 點**：由本 ADR 取代。
- **ADR-0011**：新增集中備份資料夾 `D:\LogTrace\Backups\`；案件資料庫格式改變時以原始 LOG 重建。
- **打包**：`scripts/package.ps1` 產生完整 zip、程式包、Runtime 包；新增 `CHANGELOG.md`。
- **使用說明**：首次安裝、放入升級包、退回舊版、還原案件備份。
