# LogTrace 使用說明

LogTrace 是自動化倉儲設備的 LOG 回溯工具：把 EXE、PLC、Server 三個模組的 LOG 匯入「案件」，整合到同一條時間軸上搜尋與回放。本說明中的編號、站點、時間等都是**範例／虛構**。

## 1. 系統需求與安裝

- Windows 10 或 Windows 11（64 位元）。**免安裝**，不需要 .NET 或其他元件，也**不需要網路**。
- 安裝：把 zip 解壓到任一資料夾（例如 `D:\Tools\LogTrace`），執行其中的 `LogTrace.exe`。
- 更新：關閉 LogTrace，刪除舊的程式資料夾，再解壓新版。案件與設定放在另外的位置（第 2 節），不受影響。
- 解除安裝：刪除程式資料夾。案件與設定要另外刪除（第 2 節）。
- 程式不需要登入，使用目前登入 Windows 的帳號；稽核紀錄記錄的操作人就是這個帳號。

## 2. 資料存放位置

案件與廠別設定檔預設放在 **`D:\LogTrace`**；程式設定與版面放在個人的本機資料夾 `%LOCALAPPDATA%\LogTrace`（在檔案總管的網址列輸入這串文字即可開啟）：

| 位置 | 內容 |
|---|---|
| `D:\LogTrace\Cases\` | 案件資料夾（每個案件一個） |
| `D:\LogTrace\Plants\` | 廠別設定檔（每個廠別一個 `.json`）；知識庫檔（`<設定檔名>.kb.csv`）與異常紀錄資料夾（`<設定檔名>.incidents\`），第 7 節 |
| `audit-log.jsonl`（在案件存放位置下） | 建立與刪除案件的紀錄 |
| `%LOCALAPPDATA%\LogTrace\settings.json` | 程式設定：案件與廠別設定的存放位置、最近使用的案件、最近 20 次搜尋 |
| `%LOCALAPPDATA%\LogTrace\layout.xml` | 畫面版面配置（依使用者保存） |

- 案件與廠別設定的存放位置都可以在「案件」面板按「變更…」修改；已有的資料不會搬移。
- 存放位置所在的磁碟不存在（例如沒有 D 槽）時會顯示提示，請改到其他位置。
- 存放位置在 OneDrive 同步資料夾內時會顯示警告：案件含有真實 LOG，不要同步到雲端。
- **從舊版更新時**：舊版把案件與廠別設定放在 `%LOCALAPPDATA%\LogTrace`。第一次啟動新版時，如果舊位置還有資料，程式會詢問是否搬到 D 槽：
  - 選「是」：每個檔案複製並核對內容後，才刪除舊位置的資料；新位置已有同名的項目時不覆蓋，留在舊位置並在狀態列說明。
  - 選「否」：繼續使用舊位置，之後不再詢問；可以隨時按「變更…」改位置。

## 3. 快速開始

1. **（第一次）建立廠別設定**：按右上角「Layout 編輯器…」，建立新的廠別設定，放置站點、料架、搬送機、對接設備、防火門，替它們加上 LOG 中使用的編號作為別名，存檔。沒有廠別設定時，也可以選「內建預設（不含 Layout）」，只是沒有 Layout 回放。
2. **建立案件**：在畫面頂端輸入案件名稱、選擇廠別，按「建立案件」。
   - 「廠別」預設選上次建立案件時用的廠別；沒有記錄或該設定檔已不存在時，選第一個廠別設定；沒有任何廠別設定時才選「內建預設」。
   - 有廠別設定、卻選「內建預設」建立案件時，會先詢問。內建預設的案件沒有 Layout，回放無法顯示站點與設備；選「否」不建立案件，可以改選廠別。
3. **匯入 LOG**：在「匯入 LOG」輸入或選擇資料夾、7z 或 zip，按「匯入」。結構要是「日期資料夾 → 模組資料夾 → LOG 檔」，例如 `20300107\PLC-2030-01-07\PLCLOG.txt`；可以一次匯入多天。
   - 原始檔會複製進案件並記錄雜湊；倉儲電腦上的原始 LOG 不會被修改。
   - 重複匯入時：內容相同的檔案自動略過；舊檔是新檔的開頭時自動改用新檔；內容衝突時由你逐檔選擇，舊檔一定保留。
4. 匯入完成後即可瀏覽與回放。全文索引在背景建立（搜尋面板下方顯示進度），建立期間可以照常搜尋。

**需要等待時**：匯入、開啟案件、搜尋、修改時間偏移量、套用新版廠別設定等工作進行中，狀態列會顯示會動的進度條與「已經過 N 秒」，滑鼠游標旁也會出現忙碌圖示。資料量大時（例如搜尋符合十幾萬筆），更新事件清單與畫面可能要幾分鐘，這段期間主視窗無法操作，Windows 可能在標題列顯示「沒有回應」；這時畫面中央會出現「LogTrace 正在處理中」視窗，顯示經過的秒數，完成後自動關閉。程式沒有當機，請不要強制結束。

## 4. 事件清單與旗標

- 所有模組的事件依時間排序；時間精度到 0.0001 秒。
- **混合檢視**以底色區分模組；**分軌檢視**每個模組一欄。
- 旗標（滑鼠移到圖示上可以看到說明）：

| 圖示 | 意義 |
|---|---|
| ＝ 同時間戳記 | 有其他事件時間完全相同；清單中的先後只為了排序穩定，不代表因果 |
| ↶ 時間倒退 | 比同一 LOG 的前一筆早；原始位置見「原始 LOG」面板 |
| ⌀ 時間無效 | 時間戳記無法解讀，時間沿用前一筆 |
| ？ 未知種類 | 不在廠別設定的已知 LOG 種類中；內容照樣保存 |
| � 編碼錯誤 | 有無法解碼的位元組 |
| ± 已校正 | 這個模組設定了時間偏移量（第 8 節） |

- 選一筆事件，「詳細資訊」顯示來源檔案與行號、原始時間、解析欄位與完整內容；「原始 LOG」面板依原始行序顯示該檔案並標出該行。

## 5. 搜尋

在左側「搜尋」分頁輸入條件，按「搜尋」（或 Enter）。修改條件後要再按一次才會重新查詢。

- 三個輸入框：**全部包含**、**任一包含**、**不包含**；關鍵字以空白分隔，包含空白的片語用雙引號，例如 `"door open"`。
- 預設不分大小寫、全形與半形視為相同、部分比對（搜 `Unload` 會找到 `Station_Storage_Unload`），也會比對多行事件的延續行。
- **正規表示式（進階）**：勾選後，每個關鍵字都是正規表示式，例如 `CMD_NO=0001\d{4}`。語法有誤時會提示；搜尋時顯示進度，可以按「取消」。
- **篩選條件**：時間區間、模組、Logger、等級、旗標、Layout 元素（比對它的所有別名）、命令、棧板、桶編號。
- 結果可以「只顯示符合的」或「顯示全部並標示符合的」；以 Ctrl＋← ／ → 在符合的事件間移動。時間軸總覽上以黃色標出符合的位置。
- 電話號碼會遮罩顯示；可以用電話號碼搜尋，在詳細資訊中點一下才顯示完整號碼。
- 搜尋結果的說明會寫出使用的方式（全文索引或掃描）。全文索引可以按「重建全文索引」刪除後重建，結果不受影響。

## 6. 回放

所有面板共用一個「**目前時刻**」：在任何一處移動，其他面板都會同步。

| 操作 | 作用 |
|---|---|
| → ／ ← | 下一個／上一個狀態變化 |
| Shift＋→ ／ ← | 下一筆／上一筆事件 |
| Ctrl＋→ ／ ← | 下一筆／上一筆符合搜尋的事件 |
| 空白鍵 | 播放／暫停（×1～×60，可略過 10 秒以上沒有狀態變化的時段） |
| Home ／ End | 案件開頭／結尾 |
| 點時間軸 | 跳到該時刻 |

- **Layout 回放**：顏色代表狀態（未知為灰色，第一次在 LOG 中確定後才改為已知）；站點右上角的指示燈是在席訊號（ON／OFF／未知）；⚠ 表示命令與在席訊號不一致（系統不判斷誰對）。站點左下角的紫色小字是運轉狀態不是「自動」時的標記（例如「手」），運轉狀態照 LOG 的文字顯示；運轉狀態為異常不會讓站點變成「異常中」，異常中只看警報。點元素在「元素狀態」中看到詳細狀態與造成它的事件；點料架的一格看到該列的側視圖：每一層顯示棧板編號、「空」（LOG 記載已取出）或「—」（還沒有與這個儲位有關的 LOG，不代表是空的），點「造成這個狀態的事件」可以跳到那筆事件。儲位一律以 LOG 為準：派送的目的地是儲位時，這一段抵達或作業完成就算放入；派送的來源是儲位時，派送後該儲位變成空。按「只看這個元素」，事件清單只剩與它相關的事件。畫布依元素範圍調整大小，可以用 Ctrl＋滑鼠滾輪或「符合視窗」縮放。
- **沒有 LOG 的時段**：時間軸總覽上方每個模組一列（左端色塊代表模組），灰色斜線表示這個模組在這段時間沒有任何 LOG；滑鼠移上去顯示模組、起訖與長度。預設超過 5 分鐘沒有事件就標示，案件開頭與結尾也算。這只表示「沒有 LOG」，可能是設備閒置，也可能是 LOG 缺漏，請自行判斷。目前時刻落在其中時，「Layout 回放」上方與詳細資訊顯示「目前時刻 模組 X 沒有 LOG（…）」：這段時間在 Layout 上看不到該模組的變化，不代表沒有發生。門檻可以在廠別設定中依模組調整（第 7 節）。
- **命令**：每個命令目前的狀態與到案件結束時的狀態；選一個命令列出串起來的事件，點一筆跳到該時刻。
- **樓層**：Layout 有兩層以上時，上方會出現樓層列，可以切換樓層、勾「並排」把各層排在一起（可再勾「垂直排列」，低樓層在下）。勾「跟隨切換樓層」後，點設備狀態表的一列、選取命令（選取目前執行它的搬送機）或選取事件時，會切到相關元素所在的樓層；並排時不切換。預設不跟隨；這些設定會記住。設備狀態表與元素狀態都會標出樓層。點設備狀態表的一列，會選取 Layout 上的那個元素。
- **電梯**：每個服務的樓層都畫出電梯，顯示執行中或閒置、載著的棧板與目前樓層。派給電梯後顯示「移動中：1F → 2F」並加虛線框（推估）；抵達後目前樓層是抵達站點的樓層（依 LOG）。第一次抵達前目前樓層未知時，依派送的來源站點推估；作業完成或取消時停在出發的樓層。點電梯可以看到目前樓層的依據。設備狀態表也列出電梯，「樓層」欄是目前樓層。開啟「跟隨切換樓層」時，選取電梯會切到它目前所在的樓層。
- **搬送機沿導軌移動**：在 Layout 編輯器替搬送機指定導軌後，回放時搬送機會在導軌上移動。LOG 沒有搬送機的位置，所以位置是這樣決定的：
  - 第一次派送之前，畫在 Layout 上放的位置（位置未取得資訊）。
  - 派送到抵達之間，依經過的時間比例畫在起點與目的地之間，加上**虛線框**表示「推估」，不是實際位置；中途停下或速度變化都看不出來。播放時會連續移動。
  - 起點是派送紀錄的來源（沒有時用上一次抵達的位置）；目的地投影到導軌上最近的點，儲位取那一列的中心。閉合的導軌依畫點的順序方向前進（實際方向**待確認**，請依現場方向畫點）。
  - 抵達後畫在目的地在導軌上的位置（依 LOG）。沒有抵達、取消或作業完成（LOG 沒有地點）時，停在起點。
  - 點搬送機可以在元素狀態看到「位置」的依據，以及派送、抵達的事件。沒有指定導軌的搬送機維持固定位置。
- **防火門**：綠色是開、紅色是關。還沒有 LOG 事件時，顯示 Layout 編輯器設定的「平時狀態」，加上虛線框表示「推估」；沒有設定時是灰色（未取得資訊）。門關著時，穿過它的輸送線畫成紅色（推估時為紅色虛線）。門關著時，如果貨物在這些輸送線的兩端之間移動，在那一筆事件的門上顯示 ⚠ 不一致（系統不判斷誰對），下一筆事件就不再顯示。防火門的 LOG 樣式**待確認**，需要在廠別設定的解析規則中，以「防火門開」「防火門關」兩種效果填寫。
- **設備狀態表**：所有站點、搬送機、對接設備、防火門在目前時刻的狀態，可排序、可以只看「異常中或不一致」。
- **未對應**：目前時刻前後 30 秒內出現、但 Layout 還沒對應的編號；可以到 Layout 編輯器把它拖到元素上成為別名。

## 7. 廠別設定與 Layout 編輯器

- 一個廠別一個設定檔（JSON），包含 Layout、模組順序、已知 LOG 種類、編碼、解析規則、遮罩規則與時區。分享時直接複製檔案。
- 編輯器：左邊工具箱、中間畫布（拖曳移動、拖曳角落調整大小，吸附 0.5 公尺格線）、右邊屬性；下方「載入案件比對」列出 LOG 中出現但還沒對應的編號。
- 元素清單與輸送線的起點、終點選單：每一項前面顯示類型，同類型的放在一起（依工具箱的順序），同類型內依名稱排序，名稱中的數字依數值比較（例如 A-4 在 A-12 之前）；名稱空白的排在同類型最前面。只影響清單的顯示，不改變畫布的上下層與存檔順序。
- 輸送線：表示站點、對接設備或搬送機之間的貨物流向，在屬性面板選起點、終點，勾「雙向」表示雙向（畫面不畫箭頭）。連到搬送機時，線畫到搬送機邊緣的「交接點」（橘點），拖曳橘點調整；搬送機移動時交接點不動。
- **樓層**：畫布上方的樓層列可以切換樓層，也可以新增、改名、上移（往較高的樓層）、下移、刪除樓層。
  - 舊的設定檔沒有樓層，開啟後所有元素都在「1F」。
  - 新增的元素放在目前樓層。要移到其他樓層，用屬性面板的「樓層」選單；選取多個元素時，用「移到樓層」一起移。
  - 樓層改名時，元素跟著改。名稱不可空白、不可重複（大小寫視為相同）。還有元素的樓層不能刪除，至少要保留一層。
  - 單層檢視只畫目前樓層的元素，切換樓層時，看不到的元素會取消選取。
  - 勾「並排」把所有樓層排在同一張畫布上，可以和單層一樣編輯；勾「垂直排列」改成上下排列，低樓層在下。點一層的空白處，那一層就是目前樓層（藍框）。把元素拖到另一層放開，它就改到那一層。貼上時貼到滑鼠所在的樓層。
  - 輸送線的兩端必須在同一層，跨樓層的搬送之後由電梯處理。防火門的「依位置帶入」只看同一層的輸送線。
  - 單層／並排與排列方向會記住，下次開啟時沿用。
  - 較舊版的 LogTrace 也能開啟有多層的設定檔，但會把所有樓層的元素畫在一起。
- **電梯**：在樓層之間搬送貨物的設備，和搬送機是不同的元素（有自己的 LOG）。
  - 新增時預設服務所有樓層；在屬性面板的「服務的樓層」勾選或取消（至少兩層）。電梯在每個服務的樓層、同一個位置畫出來，任何一層都可以拖曳或調整大小，所有樓層一起變；並排時拖到別層不會換樓層。
  - 每層的出入口請放一般的站點；輸送線不能接到電梯。樓層改名時電梯跟著改；電梯服務的樓層不能刪除，要先取消勾選。
  - 可以加別名（LOG 中電梯的編號）。電梯的 LOG 樣式**待確認**，解析規則中以「命令的一段派給電梯」「電梯抵達目的地」「電梯作業完成」三種效果與「電梯」欄位填寫。
  - 有電梯的設定檔，較舊版的 LogTrace 無法開啟。
- **導軌**：搬送機行走的軌道，只畫出來，不和 LOG 對應。
  - 工具箱的「導軌」建立 20 公尺的直線；「導軌（跑道形）」建立兩條 20 公尺直線、相距 6 公尺、兩端各一個半圓的環。建立後都可以自由修改。
  - 選取導軌時會出現把手：方形把手是點，拖曳移動那一點；圓形把手是每一段的中點，拖曳時把直線彎成弧線，最多到半圓。兩者都吸附 0.5 公尺。
  - 插入點：選一段（點圓形把手，或在屬性面板的「段」選單選）後按「插入點」，插在那一段的中點；或在導軌上雙擊，插在雙擊處。
  - 屬性面板另有「刪除點」（至少保留 2 點）、「這段改直線」、「閉合（頭尾相接）」、「轉 90°」。拖曳線條整條移動；框選時碰到導軌就算選到。
  - 搬送機的屬性面板有「導軌」選單，只列同一層的導軌，按 × 清除。刪除導軌時，指定它的搬送機會自動清除指定（可以 Ctrl+Z 復原）；複製貼上的搬送機不帶導軌指定。
  - 有導軌的設定檔，較舊版的 LogTrace 無法開啟。
- 防火門：在屬性面板設定「平時狀態」（不設定、開、關），以及「穿過這扇門的輸送線」：從下拉選單選一條按「加入」，或按「依位置帶入」，把線段碰到門範圍的輸送線全部加入；按 × 移除。刪除輸送線時，也會從門的關聯中移除。貼上防火門時，一起貼上的輸送線改成新的輸送線，其他的照舊關聯原本的輸送線。防火門也可以加別名（LOG 中的編號）。有防火門的設定檔，較舊版的 LogTrace 無法開啟。
- 畫布大小依元素範圍自動調整：所有元素的範圍再加 20 公尺的空白，最小 60 × 40 公尺；把元素拖到靠近邊緣時畫布跟著變大。畫布大小不寫進設定檔。
- 縮放：Ctrl＋滑鼠滾輪（10%～400%），或按畫布上方的「符合視窗」「100%」。縮放只改變顯示，吸附仍為 0.5 公尺。
- 選取與編輯：
  - 在畫布空白處拖曳可以框選，框碰到的元素（含輸送線）就算選到；Ctrl＋點選加選或取消選取。選取多個時拖曳會一起移動；屬性面板只在選取一個元素時顯示。
  - **Del** 刪除所有選取的元素，連到它們的輸送線一起刪除。
  - **Ctrl+C／Ctrl+V** 複製貼上（只在編輯器內部）：貼上的元素有新的編號（id），名稱、尺寸、旋轉、自訂屬性與別名照抄；別名重複時存檔前會提示，請修改其中一個。滑鼠在畫布上時，以滑鼠位置當作整組的左上角；不在畫布上時，放在原位置往右下 1 公尺。連到被複製元素的輸送線一起複製：兩端都被複製時連到新元素，只有一端時另一端連回原本的元素。
  - **Ctrl+Z** 復原新增、刪除、移動、調整大小、貼上與元素屬性的修改，最多 50 步；同一個欄位連續輸入算一步。「LOG 設定」分頁的設定不在復原範圍內。存檔或關閉編輯器後不能再復原。
  - 在文字框中輸入時，這些按鍵維持文字編輯的作用。
- **沒有 LOG 的門檻**（「LOG 設定」分頁）：從下拉選單選擇模組（選項就是「模組順序」中的模組），設定秒數，超過這麼久沒有事件時，時間軸標示沒有 LOG 的時段（第 6 節）。沒有列出的模組為 300 秒；0 表示不標示。有心跳的模組可以設小一點（例如心跳間隔的 2～4 倍），有事情才寫 LOG 的模組可以設大一點或設 0。門檻的模組不在模組順序中時無法存檔；比對只看模組名稱，填 Logger 名稱或 Layout 元件名稱不會生效。
- 存檔時檢查別名重複等問題，有問題時不會存檔。每次存檔修訂號加 1。
- 案件保存建立時所用設定的快照。設定檔有新版時，開啟案件會提示是否套用；套用後依新的設定重新解析事件。

### 知識庫

- 每個廠別可以有一個知識庫檔，放在廠別設定檔旁邊，檔名是設定檔名加 `.kb.csv`，例如 `F18.json` 的知識庫是 `F18.kb.csv`。沒有這個檔案時，其他功能照常使用。
- 用 Excel 整理即可：第一列是標題 `代碼,說明,處置,出處`（順序不拘，多出的欄位不使用），「代碼」「說明」必填；出處寫文件名稱與頁碼或章節。另存為「CSV UTF-8」或「CSV」（Big5）都可以。同一代碼可以有多列（例如不同設備的意義不同），全部會顯示。
- **詳細資訊**：事件有「警報代碼」解析欄位時，顯示知識庫中這個代碼的說明、處置與出處；沒有這個代碼時明確寫「知識庫中沒有這個代碼」。代碼不分大小寫、全形與半形相同。警報代碼要由廠別設定的解析規則抽出（具名群組 `alarmCode`）。
- **「知識庫」面板**：列出知識庫的內容，可以用關鍵字搜尋代碼、說明、處置、出處（空白分隔，每個都要包含）。修改知識庫檔後按「重新載入」。格式有誤的列不使用，面板會列出行號與原因。
- 知識庫是參考資料：不存入案件，也不記入稽核；開啟舊案件時看到的是目前的知識庫內容。

### 異常紀錄

處理完的異常整理成「異常紀錄」，經工程師審核後成為知識庫的經驗（ADR-0016）。目前由工程師手動建立；AI 產生草稿、匯入過去的維修紀錄、相似異常查詢之後再加入。

- **存放**：廠別設定檔旁邊的資料夾，名稱是設定檔名加 `.incidents`，例如 `F18.json` 的異常紀錄在 `F18.incidents\`；每筆一個 JSON 檔，檔名是紀錄編號（`IR-年月日-時分秒-亂碼`）。找不到案件所用廠別的設定檔時無法使用。
- **使用者**：面板上方的「使用者」是建立時的撰寫者、審核時的審核者，預設為 Windows 使用者名稱。目前不限制誰可以審核；撰寫者與審核者同一人時只提醒。
- **建立**：「從目前案件建立」帶入廠別、案件名稱與事件清單中選取的事件；「整理維修紀錄」用來手動輸入過去維修紀錄的原文。新紀錄是「草稿」，列在「待審核」分頁。
- **相關事件**：「加入選取的事件」把事件清單中選取的事件加入紀錄，保存時間、模組與**遮罩後**的訊息（不論畫面是否顯示敏感資訊），並帶入事件的警報代碼與設備編號、發生時間；可以再修改。「跳到事件」只在紀錄引用的案件就是目前開啟的案件時可以使用；其他電腦或已刪除的案件，仍可閱讀紀錄中保存的內容。
- **AI 推測**：現象、原因、處置各有「AI 推測」勾選框；仍勾選時不能審核通過，取消勾選表示已確認。
- **審核通過**：成為新的一版。下列情況不能通過：現象、原因、處置、結果有空白；現象、原因、處置仍是 AI 推測；從案件建立卻沒有相關事件；沒有填使用者。下列情況只提醒（確認後仍可通過）：執行者空白、維修紀錄沒有事件、撰寫者與審核者同一人、和上一版相比沒有修改。
- **查詢**：只列目前有效的版本，不列草稿與停用。最新一版改過的欄位在查詢結果與詳細資訊中以 ★ 醒目標示；每一版的審核者、日期與每個欄位「舊 → 新」在「修訂經過」。
- **修訂**：修改已審核的紀錄時按「修訂」，改為「修訂中」，**舊版繼續有效**，查詢仍顯示舊版；尚未審核的變更在詳細資訊以 ◆ 標示。修改內容審核通過後成為新的一版；「放棄修改」回到原來的版本。
- **停用與恢復**：填寫停用理由後「停用」，紀錄不刪除，查詢不再列出，可以在「停用」分頁找到；「恢復」退回草稿，重新審核通過後成為新的一版。還沒審核過的草稿也可以停用。
- **待審核清單**：列出草稿與修訂中（包含還不能審核的），顯示種類（新草稿、維修紀錄、修訂中、恢復）、等待時間、擋下的原因與提醒；可以審核的排前面，同類依等待時間由久到新。
- **多台電腦**：存檔前檢查檔案是否已被別人修改；已被修改時不會覆寫，請按「重新載入」後再修改。
- 照片或文件欄位尚未提供（存放位置與機密等級待確認）。

## 8. 時區與時間校正

- 畫面右上角一直顯示時區（廠別設定的時區，預設 `Asia/Taipei`）。LOG 沒有時區，畫面一律顯示廠別當地時間。
- 「**時間校正…**」：可以設定案件整體的偏移量，以及個別模組的額外偏移量（秒，可以是負數）。設定後畫面頂端顯示「已校正」，事件依校正後的時間重新排序；原始時間在詳細資訊中，原始 LOG 不會改變。改回 0 即完全恢復。每次修改都寫入稽核紀錄。
- 模組偏移量會改變不同模組之間的先後，請確定有依據再設定。

## 9. 版面

- 面板可以拖曳、浮動、自動隱藏；關閉程式時保存，下次開啟還原。
- 選單「版面」：「回放（Layout 為主）」「搜尋（事件清單為主）」兩種預設，以及「還原預設版面」。
- 新版程式增加了面板時（例如「知識庫」），第一次開啟會改用預設版面，之後再依自己的需要調整。

## 10. 備份

- **先在 LogTrace 中關閉案件（或關閉程式），再複製整個案件資料夾。**案件開啟中複製，可能複製到不完整的資料。
- 「在檔案總管開啟」可以直接打開案件資料夾。
- 公司的備份**不包含** `%LOCALAPPDATA%`；工程師的筆電由工程師自行管理與備份。案件與廠別設定預設放在 `D:\LogTrace`，請把這個資料夾納入自己的備份。
- 案件資料夾內的 `index\`（全文索引）可以刪除，之後會自動重建；其餘檔案不要修改或刪除。

## 11. 資訊安全

- 案件資料夾含有**真實的設備 LOG**，不要外流，也不要上傳到未經核准的外部服務（線上轉檔、AI 服務、公開的 issue 等）。案件資料夾內的「請先讀我.txt」也有這段提醒。
- 程式執行期間不會連線到網路。
- 刪除案件只刪除案件中的複本，倉儲電腦上的原始 LOG 不受影響。
- 知識庫檔可能含有公司的手冊與 SOP 內容，與廠別設定一樣只放在本機，不要外流。
- 異常紀錄含有設備資訊與事件摘要（訊息已遮罩），同樣只放在本機，不要外流，也不要放進 repo。

## 12. 已知限制

- 取消命令、改派命令、站點模式代號、防火門開關、電梯等 LOG 樣式尚**待確認**，需要在廠別設定中填寫規則。
- 效能數字是在開發用電腦上以虛構資料量測；工程師電腦與冷快取的表現**待實測**。
- 搜尋結果很多時，畫面更新較慢：一天份約 98 萬筆事件中符合 18 萬筆時，開發用電腦約需 3～4 分鐘（搜尋本身約 1 秒）。可以先加上更多條件縮小結果。
- 不處理日光節約時間。
