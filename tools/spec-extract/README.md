# 規格書 → 對照表：M365 Copilot 指令包（ADR-0021）

把**機密的設備通信仕樣書**（RM、STV、AGC）整理成 LogTrace 可以查的「電文／代碼對照表」。

> **資訊安全**（CLAUDE.md 第 13 條、ADR-0021）
> - 規格書與整理出來的對照表都是機密，只能交給**公司授權的 M365 Copilot**，並且只放在本機的知識庫資料夾（預設 `D:\LogTrace\Knowledge\`）。
> - **不要**把規格書或對照表的內容貼給 Claude、Jev 或其他未授權的服務，也不要放進 repo。
> - 要請 Claude 協助時，只提供 LogTrace 知識庫面板顯示的**統計數字**，以及用去識別化方式描述的問題（例如「跨頁的表格第二頁欄位對錯」）。
> - 這個資料夾裡的範例全部是**虛構**的，不是任何真實規格書。

## 流程

```
規格書（Word／PDF）
  │ 1. 在 M365 Copilot 開新對話，附上規格書
  │ 2. 貼上 prompts/00-system.md（規則）
  │ 3. 貼上 prompts/01-find-sections.md：列出有電文格式與代碼表的章節與頁碼
  │ 4. 依章節分批貼上 prompts/02-extract-codes.md 或 03-extract-telegram.md
  │ 5. 每批結束貼上 prompts/04-self-check.md：自我檢查並標示待確認
  ▼
CSV（Copilot 輸出的程式碼區塊）
  │ 6. 貼進 Excel，另存為「CSV UTF-8」
  │ 7. 工程師審核：對照原文頁碼抽查，確認後把「狀態」改成「已審核」、填審核者與日期
  ▼
放到本機知識庫資料夾
  shared\RM\*.csv、shared\STV\*.csv、shared\AGC\*.csv（各廠共用）
  plants\<廠別設定檔名>\*.csv（各廠補充）
  │ 8. LogTrace 開啟案件 →「知識庫」面板 →「重新載入」
  ▼
面板最上方的統計（例如「對照表 3 個檔、120 筆（已審核 100、待確認 20；翻譯 40）；2 列有誤，沒有使用；1 處需要注意」）
與每一列的問題（檔名、行號、原因）；只回報這些統計與原因給 Claude，不要附內容。
```

## 小訣竅

- **分批**：一次處理一章或 10～20 頁。Copilot 一次輸出太多時容易漏列或截斷。
- **跨頁表格**：請 Copilot 在表格跨頁時特別確認欄位是否對齊（04-self-check.md 會提醒）。
- **日文**：「意義（原文）」保留日文原文，「意義（中文）」由 Copilot 翻譯；LogTrace 會標示「翻譯」。審核時一併確認翻譯。
- **版本**：每一列都要填規格書的版本或日期（封面或改訂履歷），規格改版時才能追溯。
- **查不到的不要猜**：原文沒有寫的意義一律填「待確認」，不要讓 Copilot 推測。

## 檔案

| 檔案 | 用途 |
|---|---|
| `schema.md` | 對照表的欄位與規則（LogTrace 依此檢查） |
| `prompts/00-system.md` | 規則：只根據原文、附出處、不推測 |
| `prompts/01-find-sections.md` | 找出有電文格式、代碼表的章節與頁碼 |
| `prompts/02-extract-codes.md` | 抽出代碼對照（錯誤碼、狀態碼） |
| `prompts/03-extract-telegram.md` | 抽出電文與欄位的定義 |
| `prompts/04-self-check.md` | 自我檢查：缺出處、重複、跨頁、翻譯 |
| `examples/` | 虛構的規格書片段與正確的輸出，可以先拿來試一次流程 |
