# 對照表的欄位（ADR-0021 第 4 點，候選格式）

CSV，第一列是標題，欄位順序不拘（多出的欄位不使用）。UTF-8（可有 BOM），也接受 Big5。半形括號視為全形：`意義(原文)` 等於 `意義（原文）`。

| 欄位 | 必填 | 說明 |
|---|---|---|
| 設備種類 | 各廠補充必填；共用資料夾可空白 | `RM`、`STV`、`AGC`。放在 `shared\RM\` 的檔案可以空白，填了要和資料夾相同 |
| 類別 | | `電文`、`欄位`、`狀態碼`、`錯誤碼` 等 |
| 電文 | | 代碼所屬的電文 ID（例如 `T20`）；多個電文共用一張代碼表時照規格書寫法（例如 `T20、T30`、`ID21～89`），只列一次。不屬於特定電文的留空（2026-11-18 補充） |
| 欄位 | | 代碼所屬的欄位名稱（例如 `結果碼`）；不屬於特定欄位的留空（2026-11-18 補充） |
| 代碼或名稱 | 必填 | 錯誤碼、狀態碼，或電文、欄位的名稱 |
| 意義（原文） | 必填 | 規格書上的原文（日文保留日文） |
| 意義（中文） | | 原文為日文時的中文翻譯，LogTrace 會標示「翻譯」 |
| 出處 | 必填 | 文件名、章節、頁碼，例如 `RM 通信仕樣書 5.2 節 p.42` |
| 規格書版本 | 建議 | 版本或日期；空白時 LogTrace 提醒「需要注意」 |
| 狀態 | 必填 | `已審核` 或 `待確認`。Copilot 輸出一律填 `待確認`，工程師審核後改成 `已審核` |
| 審核者 | | 工程師填 |
| 審核日期 | | 工程師填，例如 `2030-01-10` |

## LogTrace 的檢查（讀取時自動進行）

- **不使用的列**：沒有代碼或名稱、沒有原文、沒有出處、設備種類不是 RM／STV／AGC、設備種類和資料夾不同、狀態不是「已審核」或「待確認」、和前面的列完全重複（設備、類別、電文、欄位、代碼與意義都相同）、雙引號沒有結束、標題列缺少必填欄。
- **需要注意（仍會使用）**：同一設備、同一類別、同一電文與欄位、同一代碼但意義不同（兩列都顯示）；沒有填規格書版本。
- **查詢**：知識庫面板的關鍵字搜尋包含電文與欄位。事件的警報代碼完全比對（不分大小寫、全形與半形相同）；設備種類依事件對應到的元素（RM 元素＝RM、搬送機＝STV），對應不到時列出所有種類；**有填電文或欄位的列是欄位值，不和警報代碼比對**（解析電文欄位的規則確定後再接上）。「待確認」的列會標示「尚未審核，不當作確定的說明」。
