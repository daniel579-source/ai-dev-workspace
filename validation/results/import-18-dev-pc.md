# 一天份基本匯入時間（#18，開發用電腦）

- 日期：2026-10-16
- 對應：#18 驗收條件「以假設量級的虛構資料量測一天份的基本匯入時間並記錄」；目標見 ADR-0011 第 4 點（一天約 500 MB，2 分鐘內可以瀏覽）。
- 程式：`tests/LogTrace.Engine.Tests/ImportPerformanceTests.cs`（Release 建置；執行方式見 README「建置與執行」）。
- 資料：技術驗證（#15）產生的**虛構** LOG，`tv-data\logs\20300107`（不在 repo）。
- 電腦：與 `summary-dev-pc.md` 相同（16 執行緒、64 GB 記憶體、NVMe SSD）；來源與案件都在同一顆 NVMe SSD。熱快取。

## 結果

| 項目 | 結果 |
|---|---|
| 來源 | 59 個檔案，502 MB |
| 事件 | 985,302 筆 |
| 基本匯入（複製並驗證雜湊、解析、排序與事件序號、寫入 case.db） | **16.3 秒** |
| 讀出所有事件（事件清單載入用） | 4.6 秒 |
| 合計（匯入完成到可以瀏覽） | 約 21 秒（目標 2 分鐘：**通過**） |
| 案件大小 | 1,833 MB，原始 LOG 的 **3.65 倍**（尚未建立全文索引） |

## 備註

- 案件大小：`case.db` 目前保存每筆事件的訊息全文（#16 的實作選擇），加上原始檔複本，約為原始 LOG 的 3.65 倍。ADR-0011 的上限是 5 倍；之後加入全文索引（#21）時要再量一次，必要時改為從原始檔讀回訊息。
- 每次匯入都會重新解析案件中所有參與查詢的檔案並重新編事件序號（重複匯入時事件可能插在中間）。案件有很多天時，加入新的一天所需的時間會隨天數增加（估計每天約 16 秒）。
- 冷快取與工程師電腦的量測仍待進行（與 #15 相同）。
